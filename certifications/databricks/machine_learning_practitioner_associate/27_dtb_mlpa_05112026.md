## Machine Learning at Scale

### Overview of Hyperparameter Tuning

#### Where Tuning fits the workflow

- is an inner loop of model development - trains many models with different settings, evaluates each and feeds the best configuration back before the model moves on to evaluation and deployment
  - **trains many models**: tuning fits a model repeatdely, once per hyperparameter combination, to find the best performing settings
  - **time-consuming**: doing by hand is slow and error prone $\to$ better automated by a search strategy
  - **breadth $\times$ time**: the more values you test, the better the results can be - but the longer the tuning job runs

#### The three things every tuning job needs

- need to define:
  - **evaluation metric**: performance measure to improve chosen to match the ML problem and its success criteria
  - **hyperparameter \& ranges**: the parameters to search and their ranges
    - good starting points
      - algorithms docs
      - autoML best runs
  - **job configuration**: CPU | GPU use, the search strategy, parallelism, stopping criteria and logging
    - parallelism increases efficiency

##### Grid, Random and Bayesian Searches

- search strategy decides which combinations of hyperparameter to try
  - **Grid Search**: evaluates every combination on a regular grid. Simple and through, but the cost explodes as parameters and values increase
  - **Random Search:** samples combinations at random. Often finds good values faster than grid search when only a few parameters really matter
  - **Bayesian Optimization**: uses past results to focus sampling on promising regions. The Tree of Parzen Estimators (TPE) is a popular Bayesian method.

#### Scalabel HPO Frameworks on Databricks

##### Four ways to tune at scale on Databricks

- **SparkML**: built-in `CrossValidator` and `TrainValidationSplit` for distributed search over large datasets
- **Optuna**: open-source framework that automates hyperparameter search with Pythonic search spaces
- **RayTune**: a scalable tuning library offering both grid and advanced search algorithms
- **Hyperopt (deprecated)**: performs optimization using Bayesian methods

##### Hyperparameter Optimization with SparkML

- tunes models with the cluster'sa parallelism - a `ParamGridBuilder` defines the search, a `CrossValidator` (or `TrainValidationSplit`) runs it and the results log to MLflow
  - **scalable \& distributed**: leverages Spark parallelism for large scale tuning
  - **built-in cross validation**: via `CrossValidator` and `TrainValidationSplit`
  - **native to SparkML pipelines**: and supports grid \& random search with `ParamGridBuilder`
  - **integrates with MLflow**: for tracking and reproducibility

##### Optuna

- define by run optimizer - express the searchspace in plain Python inside an objective function, and it effectively samples configurations, parallelize trials, and visualizes results
  - lightweight \& platform agnostic
  - pythonic search spaces
  - efficient algorithms
  - easy parallelization
  - quick visualization
  - MLflow integration
- optuna is the recommended frameworks - a full Optuna run in a few lines - define an objective that suggests hyperparameters, create a study with a sampler (TPE), optimize in parallel with `n_jobs=-1`, then log and visualize the results.

- **Advanced strategies for model selection and evaluation**
  - Optuna can optimize several objectives at once (multi-metric) or choose the algorithm inside the objective (multi-model).
  - Multi-metric studies run a Pareto frontier of trade-off solutions
- **Advanced Options in Optuna**
  - beyond the based loop, Optuna lets you inspect a study's history through attributes, resume a finished study to search further, and pass extra arguments to an objetive by wrapping it

##### RayTune

- **Ray is a unified frameowrk for scaling AI and Python applications**
- hyperparameter tuning library of the Ray ecosystem
- scales the same tuning code from a laptop to a large cluster, works with any ML frameowrk, and offers state-of-the-art schedulers
  - **laptop-to-cluster**: scalable tuning library on Ray scale from single machine to a large cluster without changing code
  - **any ML library**: tune PyTorch, XGBoost, Tensorflow / Keras, and more with the same API
  - **modern schedulers**: methods like ASHA, BOHO and population-based training stop weak trials early
  - **Tensorboard and MLflow**: integrates with Tensorboard and MLflow to tracj and compare results
