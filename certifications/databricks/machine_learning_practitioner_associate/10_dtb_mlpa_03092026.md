### Introduction to Pipeline Deployment

#### Pipeline / Streaming Pipeline Deployment

- deploy machine learning models that continously perform inference as data arrives
  - low latency, real-time insights instead of processing data in batches

**Advantages** | **Limitations**
--- | ---

generate predictions and act sooner | more complicated to develop, maintain and monitor
event-driven architecture enables system to adopt quickly | less throughput than batch

#### SDP - Lakeflow Spark Declarative Pipelines

- declarative way to do ETL and inference on the Databricks Data Intelligence Platform
  - Python or SQL
  - SDP automatically orchestrates the DAG, handles retries, and manages changing data
- **automatically manage my infrastructure** $\to$ necessary autoscaling, and performance optimization
- **ensure high data quality** $\to$ built-in quality controls testing, monitoring, and enforcement
- **unify batch and streaming** $\to$ the simplicity of SQL with the freshness of streaming, in one API

#### Streaming Tables and Materialized Views

- building blocks of a Lakeflow pipeline
- both are a kind of dataset - defined by a SQL query, created and ketp up to date by a pipeline
  - **Streaming Tables:** ingests and processes new records incrementally as they arrive - ideal for raw ingestion and streaming inference
  - **Materilized Views:** stores the precomputed result of a query and refreshes as its input change - ideal for transformation and aggregations

#### Lakeflow pipelines provides tolls

- manages dependencies
- control quality
- automate operations
- simplify colaboration
- save costs
- reduce latency

### Data Quality Validation and Monitoring

- Lakeflow SDP lets you define data quality and integrity controls $\to$ expectations
- each expectation is a constraint with a policy for what to do when a row violates it
  - warn (retain the row)
  - drop the row
  - fail the pipeline
- all pipeline runs and quality metrics are captured, tracked and reported

#### Data Pipeline Observability

- visibility into how a pipeline runs and how data flow trhough it $\to$ essential for operating a pipeline in production
- **lineage diagram:** high quality, high fidelity view of how data flows through the pipeline
  - impact analysis
- **granular logging:** operational, governance, quality and status logging down to the row level
- **monitoring:** continuously monitor pipeline jobs to ensure continued operation
- **notifications:** alerting on pipeline events using Databricks SQL

#### Continuous on Scheduled Data Ingestion

- streaming inference needs a reliable way to pick up new data $\to$ Lakeflow SDP ingests files incrementally and efficiently as they arrive in cloud storage (`AutoLoader`)
  - can run either continuously or on a schedule
  - automatically infer schema of incoming files, or superimpose what you know with schema hints
  - automatic schema evolution $\to$ JSON, VSC, Avro, and Parquet

```sql
CREATE STREAMING TABLE sales_orders_raw
COMMENT  "the raw sales orders, ingested from cloud storage"
AS SELECT * FROM STREAM
  read_files('/databricks_datasets/retails_org/sales_orders/', format=> 'json')
```

#### Building and Running a Pipeline

##### Creating Your first Lakeflow Pipeline

1. **Write Definitions**
   1. streaming table + materialized views definitions (without running them) in notebooks or source files
   2. git folders $\to$ version-control
2. **Create a Pipeline**: picks one or more source files of table definitions, plus any required configuration
3. **Check Start:** Lakeflow SDP with create or update ML the tables in the pipelines

#### Streaming Inference as the Final Step

- turn an ETL pipeline into an inference pipeline
  - make the final dataset a streaming table or materialized view
    - query applies the model
    - load the registered model from Unity Catalog as Spark UDF and call it inside the pipeline's final table definition
      - every new record is scored as it flows through
- use the same `pyfunc` model for batch and streaming pipelines
  - real time predictions and seamless integration with upstream data cleaning and transformation step
