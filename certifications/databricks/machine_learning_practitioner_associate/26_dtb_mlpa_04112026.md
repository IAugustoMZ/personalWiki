### Model Evaluation and Model Metadata with Spark

#### Model Evaluation

- assess the performance and effectiveness of the trained model to predict the output, ensuring it meets the defined success criteria
- **action**: use approriate evaluation metrics and validation techniques to throughly evaluate the model's predictive power and generalizability

##### Evaluating the Model using the SparkML API

- evaluate in turns predictions into a single comparable number. Pick the right metrics and the matching evaluator, then score the model on a held-out test set for an unbiased estimate.
  1. **make predictions**: apply the trained model to a test dataset to generate a predictions DataFrame
  2. **choose a metric**
  3. **pick an evaluator**
  4. **match the evaluator to the task**
  5. **evaluate held-out data**: always score on a separate test never seen during training to avoid optimistic bias

- **Assessing performance with `BinaryClassificationEvaluator`**
  - it scores a binary classifier on a ranking metric. Point it at the label and raw predictions columns, choose the metrics, and returns a single number
    - `labelCol`: name of the column holding the true labels
    - `rawPredictionCol` : the model's raw prediction column (default raw prediction)
    - `metricName`: `areaUnderROC` or `areUnderPR`
    - `weightCol`: per-instance weights, unset means every instance weights 1.0
- **Interpreting the prediction and probability columns**
  - once a model is applied with `transform()`, each row gains a prediction and a probability
  - **predicted class**: the class label chosen using the model's decision threshold (default 0.5)
  - **confidence per class**: a vector `[P(class 0), P(class 1)]` giving the model's probability for each class

### Model Tracking and Packaging with MLFlow

#### MLflow Models: a portable, self-describing model artifact

- when you log a model, MLflow saves it as a self-contained directory - arbitrary files plus an ``MLflowModel`` descriptor at the root. From the model page, you get its schema and copy paste prediction snippets for both Spark and pandas
- the model page shows its input / output schema and ready to ruyn prediction snippets

- **The directory and its MLModel descriptor**
  - a logged model is a self-describing directory. The `MLModel` file at its root declares the model's flavor, environment, and provenance - and the flavors are what let one saved model be consumed from many different tools
    - **flavor: python function**: makes the model loadable by any tool that can run Python - universal `pyfunc` interface
    - **flavor: Spark**: makes the same model usable by tools that understand the Spark model format
  - a flavor is a convention that lets a single logged model be consumed in different ways. The python-funciotn (`pyfunc`) is the universal one
- MLflow also ships flavor for the major ML frameworks.
  - **Python function (`mlflow.pyfunc`)**: the default interface for MLflow Python models - every model is expected to load as a plain Python function
    - it carries everything needed to load and use a model
      - log-model, save-model, load-model, predict
    - **Built-in Flavors**
      - Spark MLlib
      - Scikit-learn
      - Pytorch
      - Tensorflow
      - OpenAI
      - LangChain
      - HuggingFace
      - CustomFlavors

#### MLflow Model Registry

##### Centralized, collaborative model lifecycle management

- where trained models live after training. It versions each model and moves versions through lifecycle stages, giving data scientists and deployment engineers a shared governed hand-off point.
- **governed models with MLflow + Unity Catalog**
  - pointing MLflow at Unity Catalog registers models as governed UC objects under a three-level name
  - a single log-model call logs the model and creates a new registered version, inferring the input schema from your example data
    1. **Point at UC**: tells MLflow to use the Unity Catalog registry
    2. **infer the schema**: reads the first row of input example to infer the models input signature
    3. **Logs Model**: logs the trained model to the backing server with its environment and metadata
    4. **Register the version**: registered model name creates a new version (or the model) under `catalog.schema.name`
