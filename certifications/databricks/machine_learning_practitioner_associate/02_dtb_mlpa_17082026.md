### Data Preparation and Feature Engineering

#### Sampling Methods

- play a crucial role in selecting subsets of data for training, validation, and testing
  - influence the performance and generalization of machine learning models
- **Random Smpling**
  - most common and basic sampling technique
  - randomly selects data points from a dataset
    - assumes each data point has an equal probability of being chosen
- **Stratified Sampling**
  - when a dataset consists of subgroups
  - population divided into homogeneous subgroups (strata) and an appropriate number of instances are selected from each *stratum*
  - final sample should represent the entire population
- **Cross-validation**
  - resampling technique used to assess the performance of ML models
    - partitioning the dataset into subsets to train and evaluate the model multiple times
    - more robust estimate of its generalization performance
      - k-fold cross validation
      - statified k-fold cross validation
      - shuffle split cross validation
      - nested cross-validation
    - sampling for time-series requires special consideration
      - temporal dependencies (order of events is important)

#### Data Imputation

- process of filling in missing values in a dataset with estimated or predicted values
  - enhance the quality and completeness of the dataset
  - ultimately improving performance and reliability
- impacts of missing data
  - reduced model performance
  - biased inferences
  - imbalanced representations
  - increased complexity in model handling
- methods
  - dropping rows / columns
  - treat as category
  - replacing missing values
    - mean, median, or mode imputation
    - KNN imputation
    - regression imputation
- factors influencing imputation methods
  - **nature of data**: data type is continuous, ordinal or categorical
  - **data distribution**: may influence distribution of data imputation
  - **amount of missing data**: will inputting data improve the quality of the dataset or will it add more bias?
    - multiple imputation and KNN might be better for large missingness
  - **form of missingness**: is data missing at random? is there a missingness pattern?
    - domain knowledge
    - how would imputation affect downstream analysis?
- keep track of inputted data
  - model evaluation
  - data quality assessment
  - enable transparency of dataset
  - error identification

#### Data Encoding

- important pre-processing step in preparing categorical data for machine learning algorithms
  - vast majority of algorithsms accepts numerical input exclusively
- issues with classic ML
  - handling high-cardinality features
  - introducing unintended relationships
  - overfitting
  - increased computational cost
  - possible lack of interpretability
- **high cardinality** $\to$ large set of categories
  - can lead to a large number of dummy variables, increasing dimensionality and potentially causing issues
  - group rare categories
  - top-N categories
- **missing values** $\to$ categorial gaps
  - imputation
  - consider missing as a separate category
- **string types**: model require numerical input and categorical features must be encoded
  - one-hot-encoding $\to$ represent categorical variables as binary vectors
  - label encoding $\to$ convert data in numerical labels
  - ordinal encoding

- **Databricks**
  - **one-hot encoding**
    - introduces sparsity
    - limits split options for tree-based models
    - inneficiency for high cardinality features
    - obscures feature importance
    - increases computational costs
  - **label encoding for ordinal features**
    - arbitrary assignments can mislead models
    - misintrepration of relationships
    - model sensitivity
    - logs of informations
    - not suitable for all algorithms
  - **target encoding**
    - replacement by mean of target variable
    - overfitting risk
    - handling new categories
    - dependency of target distribution
    - limited applicability for small datasets
    - risk of bias
