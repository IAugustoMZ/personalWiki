## Machine Learning Model Development

### Types of Machine Learning

- **supervised learning**
  - when the data has associated labels
  - we train a model to predict them for new unlabeled data
    - models $P(Y|X)$
- **unsupervised learning**
  - no labels on data
  - the model tries to find structure in the data on its own
    - clusters
    - low-dimensional representations
  - model de the joint probability of features themselves
- **hybrid**
  - combines supervised + unsupervised learning
  - semi-supervised: uses a small amount of labeled data to infer labels to a larger set
    - useful when labeling is expensive
  - self-supervised: train the model to predict parts of its own input
    - predict the next word in a sentence
    - LLM pretraining
- **reinforcement learning**
  - an agent learns by interacting with an environment taking actions, and getting rewards
  - game-things agents, robotics, and autonomous vehicles
  - often learns heavily on deep learning

### Types of Supervised Learning

- regression $\to$ predicts a continuous number
- classification $\to$ predicts a category
- forecasting $\to$ predicts future values from historical time-ordered data

### MLflow

- open platform for machine learning lifecycle
- co-developed by Databricks and the ML community
- pre-instaled on the Databricks Runtime for ML
- **components**
  - **tracking**: track, compare, and reproduce your machine learning experiments with MLflow's tracking capabilities
  - **evaluation**: automatized evaluation tools for foundational ML techniques
  - **models**: unified format to package, share, and deploy models across frameworks
  - **model registry & deployments**: streamline with MLflows model registry for version control & managed deployment
- APIs: CLI, Pytho, R, Java, REST

#### MLflow Experiment Tracking

- record experiment parameters such as hyperparameters and model configurations
- log metrics and compare them for performance measures
- store and manage output artifacts such as trained models and plots
- store model's source code from the run

##### Model Tracking and Autologging

- autologging $\to$ fastest way to start tracking
  - `mlflow.autolog()` $\to$ call it at the top of your notebook
  - automatically captures paramters, metrics, models, data lineage. The environment for supported libraries

##### Model Tracking and Custom Logging

- **parameters**: custom model hyperparameters
  - custom metrics
  - artifacts $\to$ trained model and additional files within the context of the run

##### MLflow Concepts

- **experiment**: higher-level organizational unit that encompasses a set of runs
  - groups and organizes related runs, typically conducted to explore different configurations, parameters and algorithms
  - two options:
    - notebook experiment: tied to the notebook
    - workspace experiment: manually specify the path, multiple notebooks can create runs in it
- **run**: executions of data science code
  - belongs to only one experiment
  - contains:
    - metadata
    - artifacts
  - has a default `pyfunc` flavor which is a wrapper around the native code
    - framework agnostic wrapper that lets your model be deployed to Databricks, SageMaker, Kubernetes, any MLflow - compatible serving environment
  - Experiment-Run hierarchy is what makes side-by-side comparison possible

##### Examining Past Runs

- via MLflow UI
  - list and filter runs by metrics
  - auditable on the Databricks platform
- via MLflow API
  - `MLflowClient` object
  - list experiments
  - search runs by metrics, model and more
    - `MLflowClient().search_run` with filters, max results, and ordering

### Evaluating Model Performance

- numerical representation of how well a model is doing
  - metrics enable the comparison of different models on different version of the same model
    - guide the fine tuning of models
    - promote an object basis for choosing between different models or approaches

#### How to build and evaluate models?

**Dataset Type** | **Purpose** | **Usage** | **Model Impact**
--- | --- | --- | ---
Training | training data for the model | minimize loss during training | direct impact on internal model parameters |
Validation | hyperparameter tuning | used for preventing overfitting | indirect impact on model parameters 
Test | evaluate generalizability | assess real-world performance on unseen data | no influence on model training or selection

#### Common Metrics - Regression 

**Metric** | **Description**
--- | ---
$R^2$ | measures how well the model explains the variation in the target variable
Mean Absolute Error (MAE) | the average absolute difference between actual and predicted values
Mean Squared Erros (MSE) | measures the average of squared differences between actual and predicted values. Squaring gives higher weight to large errors
Root Mean Squared Errors (RMSE) | similar to MSE but taking the square root. More interpretable to the original units
Mean Absolute Percentage Errors (MAPE) | expresses error as a percentage of the actual value. Great for comparing different scales, but breaks down when actuals are near zero.
