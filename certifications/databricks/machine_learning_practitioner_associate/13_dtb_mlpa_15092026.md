## Machine Learning Model Deployment

### Introduction to Real-Time Deployment

#### The Online Feature Store

- offline features tables $\to$ optimized for training
- online feature store $\to$ low latency counter-part that a serving endpoint reads from at request-time

1. sync the offline feature table (keyed by PK) to the online feature store
2. train and deploy the model to a serving endpoint
3. at request time, the endpoint performs feature lookups / functions against the online store

- backed by Lakebase (serverless PostgreSQL)
- **low latency, high-throughput access:** optimized for real time applications and ML serving at high scales
- **managed capacity and scaling:** uses capacity units to scale up / down, with optional read replicas for higher concurrency, supports serverless compute
- **seamless model serving integration:** models deployed to MosaicAI Model Serving automatically perform featur lookups based on feature lineage
  - no extra endpoint required
- **timeseries point-in-time retrieval:** publish feature tables with a time series deisgnation
  - latest now per key
  - without (all nows)
  - enables accurate retrieval by entity ID and timestamp for verification and batch-testing
- **scheduled updates:** keep online feature fresh with an automated sync

#### Feature Functions - On Demand Features

- some features can't be precomputed because they depend on the values at request time
- automatically calculate on-demand features during inference requests
- Python UDFs governed by Unity Catalog
- function and input bindings during training
- support all data types supported by Feature Engineering
  - except MapType and ArrayType
