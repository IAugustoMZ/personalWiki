## Machine Learning Model Deployment

### Introduction to Real-Time Deployment

#### Deploying and Managing Endpoints

##### The Endpoint-Centric Workflow

- streamlines deployment with simplicity, stability, and flexibility
- create and managing endpoints using the UI or API
  - **stable scoring URI:** 1:1 mapping with a scoring URI, so client code targets a fixed address
  - **flexible deployment:** deploy multiple modes behind the same endpoint, or the same model behind multiple endpoints
  - **staged rollout:** gradually roll out models to minimize risk and ensure stability

##### A/B Testing with Traffic Splitting

- an endpoint can host multiple models and distribute traffic among them
  - safety and securely deploy new models
  - progressive rollout or online model (A/B testing)
    - assign each served model a percentage of incomming traffic
    - monitor performance and validate improvements. Before fully rolling out a new model
    - adjust traffic allocation at any time to support progressive rollout on rollback

##### Serving Custom Models, Libraries, and Artifacts

- supports packing models with custom artifacts, so real-world model with them own preprocessing code and dependencies serve cleanly
- **custom libraries:** $\to$ include custom libraries - or libraries from a private mirror server - while logging your model, and use them with model deployments
  - private PyPL mirrors and custom wheels
  - pinned dependency versions for reproducibility
  - automatic reconstruction at serve time
- **custom artifacts**$\to$ package custom files, and artifacts with your models and serve from with Model Serving
  - tokenizers, config files, and lookup tables
  - preprocessing scripts and features transformers
  - any file the model needs at inference time
- **custom models** $\to$ serve models trained with various ML libraries
  - `scikit-learn`, `xgboost`, `lightGBM`
  - HuggingFace Transformers
  - PyTorch and Tensorflow
  - any framework via MLflow PyFunc
- ensure missing dependencies, and supports reproducible, reliable deployments

#### Monitoring and Observability

- every serving endpoint comes with monitoring
  - **metric:** ready-to-use metrics dashboards for endpoints (latency, request and error rates, CPU / memory)
  - **external export API:** export your endpoints metrics with the export API $\to$ for centralized observability
  - **alerting:** set up alerts after export with DatabricksSQL or your platform of choice

#### The Endpoint API for CI/CD

- endpoints can be deployed as APIs within your CI/CD system for fully automated deployment
  - **create / manage endpoints:** REST API, Databricks SDK for Python, Go SDK
  - **integrate:** with your CI/CD process and Terraform
- endpoints an be equally create with the RAW REST API or Terraform

#### Online Feature Store and Automated Lookups

##### Automated Feature and Vector Lookups

- a real-time request carries only identifies, not full vector of features
  - **Model Serving:** completes the payload automatically
  - **Automatic Feature Lookups:** define your features once, publish them to online store
    - Databricks automatically grabs and joins the correct features to complete the payload
  - **Automatic Vector Lookups**: seamlessly integrate with Vector Stores for vector search while using LLMs.
