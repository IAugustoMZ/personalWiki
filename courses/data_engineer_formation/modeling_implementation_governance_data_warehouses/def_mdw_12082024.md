# Formação Engenheiro de Dados

## Modelagem, Implementação e Governança de Data Warehouses

### Dicas para Modelar o Data Warehouse

- pedir exemplos dos relatórios que são produzidos
- importante mapear as fontes de dados
    - *brainstorm* + documentação
    - pedir revisão + confirmação
    - certificar-se que os dados estão disponíveis para poder responder às perguntas mapeadas nos requisitos

- na etapa de mapeamento dos relatórios, conseguimos identificar dimensões e fatos
- decisão importante
    - Data Warehouse empresarial ou Data Warehouse departamental (Data Mart)
    - cuidado com o tamanho
        - tempo ETL x relatório

### O que são Entidades, Atributos e Relacionamentos

- modelo relacional
- **entidade**: objeto do mundo real, ou conceito sobre como os dados são coletados
    - **dimensão**: categoriza dados e permite análises por diferentes perspectivas

- **atributos**: características ou propriedades das entidades
    - fornecer contexto

- **relacionamento**: como as entidades estão conectadas umas às outras

- design pode afetar eficiência e estabilidade
- se as informações do modelo de dados não existirem, devemos buscar as informações na área de negócio
- pode ser necessário confirmar também na área de negócios sobre os relacionamentos

- depois de realizar o mapeamento -> Modelo Conceitual
    - geralmente precisa refinar para validar regras de negócio
    - detalhar as entidades, atributos e relacionamento

- o modelo pode ser refinado até que todos os relacionamentos devem ser um para muitos
- para selecionar o modelo dimensional, podemos olhar para exemplos de dados
- modelo lógico é template do banco de dados
    - independente do SGBD
    - na tabela fato, geralmente usamos uma chave primária composta, feita nas FKs das tabelas de dimensão
