# Formação Engenheiro de Dados

## Modelagem, Implementação e Governança de Data Warehouses

### SQL para Engenheiros de Dados

- schemas são divisões lógicas do banco de dados
    - servem para organizar os dados e podem ser usados para gerenciar e controlar privilégios de acesso às tabelas e dados

```
CREATE SCHEMA <schema_name> AUTHORIZATION <roles_with_authorization>
```

#### Instruções DDL - CREATE, ALTER, DROP

- *data definition language* - criação, alteração e deleção de objetos no banco

```
CREATE TABLE <table_name> (
    <col_name_1> <data_type_1> PRIMARY KEY
    <col_name_2> <data_type_2>
    ...
)
```

- colunas `PRIMARY KEY` não admitem repetições
- `PROCEDURES` -> é uma função do banco de dados
    - podemos colocar regras de dados e regras de negócios

```
ALTER TABLE <table_name> ADD COLUMN <col_name> <data_type>
```

```
DROP TABLE <table_name>
```

#### Instruções DML - SELECT, INSERT, UPDATE, DELETE

- *data manipulation language* -> expressões que nos permitem manipular e trabalhar com o conteúdo dos objetos do banco

```
INSERT INTO <table_name> (col1, col2, ...) VALUES (value1, value2, ...)
```

- sempre checar o número de colunas do `INSERT` em relação ao número de colunas da tabela

```
SELECT * FROM <table_name>
```

- traz todas as colunas da tabela (não recomendado)

```
UPDATE <table_name>
SET <col_name> = <new_value>
WHERE <condition1, condition2, ...>
```

- para a atualização dos registros de dados
- precisamos usar o `WHERE` para aplicar o filtro somente nas linhas que queremos aplicar a atualização
    - caso contrário, todos os registros são atualizados

```
DELETE FROM <table_name>
WHERE <condition>
```

- mesmo cuidado do `UPDATE` em relação ao `WHERE`

#### Funções de Agregação e Agrupamento

- `MIN`, `MAX`, `SUM`, `AVG` e `COUNT`
- função `ROUND` -> arredondamento para o número desejado de casas decimais
- `GROUP BY` -> realizar a segmentação com cálculos de estatísticas
    - toda coluna que não estiver sendo agrupada pelas funções de agregação, deve ir para a cláusula `GROUP BY`

```
SELECT <categ_name>, AVG(value)
FROM <table_name>
GROUP BY <categ_name>
```

- podemos usar a clásula `ORDER BY` para ordenar os resultados
- funções de agregação não são permitidas dentro do `WHERE`
    - se quisermos filtrar DEPOIS de aplicar a função do agrupamento, devemos usar o `HAVING`

```
SELECT <categ_name>, AVG(value) AS avg
FROM <table_name>
GROUP BY <categ_name>
HAVING avg > <ref_value>
```

- podemos usar o `LIKE` para filtrar strings

#### Junção de Tabelas - JOIN

- utilizadas para unir informações de duas tabelas que possuem relacionamentos por meio de chaves
    - chaves são colunas comuns entre duas tabelas
        - uma delas é a `PRIMARY KEY` e a outra, da outra tabela, é a `FOREIGN KEY`

```
SELECT <col1>, <col2>
FROM <table1> JOIN <table2>
ON <table1.primary_key> = <table2.foreign_key>
```

- `INNER JOIN` - retorna as linhas comuns a ambas as tabelas. Palavra `INNER` é opcional
- `LEFT JOIN` - retorna linhas comuns e linhas da tabela à esquerda (antes) da cláusula `JOIN`
- `RIGHT JOIN` - retorna linhas comuns e linhas da tabela à direita (depois) da cláusula `JOIN`
- `FULL JOIN` - retorna linhas comuns e também linhas de outras tabelas

- função `COALESCE` usada para mudar valores nulos para outro valor desejado

```
SELECT <categ_name>, COALESCE(AVG(value), 0) AS avg
FROM <table_name>
GROUP BY <categ_name>
HAVING avg > <ref_value>
```

#### Subconsultas e CTEs

- CTEs são tabelas temporárias para suportar outras consultas
    - existe na memória em tempo de consulta

```
WITH CTE AS (
    SELECT <col1, col2>
    FROM <table_name>
    WHERE <condition>
)
SELECT AVG(<col1>)
FROM CTE
```
- tornam consultas mais organizadas, legíveis e eficientes
    - legibilidade e manutenção
    - reutilização dentro da consulta
    - facilita consultas recursivas, onde precisa referenciar a si mesma
    - desempenho -> executa a subconsulta uma única vez
    - verstalidade
    - suporte de múltiplos SGBDs (Sistemas Gerenciadores de Bancos de Dados)

- Subconsultas - quando se faz consultas a partir de resultados de outras consultas

```
SELECT <col1>
FROM <table_name>
WHERE col3 = (
    SELECT col1, col3
    FROM <table_name>
)
```
