# Formação Engenheiro de Dados

## Modelagem, Implementação e Governança de Data Warehouses

### SQL para Engenheiros de Dados

#### O que são `VIEWS`?

- tabela virtual, resultado de uma consulta SQL
    - dados vêm de mais de uma tabela referenciada
    - executam a consulta cada vez que são utilizadas
- *simplificação de consultas complexas* -> encapsulamento
- *segurança de dados* -> dar acesso apenas à `VIEW`
- *reutilização de código e consistência* -> padronização
- *abstração* -> esconder complexidades apresentando uma interface simples

- desempenho pode ser um problema, pos as `VIEWS` são executadas em tempo real
    - consultas complexas
    - grandes volumes de dados
    - alterações nas tabelas podem afetar as `VIEWS`

```
CREATE OR REPLACE VIEW <view_name>
<query_expression>
```

- a `VIEW` salva a query no banco de dados

#### O que são `MATERIALIZED VIEWS`?

- tabela virtual que contém o resultado de uma consulta SQL
    - a view materializada armazena fisicamente o resultado de uma consulta SQL no banco de dados
- dados atualizados manualmente ou periodicamente
- melhoria de desempenho em consultas complexas e demoradas
- eficiência em consultas repetitivas
- redução na carga do banco de dados
    - cálculos intensivos apenas quando a VIEW é atualizada
- ocupam espaço físico no banco (custo)
- *trade-off* -> desempenho de consultas vs. atualização dos dados

```
CREATE MATERIALIZED VIEW ...
```

- para entender os passos de utilização da consulta, podemos usar o `EXPLAIN` antes da consulta

```
REFRESH MATERIALIZED VIEW ...
```

- para atualizar os dados da `VIEW`
- usuário final não deve executar a query diretamente, mas sim usar a consulta à `VIEW`
    - padronização das consultas

#### O que são `STORED PROCEDURES`?

- conjunto de instruções SQL que são salvas e armazenadas no banco de dados
    - reutilizável (modularização)
    - automatização de tarefas repetitivas
    - encapsular a lógica de negócios
- *eficiência de desempenho* -> código executado no servidor de banco de dados
- *redução do tráfego de redes* -> evita o envio de muitos dados pela rede
- *manutenção e segurança* -> controle de acesso, validação de dados
- *reutilização de dados e consistência* -> uso excessivo pode criar uma lógica de negócios excessivamente acoplada -> sobrecarga no banco de dados

- `STORED PROCEDURES` dão flexibilidade nas consultas SQL

```
CREATE OR REPLACE PROCEDURE <name>
LANGUAGE <language>
AS $$
DECLARE
    cur CURSOR <query>
BEGIN
    <logic>
END
```

- `CURSOR` ->  cria uma lista de objetos
- para executar a PROCEDURE usamos `CALL`
