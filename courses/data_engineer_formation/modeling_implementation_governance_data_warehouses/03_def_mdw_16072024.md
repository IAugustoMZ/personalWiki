# Formação Engenheiro de Dados

## Modelagem, Implementação e Governança de Data Warehouses

### SQL para Engenheiros de Dados

#### O que são Triggers?

- procedimentos armazenados que são executados automaticamente em resposta a eventos específicos
    - inserções, atualizações e exclusões

- automatizar ações resultantes de uma tabela atualizada
    - integridade dos dados
    - atualização e validação
    - rastreamento e registrod das atividades
- podem afetar o desempenho
    - operações complexas ou alto volume de transações
- pode dificultar a depuração
- pode disparar outro Trigger -> cadeia complexa de eventos, loops infinitos ou comportamentos inesperados

#### O que são Funções?

- procedimento que executa uma tarefa específica e retorna um valor
    - operações lógicas que podem ser reutilizadas em várias consultas
    - tornar consultas mais curtas e mais legíveis
- úteis para para formatar, extrair ou transformar dados
- uso execssivo pode prejudicar o desempenho
- podem ser específicas do SGBD

|  | `STORED PROCEDURE` | `FUNCTION`|
|-----------------------|------------------------|-----------------------|
| Propósito e uso | conjunto de operações no banco de dados | calcular e retornar um valor |
| Retorno de valores | zero, um ou vários valores, parâmetros `OUT`, conjuntos de resultados | sempre um único valor |
| Uso em SQL | não pode ser utilizada diretamente em instruções SQL | pode ser incorporada em instruções SQL |
| Natureza | mais procedimental, sequências de comandos e lógicas complexas | funcional, cálculos e operações de dados |

```sql
CREATE OR REPLACE FUNCTIONS
RETURN TRIGGER AS ...
BEGIN 
    ...
END

-- create Trigger
CREATE TRIGGER <trigger_name>
BEFORE INSERT ON ...
FOR EACH ROW EXECUTE FUNCTION ...
```

- toda vez que há uma atualização de dados numa tabela, conseguimos capturar o valor antigo com o objeto `OLD` e o novo com o valor `NEW`

#### Controle de Transações - `COMMIT`, `ROLLBACK`

- transações são atômicas, ou acontecem por inteiro, e são confirmadas (`COMMIT`) ou são canceladas (`ROLLBACK`)
    - o banco de dados sempre sai de um estado consistente para outro estado consistente, seja por sucesso ou fracasso
- podemos entender o plano da consulta e assim, olhar o desempenho usando o `EXPLAIN`
    - olhar para os valores de *cost* - é o custo computacional para executar os passos nas consultas
- desempenho pode ser melhorado pelo índice (`CREATE INDEX`)
- importante ter um plano de índices
    - se não temos um bom índice, ele vai prejudicar o desempenho
    - isso acontece, porque cada vez que os dados forem recarregados, os índices terão que ser recriados
- a cada carga do DW
    - desativar / deletar os índices
    - carregar os dados
    - ativar / recriar os índices
