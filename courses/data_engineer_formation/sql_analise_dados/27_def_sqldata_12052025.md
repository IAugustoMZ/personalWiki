## SQL para Análise de Dados e Data Science

### Programação em Banco de Dados com Linguagem SQL

- cada banco de dados possui a sua própria linguagem

#### STORED PROCEDURES

- para iniciar uma `STORED PROCEDURE`

```sql
CREATE OR REPLACE PROCEDURE <name> (args args_type)
```

- digitar a lógica em múltiplas linhas (apenas pgAdmin)

```sql
AS $$
    DECLARE -- declaração de variáveis
        <var_name> <var_type>
        <array_name> <array_type> = ARRAY['...']
```

- para variáveis: usar `VARCHAR`, para arrays, usar o `TEXT[]`
  - `TEXT[]` $\to$ lista de textos sem comprimento definido
- depois da declaração de variáveis, iniciamos a lógica com o `BEGIN...END`
- laço de repetição: `FOR i IN 1 ... N LOOP`
  - o `i` também precisa ser declarado
- todas as cláusulas precisam ser fechadas na `STORED PROCEDURE`
  - `CHR` $\to$ gerar letras

```sql
CHR(TRUNC(65 + RANDOM() * 25: INT))
```

onde:
  - `65 + RANDOM() * 25: INT` $\to$ gera um aleatório entre 65 e 89, que corresponde a código ASCII para maiúsculas
  - `TRUNC` elimina a parte decimal

- selecionar um valor aleatório de um array:

```sql
SELECT
    INTO <valor> <array>[
        TRUNC(RANDOM() ARRAY_UPPER(lista-; 1) +1)
    ] AS valor
```

- onde:
  - `ARRAY_UPPER(lista-; 1) +1` $\to$ indexação do PostgreSQL começa em 1

- para executar a `STORED PROCEDURE`: `CALL <name>(args)`

#### VIEWS

- uma view é uma consulta armazenada no banco de dados
  - `CREATE OR REPLACE <view_name`
- para executar a view, consultamos como se fosse no banco de dados
  - pode ser filtrada, e consultada como qualquer outra tabela
- a query salva na view continua a ser executada quando a view é chamada
- geralmente as aplicações acessam queries por meio de views e não diretamente o banco de dados
- se a consulta salva na view é renovada então a VIEW também pode trazer problemas de desempenho ao banco de dados

#### MATERIALIZED VIEWS

- ao invés de salvar somente a query, podemos salvar também o resultado (tabela)
- `CREATE MATERIALIZED VIEW <name> AS`
- quando chamamos a `MVIEW`, a query salva não foi executada:
  - a `MVIEW` cria um objeto físico no banco
  - não impactamos as tabelas originais
  - no entanto, `MVIEW` precisa ser periodicamente atualizada
    - `REFRESH MATERIALIZED VIEW <name>`
  - é possível criar uma `MVIEW` a partir de uma VIEW

### Diferenças entre STORED PROCEDURES e FUNCTIONS no SGBD

|| `FUNCTIONS` |  `STORED PROCEDURES` |
| --- | --- | --- |
| Retorno | <ul><li>Sempre devemos retornar um valor, de vários tiposde dados como inteiros</ul> | <ul><li>Não retornam valores diretamente<li>Podem retornar dados através de parâmetros de saída</ul> |
| Uso | <ul><li>Podem ser chamadas em instruções SQL<li>Em qualquer lugar que as expressões são permitidas<ul><li>`SELECT`<li>`WHERE`<li>`HAVING`</ul></ul> | <ul><li>São chamados usando a instrução `CALL` ou uma sintaxe específica do SGBD<li>Operações que envolvem a manipulação de dados ou a execução de lógicas de negócios complexas que não precisam ser parte de uma consulta SQL</ul> |
| Transações | <ul><li>Limitadas em termos de operações de *commit* e *rollback*</ul> | <ul><li>podem iniciar e gerenciar suas próprias transações<li>útil para operações complexas que precisam de controle explícito sobre *commit* e *rollback*</ul> |
| Outros | <ul><li>determinística ou não<li>afeta como o SGBD otimiza chamadas</ul> | <ul><li>oferecem maior flexibilidade em termos da lógica de programação<li>permite o uso de loops, condicionais, estruturas de controle de fluxo, não disponíveis em funções</ul> |

#### FUNCTIONS

- para criar uma `FUNCTION`, é semelhante ao `STORED PROCEDURE`

```sql
CREATE OR REPLACE FUNCTION <name>(args)
RETURNS <type_return> AS $$
    DECLARE
        ...
    BEGIN
        ...
    END
```

- `FUNCTIONS` podem ser usadas para implementar regras complexas de negócio, e mesmo assim retornar valores simplificados.
