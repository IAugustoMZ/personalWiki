# Formação Engenheiro de Dados

## SQL para Análise de Dados e Data Science

### Consultoria na área de dados com Agentes de IA

- primeiro passo: entender claramente os problemas do negócio e os objetivos do cliente
  - reuniões de descoberta $\to$ necessidades, desafios e metas da organização
  - contexto que pode ser suportado por dados
    - dores e oportunidades
    - métricas
  - CRISP-DM $\to$ entendimento do negócio
- documentar:
  - objetivos do negócio
  - problema de dados $\to$ qual questão será respondida com dados ou modelo de IA?
  - critérios de sucesso $\to$ como medir se a solução foi eficaz?
  - questões administrativas
    - NDA (acordo de confidencialidade)
    - quais stakeholders?
    - alinhamento de expectativas e objetivos claros

#### Avaliação de Dados Disponíveis (Discovery de Dados)

- entendimento dos dados (CRISP-DM)
  1. fontes de dados: quais bases, planilhas, sistemas
  2. qualidade / volume: dados suficientes em qualidade e quantidade
     1. identificar problemas de dados ausentes, inconsistências ou necessidades de dados externos
  3. acesso e governança: permissões, segurança, restrições legais no uso
  4. ferramentas e infraestrutura: ecossistema do cliente, nuvem, data warehouse, stack tecnológica
     1. prática $\to$ análise exploratória da amostra, hipóteses iniciais, entender a estrutura dos dados
  5. relatório de assessment e refino do escopo do projeto

#### Planejamento de Projeto e Proposta da Solução

- planejar a solução e o projeto

1. **escopo detalhado**: descrição das funcionalidades da solução de IA ou análises
2. **abordagem técnica**: técnicas de análise ou algoritmos adequados
   1. supervisionados $\times$ não-supervisionados
   2. arquitetura
   3. pipeline de engenharia de dados?
      1. batch?
      2. real-time 
   4. interface $\to$ dashboard, aplicação
3. **cronogramas e marcos**: dividir em fases, estabelecer marcos de entregas
   1. entregas claras para cada marco
4. **equipe e responsabilidades**: quem fará parte do projeto do lado da consultoria, e qual envolvimento se espera do cliente?
5. **riscos e mitigações**: listas riscos potenciais (RAID) e como serão tratados?
   1. após o planejamento $\to$ proposta formal para alinhamento, base contratual

#### Modelo de Precificação por Projeto

- **preço fixo por projeto**: valore fixo acordado para todo o escopo ou para fases definidas
  - escopo definido $\to$ entregas claras (minimiza surpresas)
- **preço por hora (*time and materials*)**:
  - valor cobrado por hora ou dia trabalhados
  - flexibilidade caso o escopo possa mudar ou não esteja totalmente claro
    - pesquisa ou incerteza envolvida

- cobrança híbriad $\to$ dase discovery com preço fixo menor e depois, precificação separada
  - segurança ao cliente sem se compremeter tanto
  - não assumir riscos com escopos tão abertos
- para chegar a valores concretos
  - **estimativas de esforços**: horas dos profissionais envolvidos em cada fase
  - **taxa dos profissionais**: dependendo da senioridade
  - **custos extras**: infraestrutura, licenças, deslocamentos
  - **margem e impostos**: lucro
- entre US$ 6,000 e US$300,000
- justificar ao cliente $\to$ *benchmark* do mercado $\times$ retorno esperado

#### Questões Administrativas e Contratuais

- formalização do contrato $\to$ escopo, prazos, preços

1. **cronograma de pagamentos**: faseados ou mensais
2. **confidencialidade e propriedade intelectual**: garantia de proteção dos dados do cliente, definindo dono dos artefatos produzidos
3. **critério de aceitação**: como o projeto será validado; processo para eventuais correções pós-entrega
4. **garantia e manutenção**: período de suporte pós-implantação
   1. assistência para ajustes finos ou correção dos bugs
   2. contrato de manutenção contínua ou evolução futura
5. **comunicação e governança**: frequência de reuniões de acompanhamento
   1. quem são os pontos focais de cada lado
   2. ferramentas de gestão de projetos

- **consultor**: controlar projeto ativamente, controlar prazos, mitigar riscos, manter o cliente informado
  - gerente de projetos

- documentação de cada etapa: facilita a transição da solução para o usuário final
  - planos
  - resultados de testes
  - manuais do usuário

#### Implantação Técnica - Engenharia de Dados

- geralmente a primeira parte a ser implementada

1. **extração e integração de dados (ETL/ELT)**:
   1. desenvolver pipelines para coletar os dados necessários $\to$ ingestão para um repositório unificado
      1. bases internas do cliente
      2. fontes externas
2. **limpeza e qualidade**: tratar valores faltantes, remover *outliers* ou registros inconsistentes
   1. padronizar formatos (datas, unidades)
   2. deduplicação
   3. regras de negócio fornecidas pelo cliente
3. **transformação e feature engineering**: preparação os dados no formato ideal para análise ou modelagem
   1. novas variáveis (features) relevantes
   2. agregações (médias semanais, total por categoria)
   3. normalização
   4. codificação de variáveis categóricas
   5. pré-processamento de texto e geração de embeddings
   6. redirecionamento ou aumentações de imagens
4. **armazanamento e arquitetura**: definir onde os dados processados são armazenados para acesso
   1. data warehouses
   2. dataframes in-memory
   3. data lake em cloud

- garantir que há um pipeline reprodutível, de preferência automatizado
  - consistência na obtenção e preparação de novos dados
    - datasets de treinamento e testes
    - data dictionary
    - schemas
  - assistência de agentes de IA

#### Implementação Técnica - Desenvolvimento de Modelos de IA (Machine Learning)

- modelagem preditiva ou de IA

1. **seleção do algoritmo / arquitetura**: baseado no problema
   1. classificação, regressão, agrupamento, NLP, visão computacional
   2. algoritmos clássicos, redes profundas
2. **treinamento do modelo**: usando o conjunto de dados de treinamento para ajustar o modelo
   1. treino / validação
   2. experimentação de hiperparâmetros
3. **avaliação do modelo**: medir métricas de desempenho relevantes
   1. validação cruzada para melhorar a generalização do modelo
   2. resultado são comparados aos critérios de sucesso definidos lá no início
   3. pode ser necessário voltar etapas anteriores, coletar mais dados, criar novas features ou tentar abordagens diferentes de modelagem
      1. ciclo iterativo é normal
4. **documentação e explicabilidade**: registrar o modelo escolhido, parâmetros e métricas obtidas
   1. mecanismos de interpretabilidade $\to$ fatores mais influentes (principalmente)

- ferramentas de agentes inteligentes podem ajudar
  - automação de experimentos de modelagem (combinações de algoritmos e hiperparâmetros)
  - geração de código de modelagem, documentações, explicação de resultados em linguagem natural para stakeholders
  - multi-agentes ajudam a gerenciar a complexidade

#### Iteração e Envolvimento do Cliente

- importante iterar com frequência e envolver o cliente
- raramente o primeiro modelo ou solução será final sem ajustes

1. **apresentar protótipos ou resultados parciais**: ao final de marcos importantes
2. **coletar feedback e refinar a solução**: o cliente pode trazer conhecimento do negócio
   1. explicar padrões e *outliers*
   2. orientar melhorias
3. **ajustar o escopo**: mudança de premissas inicias ou estavam incorretas
   1. deve ser tratado na governança do projeto
   2. formalizando *change requests* e analisando impactos no prazo/custo

- transparência é fundamental para evitar surpresas desagradáveis
  - iteração controlada $\to$ cliente sabe o que será entregue e tem confiabilidade no resultado

#### Deploy, Implementação e Entrega Final

- colocar os modelos em produção

1. **desenvolvimento do pipeline de produção**:
   1. job diário que executa o modelo nos novos dados
   2. integrar o modelo num sistema existente via API
      1. Docker / Kubernetes $\to$ portabilidade
      2. prepração de ambientes para hospedagem
2. **integração com sistemas do cliente**:
   1. previsões precisam chegar no usuário final ou sistemas de negócio
      1. gravar resultados em tabelas no data warehouse
      2. expor um web service consumido pelo cliente

- trabalho junto da equipe do TI para assegurar integração, segurança e desempenho

3. **interface do usuário e visualização**:
   1. camadas de visualização
      1. dashboards
      2. aplicações web
4. **testes finais e aceites**
   1. desempenho de resposta
   2. testes de carga e de sergurança
   3. demonstração final e aceita formal conforme critérios estabelecidos em contexto
   4. entrega final = sistema funciona + documentações
      1. manual do usuário
      2. manual técnico
      3. documentação do código
      4. relatórios dos resultados e métricas
      5. artefatos como códigos fonte (repositório git), arquivos de configuração

#### Suporte, Monitoramento e Encerramento

- encerrar o projeto ou iniciar um período de suporte monitorado
- modelos de IA precisam ser monitorados quanto à qualidade das previsões ao longo do tempo
  - data drift
  - métricas de acompanhamento e alarmes
- acompanhamento de X semanas (ajustes menores são cobertos)
  - pode ser manutenção contínua
  - *retainer* $\to$ time disponível para evoluções ou suporte reativo
- caso contrário, projeto formalmente encerrado com reunião final
  - avaliação de satisfação
  - discussão de projetos futuros
- *debriefing* (*post-mortem*)
  - lições aprendidas (certo / errado)
  - coleta de depoimentos de sucesso $\to$ casos de uso

#### Importância dos Agentes de IA no Processo de Consultoria

- automação de tarefas, análise de dados e colaboração com humanos

1. **assistentes para os consultores (agentes internos)**
   - ganho de produtividade
     - geração de código e scripts
     - responder perguntas técnicas $\to$ busca de documentações
2. **partes da solução final (agentes para o cliente)**
   - chatbots inteligentes treinados no conhecimento de uma empresa
   - agentes de automação de processos: operando continuamento e tomando ações, dentro dos limites definidos
   - equipes de agentes especializados, cooperando projetos divididos unidades manejáveis
     - agentes podem aprender
     - automação e escalabilidade $\to$ atividades mais estratégicas / design de solução
