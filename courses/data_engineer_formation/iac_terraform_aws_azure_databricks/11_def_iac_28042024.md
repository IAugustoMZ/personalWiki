# Formação Engenheiro de Dados

## Infraestrutura como Código com Terraform, AWS, Azure e Databricks

### Creation-Time e Destroy-Time

- se eu preciso executar o `remote-exec`, preciso configurar o par de chaves
    - para acesso aos recursos da AWS
    - criação de um par de chaves genérico
- caso eu não associe o par de chaves SSH, eu não consigo conectar ao terminal para executar configurações na máquina virtual
- par de chaves associado no momento da criação da instância EC2
    - `pem` -> OpenSSH (Linux)
    - `ppk` -> Putty (Windows)
- provisioner -> automatiza a infraestrutura e o que vamos fazer com a infraestrutura
- na connection, não especificamos senhas, pois estamos fazendo autenticação via par de chaves
- para garantir unidade, temos que colocar o servidor + serviços web como unidade no Terraform
    - no caso do provisioner, mesmo que aconteça um erro, o Terraform não vai tratar a exceção
- sem definição do campo de segurança, é aplicação o grupo padrão
    - totalmente restritivo -> não permite conexão
- Terraform automatiza coisas, mais não vai substituir o conhecimento em Cloud Computing
- checar as regras de entrada
- `sudo yum update` -> atualizar os pacotes do SO
    - `-y` -> configuração automática
- `sudo yum install httpd` -> instalação do `httpd`
- `sudo system ctl start httpd` -> inicialização do `httpd`
- verificar a porta padrão do httpd (80) -> no grupo de segurança
