# Formação Engenheiro de Dados

## Infraestrutura como Código com Terraform, AWS, Azure e Databricks

### Compreendendo o Conceito de DevOps e IaC

- **DevOps** -> colaboração em desenvolvimento de software, buscando aumentar a agilidade e a qualidade
    - integração contínua
    - automação dos processos de desenvolvimento, teste e implantação
    - comunicação e colaboração

- **IaC** -> gerenciamento da infraestrutura de TI de forma automatizada e declarativa
    - permite versionamento e teste
    - automatização e padronização
        - provisionamento
        - configuração de segurança
        - deploy
    - facilita colaboração e responsabilidade
    - implantação contínua e integração contínua

- **infraestrutura** -> recursos físicos ou virtuais necessários para suportar os processos de software
    - servidores (hospedagem)
    - armazenamento
    - rede
    - monitoramento e gerenciamento
    - plataformas em nuvem
    - ferramentas e processos de gerenciamento e automatização

- na IaC, é tratada como qualquer outra parte da aplicação
    - escalonamento horizontal ou vertical, deploy
    - útil em ambientes em nuvem

- **o que não é IaC**
    - gerenciamento manual de infraestrutura
    - scripts e automações isoladas
    - gerenciamento da configuração dos servidores
    - scripts em linguagens de programação
    - arquivos de configuração sem controle de versão

#### Princípios da IaC

1. **declarativo** - apenas define o que, não como
2. **automatizado** - consistência e repetibilidade
3. **controlado por versão** - como qualquer outro código
4. **modular** - módulos reutilizáveis -> manutenção
5. **portátil** -> funcionar em diferentes ambientes
6. **testável** -> garantir a qualidade e complitude
7. **monitorado** -> proativamente

- *formas de representação* -> sintaxe
    - Terraform = HCL
    - Ansible = YAML (playbook)
    - Chef = DSL baseada em Rust (recipes)
    - Puppet = puppet DSL baseada em Rust
    - CloudFormation (AWS) = JSON ou YAML
    - ARM Templates (Azure) = JSON

1. escolher ferramenta
2. aprender sintaxe
3. definir infra desejada
4. versionar
5. automatizar CI/CD
6. monitorar e agir

- *padrões adicionais*
    - *imutabilidade* - criar novos recursos ao invés de modificar os existentes
    - *documentação* - facilitar manutenção e entendimento
    - *princípio do menor privilégio* - apenas os acessos necessários
    - *atualização e monitoramento contínuo*
