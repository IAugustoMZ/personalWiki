# Formação Engenheiro de Dados

## Infraestrutura como Código com Terraform, AWS, Azure e Databricks

### Terraform Registry

- **provider** -> qual o provedor (conector) da nuvem que estamos provisionando
    - vem do Terraform Registry -> repositório de conectores
    - cada provider terá os seus parâmetros
- **region** -> parâmetro que especifica a região do deploy

### Terraform Resource

- cada provider allow the implementation of specific resources

### Terraform Core Workflow

1. **escrever**: a infraestrutura como código
2. **planejar**: pré-visualizar as mudanças antes da aplicação
3. **aplicação**: provisionar a infraestrutura reprodutível

### Dependency Lock File

- melhorar a gestão das dependências dos provedores
- `terraform.lock.hcl`: contém as informações sobre as versões exatas dos provedores em uso
    - consistência entre ambientes
    - informações de hash dos pacotes, integridade dos binários do servidor
    - atualizações controladas -> registros explícitos de quando e como
    - opção de ignorar (`-upgrade`)
- `terraform plan` -> visualização prévia dos estados (relatório de criação da infraestrutura)
    - controle de versão do plano
    - `terraform apply <nome_do_plano>`
