# Formação Engenheiro de Dados

## Infraestrutura como Código com Terraform, AWS, Azure e Databricks

#### Cloud Computing com Microsoft Azure

- grupo de recursos
    - forma de organização dos recursos
- toda máquina precisa estar numa rede para se comunicar
    - criar uma rede virtual e subnets
- interface de rede -> rede do modem (subnet)
    - rede do provedor (vnet)
- alocação dinâmica não mantém o endereço IP fixo
- é comum uma máquina possuir mais de uma interface de rede
    - rede de backup
    - rede principal
- podemos usar o `terraform validate` para checar a sintaxe dos arquivos Terraform

#### Terraform Graph

- visualizar a estrutura e as dependências dos recursos definidos no código da infraestrutura
    - `terraform graph` -> DAG
    - como recursos estão conectados e suas dependências
- útil em infraestrutura complexas
- planejamento da execução / mudanças

#### Automatizando o Deploy Multi-Cloud

- distribuir aplicações, servicos e recursos entre várias plataformas de computação em nuvem
    - vantagens específicas de diferentes provedores
    - otimizar recursos, performance, custo, resiliência, conformidade regulatória
    - redundância, reduz risco de dependência de um único provedor

#### Quando precisameos de um deploy multi-cloud?

- **resiliência e redundância** - continuidade de serviços
- **otimização de custos** - preços variados pelos recursos semelhantes
- **conformidade regulatória e geográfica**
- **evitar dependência de um único fornecedor** -> deterioração dos serviços ou aumento de preços
- **especialização de serviços**
- **balanceamento de carga e performance**

#### Como o Terraform trata o deploy multi-cloud?

- múltiplos provedores suportados de forma consistente
- **providers**: blocos específicos
- **abstração e consistência**: sintaxes consistente e processo uniforme
- **módulos**: mesma configuração podendo ser implementada em diferentes cenários de cloud
- **gerenciamento de estado**: versão integrada e controle sobre recursos distribuídos
- **workspace**: gerenciar múltiplos ambientes dentro da mesma configuração
- **planejamento e aplicação**: visualização do planejamento de infraestrutura
