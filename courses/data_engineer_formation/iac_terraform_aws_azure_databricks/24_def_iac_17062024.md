# Formação Engenheiro de Dados

## Infraestrutura como Código com Terraform, AWS, Azure e Databricks

### Execução e Debug do Terraform

- **Execução**
    - *inicialização*: `terraform init`
        - inicializa diretório de trabalho
        - instala módulos, provedores, e configura o *backend* do estado do Terraform
    - *planejamento*: `terraform plan`
        - cria o plano de execução
    - *aplicação*: `terraform apply`
        - aplica as mudanças na infraestrutura, garantindo do que o estado real seja igual ao estado no código
    - *destruição*: `terraform destroy`
        - remover todos os recursos gerenciados pel Terraform
- **Debug**
    - *logs detalhados*: variável `TF_LOG` (`TRACE, DEBUG, INFO, WARN, ERROR`)
    - *verificação de configurações*: revisão
    - *validação (`terraform validate`)*: erros de sintaxe de configurações incorretas
    - *estado (`terraform state`)*: inspeção da infraestrutura -> discrepâncias estado real e esperado
    - *recursos de saída*: valores que podem ser inspecionados, verificados manualmente ou usados em outra parte

### Automatizando o Deploy de Infraestrutura com Databricks e Terraform

- Databricks = Apache Spark na nuvem
- a infraestrutura na verdade está num provedor em nuvem (AWS, Azure ou GCP)
- o comando do Terraform permite a iteração direta com a infra do Databricks
- apesar de ser uma plataforma em nuvem. é muito mais focada em processamento de dados e processamento em tempo real
    - limitação quando comparada com AWS ou Azure

1. processamento em grandes volumes de dados (Apache Spark para processamento distribuído)
2. análise em tempo real
3. integração com várias fontes de dados
    - Bancos relacionais
    - Data Lakes
    - Storages em Cloud
4. Machine Learning e IA
5. colaboração e notebooks interativos
6. automação e orquestração de workflows
7. segurança e conformidade (controle de acesso, criptografia)
8. redução de custos com a infraestrutura em nuvem (pague pelo uso)
