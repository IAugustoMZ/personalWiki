### PySpark para Processamento Distribuído de Dados - Parte I

#### Diferença entre Arrays e Map

- ambos são tipos de dados complexos, porém com propósitos diferentes
- **Array**
  - coleção ordenada de elementos, todos os elementos do array devem ser do mesmo tipo
  - úteis quando precisamos armazenar múltipls valores numa única coluna do DataFrame
    - valores têm uma ordem específica ou quando a ordem pode ser importante para análises subsequentes
  - muitas operações de arrays: adicionar, remover, filtrar e transformar
- **Map**
  - coleção de pares chave-valor, onde cada chave é única dentro do mapa
  - tipo de chaves e dos valores podem ser diferentes entre si
    - cada chave é associada a exatamente um valor
  - úteis para armazenar valores acessados por meio de chave específicas
    - representa dados de forma estruturada
  - operações de adição, remoção de pares, alterar valores associados a uma chave específica e realizar buscas por chaves
- no array, dados acessados por meio de índices e no map, por meio das chaves
- no array, não há restrição de unicidade

#### Método `collect()` no Spark

- permite trazer todos os elementos do RDD para a memória do driver como uma lista
  - fins de depuração
  - quando os conjuntos de dados são suficientemente pequenos para caber na memória sem causar problemas de desempenho
- **funcionamento**
  - ao ser chamado, execuções de todas as transformações pendentes (*lazy*) para consrtuir o novo RDD
  - transformar dados para o processo driver
    - visualizar dados após uma série de transformações
    - exportar pequenos conjuntos de dados para outras ferramentas
- **considerações**
  - **desempenho de escalabilidade:** pode ser custoso em desempenho e uso de rede
    - lentidão e erros de falta de memória
  - **uso cauteloso:** principalmente em ambientes de produção ou grandes volumes
    - `take` ou `saveAs` $\to$ métodos que gravam o RDD no sistema de arquivos ou banco de dados
  - **alternativas:** considerar métodos como `count()`, `first()` ou `aggregate()`
    - proporcionam insights sem a necessidade de materializar todo o RDD no driver

#### Operadores

- métodos que podem ser aplicados a fim de realizar transformações ou filtros nos dados
  - processamento e transformação de forma distribuída

##### `withColumn`

- permite adicionar uma nova coluna ao DataFrame ou substituir uma coluna existente por outra baseada em expressão ou valor
  - parte das transformações do DataFrame API
  - usado para derivar novos dados, formatar dados existentes ou incorporar cálculos complexos
- sintaxe
  - `DataFrame.withColumn(colName, col)`
  - `df = df.withColumn('square', col('value') ** 2)`
- também aceita cálculos realizados com base em expressões lógicas

##### Operações em Colunas

- Spark oferece muitas opções, desde operações simples (adição e subtração), até transformações mais avançadas
  - operações aritméticas
  - operações relacionadas para comparações
  - operações de strings $\to$ concat, substring, regex-replace
  - transformações de data-hora
  - funções de agregação $\to$ após o `groupby()`
  - funções complexas definidas pelo usuário (UDFs), funções integrada complexas (explode para expandir arrays e maps)

##### Considerações de Desempenho

- operações como join, groupby e uso excessivo de UDFs $\to$ custosas em termos de computação e rede
- monitorar o plano de execução das consutlas
  - entender e otimizar o processamento


##### **`MapType`**

- tipo de dado que representa uma coleção de pares chave-valor
  - pode ser empregado tanto em RDDs quanto em DataFrames
  - definido especificando-se os tipos de dados para as chaves e valores
    - `MapType(keyType, valueType)` $\to$ qualquer tipo de dado Spark
- **operações comuns**
  - **acesso a elementos**: usando a sintaxe `col('mapColumn')['key']` $\to$ retorna o valore associado à chave
  - **adicionar ou atualizar elementos**: funções como `map-concat` para mesclar mapas existentes como novos pares chave-valor
  - **remover elementos:** a remoção de elementos específicos de um mapa pode ser feita criando-se uma UDF
    - operações de remoção direta não são suportadas
- **considerações**:
  - tipos de chaves e valores: são sempre tradas como tipos uniformes
  - desempenho: pode ser menos eficiente que operar sobre colunas individuais, especialmente no caso de muitos elementos ou operações complexas frequentes
    - `MapType` é particularmente útil em casos de agregação e múltiplos atriubtos em uma única coluna ou quando trabalhamos com dados semi-estruturados
