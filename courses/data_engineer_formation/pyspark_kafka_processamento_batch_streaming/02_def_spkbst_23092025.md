# Formação Engenheiro de Dados

## PySpark e Apache Kafka para Processamento de Dados em Batch e Streaming

### Automação de Pipelines e ETL

#### 1. **Ferramenta de agendamento e orquestração**

- Apache Airflow (definir DAGs)
- Apache Nifi $\to$ automação do fluxo de dados
- Luigi $\to$ ferramenta Python para criar pipelines complexos + gerenciamento de tarefas

#### 2. **Scripting e Automação de Tarefas**

- Python / R scripts $\to$ ETL
- cron jobs $\to$ tarefas simples e agendamento de execução scripts em intervalos regulares
- shell scripts $\to$ automação de tarefas do sistema como mover arquivos e realizar backups

#### 3. **Integração com mensagens e filas**

- Kafka $\to$ pipelines e ETK em sistemas reais
- RabbitMQ $\to$ mensageria

#### 4. **Containers e Orquestração de Containers**

- Docker $\to$ ambientes isolados e consistentes
- Kubernetes $\to$ larga escala, orquestração de containers para gerenciamento e escala

#### 5. **Monitoramento e Logging**

- ferramentas como Grafana, Prometheus, ELK (Elasticsearch, Logstack, Kibana) para monitorar pipelines de ETL e registrar eventos importantes

#### 6. **Cloud Services**

- AWS, Azure e GCP oferecem serviços integrados
  - AWS Glue, Azure Data Factory, Google Cloud Platform

#### 7. **Práticas Recomendadas**

- modularidade $\to$ componentes reutilizáveis
- documentação $\to$ documentação clara de cada parte do pipeline
- testes $\to$ automatizados para garantir qualidade dos dados
- gerenciamento dos erros $\to$ estratégias de tratamento de exceção robusta
- segurança $\to$ dos dados, especialmente ao lidar com dados sensíveis

### Logging e Monitoramento de ETL

- visibilidade sobre o desempenho, ajuda a identificar e a diagnosticar problemas

1. **registrar mensagens detalhadas:** timestamps, nomes de tarefas, ids de execução, detalhes de contexto
2. **níveis de logs:** categorizar importância, facilitador da filtragem
3. **logs centralizados:** coletar de múltiplos processos e servidores
4. **rotina e arquivamento:** rotação para evitar arquivos longos e arquivamento de logs antigos

#### Estratégias de Monitoramento

1. **desempenho:** tempo de execução, taxa de *troughput*, uso de recursos
2. **verificação de dados:** integridade e qualidade dos dados necessários
3. **alertas:** notificações de erros e desempenhos
4. **dashboard de monitoramento:** visualização em tempo real dos estados e da saúde
5. Ferramentas:
   1. Apache Airflow
   2. Prometheus e Grafana
   3. Nagios e Zabbix
   4. AWS Cloud Watch
   5. Azure Monitor e Log Analytics
   6. Google Stackdriver
6. Boas Práticas:
   1. **consistência:** práticas de logging, mointoramento de todos os pipelines
   2. **segurança dos dados:** cuidados com dados sensíveis e confidenciais
   3. **análise regular dos logs:** melhorar eficiência e a eficácia dos processos de ETL

#### Erros Comuns e Como Tratá-los

1. **problema de conexão com fontes de dados**
   1. falha de conexões com banco de dados, APIs, sistemas de arquivos
   2. verificar crendenciais, URLs/endpoints e parâmetros de rede
   3. implementar tentativas de reconexão, e backoff exponencial em casos de falhas temporárias
2. **inconsistências e qualidade de dados**
   1. dados ausente, formatos inesperados ou dados corrompidos
   2. validação de entrada com schemas (`Pydantic`, por exemplo)
   3. limpeza e normalização de dados, considerar rejeitar registros com dados inválidos e registrar esses incidentes
3. **erros de performance e escalabilidade**
   1. processamento lento, uso excessivo de memória, CPU
   2. otimizar consultas SQL
   3. estratégias de processamento em lote ou streaming
   4. considerar paralelização
   5. verificar e ajustar a configuração de recursos de hardware
4. **erros de integração e dependências**
   1. falahas ao integrar diferentes sistemas, versões incompatíveis de bibliotecas
   2. manter as bibliotecas atualizadas
   3. testes de integrações regularmente
   4. ambientes virtuais para gerenciar dependências
5. **problemas de codificação e formato de arquivo**
   1. leitura ou escrever dados em formatos específicos (CSV, JSON, XML)
   2. verificar o formato e a codificação dos arquivos
   3. usar bibliotecas robustas para manipulação de formatos de arquivos
6. **falhas de transformações de dados**
   1. erros ao transformar ou manipular dados (operações de JOINs, ou agregações)
   2. testar as funções de transformação extensivamente
   3. implementar a captura de exceções
   4. registrar erros detalhadamente
7. **problemas de orquestração de workflow**
   1. falhas da execução de tarefas programadas, dependências não resolvidas
   2. use ferramentas de orquestração como Apache Airflow ou Luigi
   3. monitore os fluxos de trabalho
   4. configurar alertas para falhas
8. **erros de segurança e acesso**
   1. problemas de acesso não autorizado, vazamento de dados
   2. implementar controle de acesso
   3. usar criptografia para dados sensíveis
   4. manter práticas regionais de segurança de dados
9. **limitações e quotas de API**
   1.  exceder as quotas ou limites de rateio de API
   2.  implementar lógicas de rate limiting
   3.  estratégias de cache ou assentamento estratégico de chamadas
10. **erros de infraestrutura e rede**
    1.  problemas de conectividade, falhas de hardware
    2.  implementar redundância e recuperação de desastres
    3.  usar monitoramento

#### Estratégias Gerais de Tratamento de Erros

- logging detalhado
- monitoramento e alertas
- testes automatizados $\to$ detectar problemas antecipadamente
- documentação de erros conhecidos $\to$ mantenha uma base de conhecimento com erros conhecidos
- equilíbrio entre prevenção proativa, monitoramento em tempo real, respostas rápidas aos incidentes
  - abordagem sistemática e metódicas é essencial para manter integridade e a confiabilidade dos piplines de ETL

### Performance e Otimização de Código Python

- eficiência pode ter um grande impacto no desempenho geral do sistema

1. **perfilamento do código**
   1. entender onde estão os gargalos
   2. usar ferramentas de perfilamento para identificar partes do código que estão consumindo mais tempo ou recursos
2. **uso eficiente de estruturas de dados**
   1. preferir estruturas de dados `numpy`, que são altamente otimizadas
   2. usar sets para operações de pesquisa, união e intersecção rápidos
   3. uso de arrays do módulo `numpy` para coleções de dados homogêneas
3. **evitar redundâncias**
   1. evitar cálculos repetidos armazenando resultados em variáveis
   2. usar list comprehension e generators eficientemente
4. **otimização de loops**
   1. minimizar o trabalho dentro de loops, mover operações não relacionadas para fora
      1. usar funções nativas e compreensão de listas
5. **uso de funções nativas e bibliotecas**
   1. geralmente mais eficientes que o código personalizado
6. **programação concorrente e paralela**
   1. *threading* para operações I/O bound
   2. CPU-bound $\to$ módulo `multiprocessing` ou ``joblib`
7. **caching e memoization**
   1. armazenar resultados de operações que consomem mais recursos computacionais
8. **otimização de acesso a dados**
   1. otimizar a leitura / escrita de dados
   2. formatos de dados eficientes como Parquet/HDFS
9. **gestão de memória**
   1.  gerenciadores de contexto para garantir que recursos sejam liberados
   2.  deletar objetos grandes
   3.  usar o recurso `gc` para gerenciar a coleta de lixo
10. **`cython` e `numba`**
    1.  usar Cython para as partes críticas do código para compilar em C
    2.  `numba` é uma opção de computação JIT (*just-in-time*), especialmente para cálculos numéricos

### Considerações Finais

- medir antes e depois das otimizações para garantir que são efetivas
- código limpo $\times$ manutenção: equilíbrio
- ajustar as otimizações ao caso de uso
