# Formação Engenheiro de Dados

## PySpark e Apache Kafka para Processamento de Dados em Batch e Streaming

### Multi-Node Cluster Spark, HDFS e Kafka

#### Otimização de Desempenho na Stack PySpark - Kafka

- **No Kafka**
  - ajuste do tamanho dos batches: configurar o parâmetro `batch.size` para um valor apropriado ao volume de dados e recursos disponíveis
    - equilibrar latência e throughput
  - **particionamento eficiente**: distribuição de carga entre os consumidores
  - **retenção de mensagens**: configurar retenção (`retention.ms` ou `retention.bytes`) de acordo com as necessidades do pipeline, evitando a sobrecarga desnecessária
  - **ajuste do `fetch.max.bytes`**: evitar sobrecarregar o consumidor especialmente em pipelines em alta latência
- **No PySpark**
  - **persistência adequada**: métodos `cache()` ou `persist()` para armazenar dados intermediários
    - evitar armazenar RDDs / Datasets quando desnecessário
  - **gerenciamento de particionamento**: ajustar número de partições no RDD ou DataFrame para evitar subutilização de recrusos ou sobrecarga
    - `repartition()` ou `coalesce()`
  - **evitar ações desnecessárias:** minimizar operações como `count()`, `collect()` e `show()`
    - forçar a execução prematura de um pipeline
  - **uso de API nativas**: prefira as APIs estruturadas (DataFrame ou Datasets) em vez de RDDs, pois são otimizadas pelo Catalyst Optimizer

#### Integração PySpark-Kafka

- **batch size e frequência**: no structured streaming, ajustar `maxOffsetsPerTrigger` e trigger para controlar o volume de dados processados por microbatch, evitando latência ou gargalos
- **checkpoints**: configurar um diretório de checkpoint para permitir a recuperação em caso de falhas e garantir consistência
- **offset management**: usar `startingOffsets` e `endingOffset` de forma estratégica, especialmente para lidar com histórico de dados ou para evitar a sobrecarga inicial

- **Geral**
  - **monitoramento**: ferramentas como Kafka Manager, Spark UI, Control Center para monitorar gargalos em tempo real
  - **recursos alocados**: ajustar configurações como `executorMemory`, `executorCores`, número de executores para atender à carga real de trabalho
  - **compactação**: no Kafka, use compressão de mensagens  (snappy ou lz4) para reduzir o uso da largura de banda e armazenamento

#### Monitoramento de Pipelines em Tempo Real

- essencial para garantir a eficiência, confiabilidade e desempenho de fluxos de dados em sistemas distribuídos e ambientes de processamento distribuído
  - observaçãoi, coleta, análise e alerta sobre métrica e eventos relevantes

1. **Métricas Essenciais**
   1. **taxa de processamento (troughput)**: volume de dados processados por unidade de tempo, medido em mensagens por segundo ou bytes / segundo
   2. **latência**: tempo necessário para processar uma unidade de dados, desde a entrada até a saída
   3. **erros e falhas**: taxa de erros do pipeline ou falhas em tarefas específicas
   4. **utilização de recursos**: monitoramento de CPU, memória, largura de banda de rede armazenamento
   5. **estado de checkpoints**: indicadores de consistência e recuperação, especialmente em pipelines de processamento contínuo
2. **Técnicas e Ferramentas**
   1. **logs em tempo real**: registros detalhados para identificar problemas
   2. **paineis de visualização**: dashboards criados com ferramentas como Grafana, Kibana ou Prometheus, que oferecem insights em tempo real com gráficos e alertas
   3. **alertas automatizados**: configuração de notificações para eventos críticos, como falhas, latências elevadas ou degradação do desempenho
   4. **tracing**: rastreamento de eventos de ponta-a-ponta para identificar gargalos ou erros
3. **Monitoramento Específico para Pipelines**
   1. **Kafka**: Kafka Manager, Confluent Control Center ou métricas integradas no JMX para monitorar offset, lag, throuput de tópicos e saúde do cluster
   2. **Apache Kafka**: Spark UI permite acompanhar a execução de tarefas, uso de memória, e estado de RDDs
      1. structured streaming: o monitoramento inclui dados sobre taxas de microtabelas e latência
4. **Práticas Recomendadas**:
   1. **definir SLAs / SLIs**: estabeleça limites claros para métricas como latência, disponibilidade, e throughput para analisar a saúde do pipeline
   2. **coleta centralizada**: consolide métricas e logs de diferentes componentes em um único local para análise
   3. **escalabilidade de monitoramento**: certifique-se que o sistema de monitoramento seja escalável, suportando o crescimento do pipeline
   4. **testes de carga**: testes regulares para identificar pontos de falha em condições de alta demanda
5. **Benefícios**
   1. **prevenção de problemas**: identificação proativa de gargalos, e falhas que afetam produção
   2. **otimização contínua**: insights que permitem ajustar e otimizar a arquitetura e os parâmetros do pipeline
   3. **confiabilidade e SLA**: garantia de que os pipelines atendam aos requisitos de tempo real definidos pelo negócio
