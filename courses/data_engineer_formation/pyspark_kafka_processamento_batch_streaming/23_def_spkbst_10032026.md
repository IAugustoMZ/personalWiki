### Multi-Node Cluster Spark, HDFS e Kafka

#### KSQL e Processamento de Streams SQL-Like

- KSQL $\to$ ferramentas de consulta SQL-like desenvolvida especificamente para o Apache Kafka
  - facilitar o processamento e a análise de stream de dados em tempo real
- interface simples e declarativa $\to$ interagir com fluxos de dados sem a necessidade de escrever código em linguagens como Java ou Scala
  - reduz a complexidade do desenvolvimento
- possível realizar transformações, agregações, filtros e outras operações comuns de fluxos de dados
  - consultas para identificar eventos específicos em tempo real: calcular métricas agregadas
  - unir fluxos de dados
- acontece diretamente sobre os tópicos do Kafka
  - sem necessidade de mover para sistemas externos
- abstração de *streams* e *tables*
  - *schema* representa uma sequência contínua de eventos ordenados no tempo
  - *table* é uma visão materializada desses dados, representando seu estado atual
  - a dualidade permite realizar operações tanto em fluxos contínuos quanto em dados agregados ou transformados
- KSQL suporta consultas contínuas, que executam indefinidamente e produzem resultados à medida que novos dados chegam

##### JOINs em Streams de Dados

- operações que combinam dois fluxos distintos ou um fluxo e uma tabela para produzir:
  - um novo fluxo
  - uma nova tabela com informações enriquecidas
- correção de eventos, adição de contextos aos dados
- usa-se a StreamsAPI ou o KSQL
- diferentes tipos de joins:
  - **stream-to-stream**: combina dois fluxos com base numa chave comum
    - requer uma janela de tempo, já que os eventos chegam em momentos diferentes
    - define o intervalo de tempo que os eventos de ambos serão considerados
  - **stream-to-table**: fluxo de dados + tabela (visão materializada e atualizável de dados)
    - adicionar contexto a streaming de dados
      - transações + dados de catálogo
    - não requer janela de tempo $\to$ tabela é um estado estático ou dinamicamente atualizável
  - **table-to-table**: semelhante a JOINs em bancos de dados tradicionais, mas em tempo real, e com atualizações contínuas à medida que os dados mudam
- necessário lidar com desafios com latência, gerenciamento de estado e ordenação de eventos
  - automação para StreamsAPI do Kafka
  - para JOINs baseados em janelas, o estado associado é mantido localmente e pode ser configurado para otimizar desempenho e consumo de recursos

##### Windowing e Time Series Processing

- análise de dados em segmentos temporais definidos, facilitando operações como agregações, contagens e detecção de padrões 
- windowing é o processo de dividir um fluxo contínuo de dados em janelas temporais
  - útil quando os eventos chegam em momentos diferentes e precisam ser agrupados com base em sua ocorrência no tempo
- **Janela com Base em Tempo (Time Based Window)**: divide os dados com base em intervalos fixos
  - útil para calcular métricas como médias ou somas em intrervalos regulares
- **Janela Deslizante (SlidingWindow)**: permite sobreposição entre janelas, onde cada janela captura um intervalo específico de tempo, podendo haver sobreposição parcial
  - análise em tempo real que requerem visão contínua dos dados
- **Janela *Tumbling* (Tumbling Window)**: semelhante à janela com base em tempo, mas sem sobreposição
  - eventos de cada janela são completamente independentes das outras
- **Janela Baseada em Sessão (Session Window)**: agrupamento com base em períodos de inatividade ou gaps temporais
  - ideal para rastrear sessões de usuário ou atividades intermitentes

- **Principais Operações**
  - **agregações temporais**: resumir dados ao longo do tempo
  - **cálculo de taxas e diferenças**: determinar como valores mudam ao longo do tempo
  - **identificação de tendências e padrões**: reconhecer aumentos, quedas e sazonalidade
  - **preenchimento de gaps (imputation)**: lidar com dados ausentes em séries temporais, interpolando ou preenchendo valores para manter a continuidade
- tudo suportado nativamente pela StreamsAPI e do KSQL

#### MongoDB - Banco de Dados NoSQL

- banco NoSQL $\to$ flexibilidade, escalabilidade e facilidade de uso
- não utiliza tabelas e colunas (não relacional)
  - armazena documentos JSON-like (BSON, um formato binário, otimizado para desempenho)
    - organizados em coleções (equivalentes a tabelas) e cada coleção tem documentos (equivalentes a linhas)
    - cada documento pode ter estruturas variadas
- flexibilidade no esquema $\to$ alterações dinâmicas sem a necessidade de migração
- consultas ricas $\to$ filtros complexos, projeções, agregações e operações geoespaciais
- escalabilidade horizontal $\to$ sharding, larga-escala, distribuição em servidores
- desempenho elevado $\to$ sem overhead de sistemas SQL
- índices $\to$ campos específicos para otimizar desempenho de consultas
- suporte a replicação $\to$ alta disponibilidade e redundância dos dados
- **casos de uso**
  - aplicações de grandes volumes de dados semi ou não estruturados
  - mudanças frequentes de esquema
- **ferramentas e ecossistema**
  - Atlas: banco de dadoss como serviço na nuvem
  - drivers oficiais: JavaScript, Python, Java, C#
  - Compass: interface gráfica para explorar e gerenciar dados
