# Formação Engenheiro de Dados

## PySpark e Apache Kafka para Processamento de Dados em Batch e Streaming

### Multi-Node Cluster Spark, HDFS e Kafka

- **KRaft** $\to$ mecanismo de consenso para gestão do cluster
  - projetado para simplificar na gestão do cluster
  - maneira nativa de gerenciar metadados e alcançar consistência distribuída
    - elimina a dependência de um sistema externo (Zookeeper) para orquestração
- metadados do cluster são armazenados diretamente em logs internos do Kafka
  - replicados entre brokers (atualizações de metadados, ocorrem de forma mais confiável)
  - permite que o Kafka gerencie seu próprio estado
    - lista de tópicos
    - partições e configurações
- melhoria a estabilidade do Kafka ao reduzir a sobrecarga de comunicações entre os brokers e o Zookeeper
  - mais simples de operar
  - menos sujeito a pontos únicos de falhas
- melhorias em termos de confiabilidade e recuperação de falhas
- projetado para ser intuitivo e robusto, garantindo consenso mesmo em cenários de falhas paricias no cluster

#### Schema Registry

- componente oferecido pela Confluent para gerenciar esquemas de dados em sistemas distribuídos
- repositório centralizado a uma API REST que armazena e versiona os esquemas Avro, JSON schema e Protobuf utilizados pelos tópicos do Kafka
  - consistência, compatibilidade e validação dos dados no tráfego entre produtores e consumidores
- no contexto de pipelines de dados
  - permite que os produtores enviem dados codificados com esquemas definidos e registrados
  - consumidores podem consultar para garantir que estão usando versão correta do esquema
    - evita erros de serialização ou incompatibilidades de estrutura
    - facilita o gerenciamento de mudanças nos dados ao longo do tempo $\to$ boas práticas da evolução dos esquemas
- garante diferentes níveis de compatibilidade entre esquemas
  - backward, forward ou total
  - novos esquemas podem ser introduzidos sem quebrar os consumidores existentes ou exigir atualizações sincronizadas em toda a aplicação
  - validação automática dos dados antes de serem escritos no Kafka
- integração perfeita com o ecossistema Kafka
  - Streams e Context
- pipelines de dados escaláveis e robustos
- melhora a eficiência do sistema ao reduzir a necessidade de armazenar esquemas completos de mensagens
  - armazena referências de esquemas registrados
  - interoperabilidade e governança de dados em sistemas distribuídos

- **Kafka Control Center:** ferramenta de gerenciamento e monitoramento projetada para simplificar a administração de clusters do Apache
  - interface gráfica intuitiva que permite visualizaçã, configuração e monitoramento de tópicos, consumidores, produtores, e outros componentes em tempo real
- facilitar a operação de pipelines de dados, maior controle e visibilidade
- **Webserver Apache Airflow** $\to$ interface gráfica para que os usuários possam interagir com o sistema
  - visualizar, monitorar e gerenciar os fluxos de trabalho (DAGs)
  - verificar logs, acompanahar a execução de tarefas, configurar variáveis e conexões
  - baseado em Flask
- **Apache Aiflow schedule** $\to$ núcleo que orquestra o workflow
  - verificação periódica de quais tarefas estão prontas para execução com base na programação definida nas DAGs, no estado das dependências e nos critérios estabelecidos pelo usuário
  - disitrbui para os workers, garantindo a priorização e os paralelismos necessários
- **Apache Airflow PostgreSQL** $\to$ backend do Airflow
  - metadados sobre DAGs, estados das tarefas, logs e outras configurações
  - garantir persistência e consistência $\to$ rastreio de histórico e fornecido das informações sobre execuções passadas
