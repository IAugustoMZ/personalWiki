### PySpark para Processamento Distribuído de Dados - Parte I

#### O que é Armazenamento Distribuído?

- sistema de armazenamento de dados que utiliza múltiplas  localizações físicas, espalhadas através de várias máquinas, ou locais geográficos, ou até mesmo infrestrutura de armazenamento.
- garantir disponibilidade, escalabilidade e redundância dos dados

1. **redundância e tolerância a falhas**: reduz risco de perda de dados
   1. recuperação de desastres e continuidade dos negócios
2. **escalabilidade**: adição de mais nós no sistema, aumentar o armazenamento, sem a interrupção significativa
3. **balanceamento de carga:** equilíbrio de carga entre vários servidores, melhorando o desempenho, eficiência de resposta às solicitações do usuário
4. **acesso concorrente:** múltiplos usuários ou aplicações podem acessar os dados ao mesmo tempo de diferentes localizações
   1. colaboração e eficiência operacional
5. **consistência dos dados:** desafiador, modelos de consistência específicos
   1. consistência eventual ou consistência forte
   2. gerenciamento de como e quando as atualizações nos dados são propagadas nos nós

- Haddop Distributed Filesystem (HDFS)
- Cassandra e MongoDB
- sistemas de armanzenamento de objetos (Amazon S3)

#### Modos de Gerenciamento do Cluster Spark

1. **Standalone:** Spark gerencia seus próprios clusters e não depende de gerenciadores externos
  - modo mais simples de configurar e é fornecido com o próprio Spark
  - testes em ambientes de desenvolvimento, produção em menor escala (sem a necessidade de configurações avançadas)
2. **YARN (Yet Another Resource Manager)**
   1. gerenciador de recursos do Hadoop $\to$ permite Spark ser executado sobre Hadoop
      1. compartilhando recursos com outros recursos computacionais
   2. permite que o Spark aloque recursos como necessário
      1. ideal para clusters compartilhados
   3. adequado para organizações que já utilizam o Hadoop e desejam integrar o Spark
3. **Mesos**
   1. granularidade mais fina no controle de recursos do que o YARN $\to$ vantajoso para certos tipos de cargas de trabalho
   2. suporta a execução de Docker containers $\to$ flexibilidade na execução de tarefas
4. **Kubernetes**
   1. plataforma de orquestração de containers, incluindo o Spark
   2. usuários podem tirar vantagens dos recursos de orquestração de containers
      1. auto-scaling
      2. isolamento de recursos
      3. gestão de configurações

##### Gerenciamento de Cluster com YARN

- sistema de gerenciamento de recursos que permite que várias aplicações de processamento distribuído compartilhem um cluster comum de forma eficiente

- **Componentes do YARN**
  1. **Resource Manager (RM):** aloca recuros e gerencia os aspectos de alto nível do cluster
     1. agendamento de jobs e o monitoramento de recursos
     2. possui dois componentes:
        1. Scheduler $\to$ aloca recursos entre aplicações
        2. Applications Manager $\to$ gerencia o ciclo de vida das aplicações submetidas ao cluster
  2. **Node Manager:**
     1. cada máquina no cluster tem um NM, que é responsável por monitorar o consumo de recursos e reportar ao Resource Manager
     2. responsável por gerenciar os containers de aplicações que executam tarefas processadas

##### Integração de Spark com YARN

###### Modo CLiente $\times$ Modo Cluster

- **no modo cliente:** o driver do Spark é executado na máquina local que submeteu a aplicação
  - executores são gerenciados pelo YARN no cluster
  - aplicações interativas com o uso do SparkShell
- **modo cluster:** tanto o drive quanto os executores são executados dentro de containers gerenciados pelo YARN no cluster
  - jobs de produção ou apps sem interatividade

###### Submissão de Jobs

- jobs submetidos ao YARN com `spark.submit` com a configuração `--master yarn`
  - especificar recursos como quantidade de memória e núcleos de CPU para o driver e para os executores

###### Alocação Dinâmica

- suportada para executores, permitindo adição ou remoção dinâmica de executores com base na carga de trabalho
  - melhorar a utilização de recursos no cluster
- habilitar: configurar a propriedade
  - `spark.dynamicAllocation.enable=true`
  - garantir que o serviço de shuffle externo do Spark esteja habilitado

#### Vantagens do Uso do Spark

- **Eficiência:** múltiplas aplicações de diferentes frameworks compartilham um único cluster $\to$ melhora a utilização de recursos
- **Escalabilidade:** facilita a gestão de grandes clusters, permitindo escala das operações de acordo com a demanda
- **Flexibilidade:** variedade de aplicações, não se limitando ao Spark, reutilização do mesmo cluster para diferentes tecnologias de processamento de dados

- gerenciamento do cluster Spark $\to$ compreensão das necessidades dos recursos das suas aplicações e a capacidade de confirmar e ajustar as propriedades do Spark e do YARN para otimizar tanto o desempenho quando a utilização de recursos
