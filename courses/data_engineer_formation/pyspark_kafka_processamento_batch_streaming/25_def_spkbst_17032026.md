### Multi-Node Cluster Spark, HDFS e Kafka

#### O que é e Quando Usar Apache Airflow?

- plataforma de código aberto para orquestrção de workflows
  - criar, programar, e monitorar pipelines de dados complexos
- workflows definidos como DAGs (*directed acyclic graphs*)
  - cada tarefa é um nó do grafo
  - dependências claras $\to$ execução em sequência ou paralela
- principais recursos
  - escrita de workflows usando Python, proporcionando flexibilidade e integração com bibliotecas
  - agendamento automático para execução em horários definidos
  - monitoramento visual com logs e alertas
  - escalabilidade para gerenciar centenas de tarefas simultaneamente
  - suporte a operadores pré-construídos para integração com bancos de dados, APIs, Hadoop, Spark e outros
- quando usar $\to$ gerenciar pipelines de dados complexos ou realizar tarefas recorrentes
  1. **Pipelines de ETL**
  2. **Orquestração de Workflows de Dados** $\to$ coordenação de tarefas dependentes, como processamento com Spark seguido de carregamento no Delta Lake
     1. garantir que uma tarefa só comece após o sucesso da outra
  3. **Automação de Processos** $\to$ agendar tarefas recorrentes como backups, sincronização de dados, geração de relatórios
     1. enviar notificações ou executar scripts automaticamente com base em eventos
  4. **Integração de Ferramentas de Big Data** $\to$ orquestrar fluxos entre ferramentas como Hadoop, Spark, Hive ou Redshift
     1. gerenciar pipelines para Machine Learning, ou preparação de dados
  5. **Monitoramento e Alertas** $\to$ configurar alertas para tarefas com falhas ou atrasos
     1. manter logs centralizados e fáceis de acessar

- quando não usar o Airflow
  - simplicidade excessiva
  - alta frequência $\to$ execução contínua e muito frequente, o Apache Kafka pode ser mais adequado

#### O que é e Quando Usar Apache Cassandra?

- sistema de banco de dados NoSQL destribuído altamente escalável e projetado para gerenciar grandes volumes de dados
  - alta disponibilidade e sem pontos únicos de falha
- modelo de armazenamento orientado a colunas
  - cenários que exigem alta capacidade de leitura e escrita de dados com baixa latência
- características: 
  - **desempenho e escalabilidade**: manipula grandes conjuntos de dados distribuídos de forma horizontal em vários nós
  - **alta disponibilidade**: projetado para garantir que o sistema continue funcionando mesmo com falhas de hardware ou rede
  - **modelo de consistência configurável:** permite ajustar o equilíbrio entre consistência, disponibilidade e tolerância a partições
  - **sem ponto único de falha:** cada nó no cluster é igual (arquitetura *peer-2-peer*)
  - **replicações multidatacenter:** suporte nativo para replicar dados em várias regiões geográficas
- **quando usar o Apache Cassandra?**
  1. **Cenários com grande escalabildidade e alta disponibilidade:**
     1. aplicções que precisam lidar com volume massivo de dados distribuídos globalmente
        1. plataformas de mídia social ou aplicativos de IoT
     2. necessidade de manter o sistema operacional mesmo durante falhas em servidores ou data centers
  2. **requisitos de alta taxa de escrita**
  3. **aplicações de baixa latência**: sistemas de recomendações em tempo real, mecanismos de busca, ou catálogo de produtos
  4. **sistemas com dados replicados globalmente:** reduzir latência percebida por usuários distribuídos geograficamente
  5. **modelos de ados orientados a colunas**: dados organizados como coleções de colunas, registros de logs, perfis de usuários ou sensores IoT
- **quando não usar o Apache Cassandra**
  - transações complexas e fortemente consistentes
    - ACID complexas, JOINs, bancos de dados relacionais
  - consultas *ad-hoc*: não é otimizado para consultas compelxas com múltiplos filtrso ou JOINs
    - melhor com esquemas de dados previamente definidos e organizados
  - baixo volume de dados: pode ser um exagero
  - análises complexas: soluções como Apache Hive, Presto ou banco de dados analíticos (Snowflake) são mais indicados
