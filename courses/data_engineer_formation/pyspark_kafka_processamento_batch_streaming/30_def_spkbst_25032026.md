## PySpark e Apache Kafka para Processamento de Dados em Batch e Streaming

### Multi-Node Cluster Spark, HDFS e Kafka

#### Fator de Replicação em um Cluster Kafka

- número de cópias de cada partição de um tópico que são mantidas no cluster para garantir alta disponibilidade e resiliência a falhas
- cada partição tem uma cópia principal (líder) e uma ou mais réplicas (followers) que são mantidas em diferentes brokers para evitar pontos únicos de falhas

- **redundância e resiliência**
  - se um broker que contém uma partição líder falhar, uma das réplicas pode assumir automaticamente o papel de líder, garantindo que os dados ainda fiquem acessíveis e o sistema continue funcionando
  - distribuição pelo cluster: os brokers no cluster são responsáveis por essas réplicas. O Kafka tenta distribuir as réplicas entre os brokers de forma equilibradas para evitar sobrecarga em um único broker
- para ganhar alta disponibilidade, é importante que o número de brokers no clusters seja pelo menos igual ao fator de replicação
