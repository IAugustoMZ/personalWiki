## PySpark e Apache Kafka para Processamento de Dados em Batch e Streaming

### Multi-Node Cluster Spark, HDFS e Kafka

#### Zookeeper

- gerenciamento e coordenação de várias funções críticas para o funcionamento do Kafka
  - **gerenciamento de metadados**: informações sobre os brokers do Kafka
    - estados, tópicos associados
    - atividades e saúde de metadados
  - **coordenação de brokers**: gerencia o processo de eleição de líderes para partições dos tópicos
    - garante que sempre existe um líder ativo
  - **configurações centralizadas**: configurações compartilhadas entre brokers
    - informações sobre tópicos, partições e réplicas
  - **detecção de falhas**: detecção e reatribuição de partições para outros brokers disponíveis
  - **controle de acesso**: armazena informações de controle de acesso e autenticação
- gradualmente sendo substituído pelo Kafka Raft
  - eliminação de dependênicas e gerenciamento direto
  - simplificação de arquitetura

#### Integração Kafka com Bancos de Dados

- Kafka  é o intemediário que permite captura, transformação e transmissão dos dados
  - útil para replicação, análise de eventos, e sincronização entre sistemas heterogêneos
- geralmente usam-se conectores especializados oferecidos pelo Kafka Connect
  - facilita transferência de dados entre Kafka e outras fontes e destinos
    - source connectors $\to$ capturar dados de bancos relacionais ou não-relacionais em tópicos do Kafka
    - sink connectos $\to$ receber dados dos tópicos e os gravam em bancos de dados
- integração de maneira contínua por meio de mudança de captura (CDC, *Change Data Capture*)
  - monitora alterações de tabelas de bancos de dados e as transmite ao Kafka
  - consistência em sistemas distribuídos ou alimentar pipelines de dados em tempo real
- configuração de particionamento e replicação $\to$ alta disponibilidade e escalabilidade
  - uso de esquemas, como Avro ou Protobuf, permite a definição clara dos dados transmitidos
- principais objetivos de uma API $\to$ facilitar a interação entre diferentes softwares, promovendo interoperabilidade e reutilização de recursos
- **serialização**: processo de converter um objeto ou estrutura de dados em um formato que possa ser facilmente armazenado ou transmitido $\to$ JSON, XML, ou binário
  - essencial para enviar dados entre sistemas ou armazená-los de forma eficiente
- UTF-8 $\to$ padrão de codificação amplamente usado
  - suporta diferentes idiomas $\to$ compatibilidade global
    - caracteres ASCII = 1 byte
    - caracteres especiais = até 4 bytes
- **desserialização**: processo inverso, onde os dados são convertidos de volta para seu estado original

##### Kafka Connect Sinks and Sources

- componente do ecossistema Apache Kafka projetado para integrar o Kafka com sistemas externos de forma escalável e confiável
  - conectores para transferência de dados entre o Kafka e outros serviços
- sources (sistemas para tópicos) e sinks (tópicos para sistemas)
  - sources $\to$ produtores automatizados
  - sinks  $\to$ consumidores automatizados

#### Processamento de Dados Multi-Stream

- capacidade de manipular e processar dados provenientes de múltiplas fontes de forma simultânea e integrada
  - vários tópicos ou fluxos de eventos, aplicando transformações e combinando informações
  - útil para dados de stream interdependentes ou complementares
    - enriquecimento de dados
- desafios de sincronização temporal e ordenação
  - dados chegando em velocidades e latências diferentes
  - mecanismos de *watermarking* e janelas temporais
    - consolidação coerente de eventos, mesmo com atrasos ou falhas da entrega
- precisa ser escalável e resiliente
  - quantidade de dados e o número de streams podem variar ao longo do tempo
  - particionamento dos dados + balanceamento de carga
