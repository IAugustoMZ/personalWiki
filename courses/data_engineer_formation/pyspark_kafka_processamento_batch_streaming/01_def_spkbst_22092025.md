## PySpark e Apache Kafka para Processamento de Dados em Batch e Streaming

### Princípios Básicos do ETL

- ETL $\to$ extract, transform and load
  - não é necessariamente contínuo
  - batch x streaming
- ETL é um conceito independente das ferramentas

#### Extração

- coleta de dados de diferentes fontes
  - estruturados e não-estruturados
- assegurar extração consistente, confiável e em intervalos regulares
  - deve garantir que não comprometa a integridade dos sistemas de origem
    - menor impacto possível
    - evitar sobrecarga ou desempenho reduzido
- pode fazer pequenas limpezas, e transformações durante a extração, mas cuidado para não sobrecarregar a fonte

#### Transformar

- não é obrigatória, mas geralmente necessária
- remover imprecisões ou erros nos dados como valores nulos
- converter dados para um formato padrão
- adicionar valor aos dados, combinando-se com outras fontes de dados ou calculando novas métricas
- resumir ou agrupar os dados
- assegurar que os dados transformados atendam aos requisitos de negócio ou às regras de governança de dados

#### Carregar

- carregar os dados no sistema de destino, que podem ser vários sistemas de armazenamento
  - atualizações incrementais $\times$ carregamentos completos
    - para atualizações muito frequentes na fonte, pode fazer mais sentido fazer atualização completa
- assegurar que os dados carregados estejam íntegros e consistentes com outras fontes de dados no sistema de destino
- otimizar o desempenho no processo de carregamento para minimizar tempos de inatividade e maximizar eficiência
- ETL também envolve considerações sobre:
  - automação de processos
  - monitoramento e logging de atividades
  - tratamento de erros
  - manutenção do histórico de dados para auditoria e conformidade

### Trabalhando com JSON e XML em Python

- tarefa comum na engenharia de dados
- usar biblioteca `json` para trabalhar com JSON
- para XML $\to$ podemos usar a biblioteca `xmletree`
  - `ElementTree`, para analisar e manipular dados XML
- **dicas adicionais**
  - **tratamento de erros**: lidar com erros de leitura e formatação
  - **uso de bibliotecas avançadas**: `pandas` também pode funcionar para JSON e `lxml` para XML
- JSON e XML são formatos extremamente flexíveis

### Conexão com Banco de Dados usando `SQLAlchemy`

- toolkit SQL e ORM para Python
  - abordagem de alto nível e abstrata para interagir com bancos de dados SQL
    - permite escrita de código Python ao invés de SQL para criar, ler, atualizar e excluir dados
- criar a engine do banco de dados (ponto de partida para qualquer interação) com o banco de dados no `SQLAlchemy`
  - engine criada a partir da string de conexão com o tipo do banco de dados
- a engine permite a execução de consultas diretas (SQL puro) ou com métodos CRM
- usar CRM para definir classes que mapeiam modelos Python para as tabelas do banco de dados
- **Considerações**
  - **segurança**: considerar aspectos de segurança como armazenamento seguro de credenciais
  - **drivers do banco de dados**: podem ser necessários adicionalmente
  - **sessões e transações**: gerenciar com cuidado, especialmene em situações de escrita, para manter a integridade dos dados
- ``SQLAlchemy`` abstrai muito dos detalhes de baixo nível do SQL, permitindo maior concentração na lógica de negócios
