### PySpark para Processamento Distribuído de Dados - Parte I

#### O que é Processamento de Streaming?

- processamento de dados em tempo real onde os dados são analisados e processados de maneira contínua à medida que são gerados ou recebidos
   - sem armazenamento intermediários
   - insights rápidos e acionáveis
- **características**
   1. fluxo de dados contínuos, de múltiplas fontes
   2. baixa latência $\to$ quase tempo real
   3. frameworks e ferramentas $\to$ diversos, Apache Kafka, Apache Flink, Apache Spark Streaming, Google Dataflow
- detecção de anomalias, monitoramento em tempo real de sistemas, análise de comportamento de usuário
   - lidar com altos volumes de dados em tempo real
   - garantir estabilidade e precisão das análises

#### Machine Learning e Deep Learning para Análise de Dados em Tempo Real

- poder de aprendizado de máquina com a capacidade de processar grandes volumes de dados continuamente
- Apache Kafka, Apache Flink e Apache Spark Streaming
- deep learning oferece capacidade mais avançadas, principalmente para o processamento de dados não-estruturados, imagens, vídeos e texto

- Redes Neurais Convolucionais (CNN) e Redes Neurais Recorrentes (RNNs)
   - reconhecimento facial em tempo real ou análise de sentimentos em redes sociais
- otimização da inferência $\to$ frameworks escaláveis como Tensorflow e PyTorch

##### Arquitetura de Autoencoder

- **encoder**: comprime a entrada em uma representação de menor dimensão
   - vetor latente, ou bottleneck $\to$ reduzir a diomensionalidade de dados
      - extrair as características mais importantes
- **decoder**: reconstrói a entrada original a partir da representação comprimida
   - a partir da informação essencial do encoder, gerar uma saída o mais parecida possível com a entrada original
- modelo treinado para minimizar a diferença entre entrada e saída reconstruída
- espaço latente $\to$ menor dimensão onde as características mais importantes são representadas de forma condensada e abstrata
- tarefas de compressão usam o espaço latente
   - manter informações mais importantes e descartar detalhes redundantes
- tarefas de *data augmentation*
- detecção de anomalias $\to$ uma entrada anômala normalmente resultará em erros de reconstrução maior

##### Função de Erro (*Loss Function*)

- mede a diferença entre a saída do modelo e o valor esperado, na forma de uma métrica numérica
   - indica o quão bem o modelo está se saindo

##### *Backpropagation*

- algoritmo usado para ajustar os pesos das conexões da rede neural, minimizando o erro calculado pela função de perda
   - **propagação para frente**: entrada passa pelas camadas do model, e o erro é calculado pela função de perda
   - **propagação para trás**: o erro é propagado de trás para frente pelo modelo. O gradiente do erro em relação aos pesos da rede é calculado
   - **atualização dos pesos**: usando o gradiente, ajuda a minimizar o erro, aproximando a saída do modelo ao valor desejado

##### Otimizador Adam

- *Adaptative Moment Esimtation* $\to$ combina o *AdaGrad* e o *RMSProp*
- uso de modelos adaptativos (média e variância) dos gradientes para ajudar o aprendizado de cada parâmetro individualmente
   - primeiro momento - média $\to$ média móvel dos gradientes para estimar a direção de atualização
   - segundo momento - variância $\to$ média móvel dos gradientes ao quadrado $\to$ variância da atualização
- vantagens
   - taxas de aprendizado adaptativas que aceleram a convergência
   - boa estabilidade em redes profundas e complexas
   - desempenho eficiente em problemas de alta variância
