# Formação Engenheiro de Dados

## PySpark e Apache Kafka para Processamento de Dados em Batch e Streaming

### Multi-Node Cluster Spark, HDFS e Kafka

#### Construindo Kafka Spark Consumer

- *watermark*: técnica usada para gerenciar dados atrasados (ou dados fora de ordem) em fluxo de streaming
- ajuda a lidar quando dados com timestamps antigos podem chegar após o processamento principal
  - janela de tolerância para atrasos
- função `withWatermark` define "marca d'água"
  - quanto tempo o Spark deve esperar por dados atrasados antes de considerar que o estado correspondente pode ser descartado

##### Como funciona o Watermark?

- **atraso tolerado**: define uma duração de atraso tolerado
- **descartar dados antigos** Spark usa a marca d'água para determinar quando pode descartar o evento de estados mais antigos do que o atraso definido
- **manter eficiência**: liberar memória e recursos, já que estados desnecessários para dados antigos são removidos

- **Benefícios**
  - **gerenciamento de dados fora de ordem**: processamento de dados atrasados sem comprometer precisão
  - **economia de recursos**: remove estados de janelas de tempo que não são mais relevantes, reduzindo o uso de memória
  - **controle de latência**: sem atrasos por conta de dados fora de ordem

#### Grupos de Consumidores e Balanceamento de Carga

- grupos de consumidores trabalham juntos para processar mensagens de um ou mais tópicos
  - identificados por um `group_id`
  - colaboração dentro de um grupo para consumo de mensagens de maneira eficiente e sem duplicação
    - cada partição de um tópico é atribuída apenas a um consumidor $\to$ garantia de processamento sequencial
- balanceamento de carga ocorre automaticamente dentro de um grupo de consumidores
  - novos consumidores adicionados, Kafka redistribui as partições
    - mesma coisa se um consumidor falhar ou for removido
  - alta disponibilidade e escalabilidade $\to$ sistemas distribuídos
- se o projeto ficar muito lento, podemos eliminar workers do Spark ou do Kafka
