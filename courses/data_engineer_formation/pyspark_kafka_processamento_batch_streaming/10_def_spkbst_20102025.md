## PySpark e Apache Kafka para Processamento de Dados em Batch e Streaming

### PySpark para Processamento Distribuído de Dados - Parte I

#### O que são dados em Batch?

- coleções de dados processados e manipulados em blocos
   - quando é viável coletar um conjunto de dados antes do processamento
- **coleta de dados**: dados acumulados durante um período definido
   - dados processados como um único lote
- **eficiência e escalabilidade**: eficiente para grandes volumes de dados
   - otimização das operações sem a necessidade de resposta imediata
   - mais fácil de escalar
- análises de dados histṕoricos, geração de relatórios períódicos, atualizações em massa em sistemas de bancos de dados

#### Limpeza e Tratamento de Dados Faltantes

1. **remoção de linhas**: podemos especificar subconjuntos de colunas
2. **preenchimento de valores faltantes**: por algum valor específico, ou uma estatística descritiva
   - também podemos fazer substituições específicas em cada coluna
3. **interpolação**: criação de lógicas customizadas para interpolar valores com base em outras linhas
   - modelos estatísticos
4. **uso de indicadores**: mostra se o valor original estava faltando
   - útil em modelagem preditiva para capturar a importância da ausência de dados

#### Desnormalização e Normalização de Dados

##### Normalização

- estruturação do banco de dados para reduzir a redundância e melhorar a integridade dos dados
- divisão de grandes tabelas em tabelas menores e definição de regras entre elas por chaves estrangeiras
   - redução da redundância $\to$ armazenamento eficiente
   - melhoria da integridade $\to$ atualizações, inserções e exclusões
- no pySpark podemos mimetizar o comportamento
   - chaves estrangeiras
   - divisão de dados em múltiplos DataFrames
- adequada para as fases de modelagem de dados, design do banco de dados
   - especialmente quando a integridade é uma prioridade e a escrita de dados é frequente

##### Desnormalização

- processo de restruturação de um banco de dados para melhorar o desempenho de leitura, combinando tabelas e eliminando necessidade de alguns JOINs
   - comum em Data Warehouses, onde o desempenho de leitura é prioritário
   - consultas mais rápidas $\to$ menos JOINs resulta em maior velocidade de consulta
   - simplificação de consultas $\to$ estrutura de dados é geralmente mais fácil de entender e manipular
- ambiente de análise e relatórios, onde a performance de leitura é crucial, frequência de atualização é relativamente baixa

#### Views Temporárias vs. Tabelas Persistentes

##### Views Temporárias

- tabela virtual  que podemos consultar durante uma sessão do Spark
   - não é armazenada fisicamente
   - desaparece quando a sessão é encerrada
- consultas eficientes $\to$ úteis para segmentar um DataFrame grande ou complexo em partes menores
   - consultas frequentes
   - sem sobrecarga I/O de dados físicos
- views temporárias são locais a uma sessão Spark
   - boas para análises ad-hoc, experimentos rápidos e transformações intermnediárias que não precisam ser reutilizadas

##### Tabelas Persistentes

- físicas e armazenadas num sistema de armazenamento do Spark, Amazon S3, ou em um sistema de arquivos local
   - armazenar dados para uso futuro
- armazenamento durável $\to$ persistem após o encerramento da sessão
- ideal para grandes conjuntos de dados que serão utilizados ao longo do tempo
- dados processados, que serão usadas repetidamente em várias análises, relatórios ou aplicações

#### Executando  SQL com PySpark

- execução de consultas complexas sobre grandes conjuntos de dados

1. configurar o ambiente PySpark e iniciar a sessão Spark (ponto de entrada)
2. criando e trabalhando como DataFrame
   - lendo de várias fontes ou diretamente de RDDs
3. registrar o DataFrame como view temporária
   - antes de executar qualquer consulta
4. executando SQL
   - método `sql` da sessão Spark para executar consultas na view
   - aceita todas as operações padrão

- Spark utiliza otimizações internamente, e às vezes, o SQL pode ser mais eficiente do que as operações equivalentes de DataFrame usando APIs do PySpark
- integração com outras fontes de dados (muitas) e com outros sistemas existentes
- familiaridade do SQL + escalabilidade e desempenho do Spark para processametno de grandes volumes de dados

#### Uso de Built-in Functions no PySpark

- pré-definidas e otimizadas para processar e analisar dados de forma eficiente
   - parte da biblioteca PySpark
   - projetadas para serem usadas diretametne em DataFrame e RDDs

- categorias de funções
   - string $\to$ manipulação de textos
   - matemáticas
   - data e hora
   - agregação
   - funções de janela $\to$ análises sequenciais ou baseadas em grupos
   - funções condicionais e de nulos

##### Vantagens das Built-in

1. otimizações automáticas $\to$ eficiente em grandes volumes de dados distribuídos
   - execução e uso eficiente de recursos 
2. simplicidade e conveniência $\to$ escrita de transformação de dados
   - maneira direta e expressiva de implementar lógicas de dados
3. escalabilidade $\to$ distribui o processamento em vários nós de um cluster
   - desempenho mesmo com  volumes de dados muito grandes
