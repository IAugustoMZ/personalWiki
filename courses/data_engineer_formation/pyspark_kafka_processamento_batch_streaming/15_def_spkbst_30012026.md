# Formação Engenheiro de Dados

## PySpark e Apache Kafka para Processamento de Dados em Batch e Streaming

### Multi-Node Cluster Spark, HDFS e Kafka

#### Tópicos, Partições, Replicação e Offset

- **Tópicos:** canais de comunicação dentro do Kafka
  - subdivididos em partições $\to$ distribuição e o processamento paralelo de dados
    - uma das razões da alta disponibilidade do Kafka (diferentes consumidores lêem dados simultaneamente)
- **Replicação:** cada partição tem seu fator de replicação
  - dados duplicados em vários brokers para garantir disponibilidade e recuperação de falhas
  - uma cópia líder, que coordena a leitura e escrita, e réplicas para fornecer redundância
- **Offset:** Número, identificador de cada mensagem enviada
  - único dentro da partição
  - permite o rastreio e gerenciamento das posições de leitura de forma precisa

#### Fluxo de Dados na Arquitetura do Kafka

1. **Produção:** mensagens em tópicos específicos $\to$ Kafka distribui nas partições do tópico
2. **Armazenamento e Replicação:** das mensagens nos brokers e as partiões podem ser replicadas em outros brokers para garantir disponibilidade
3. **Consumo:** os consumidores lêem os dados das partições dos tópicos aos quais estão inscritos
   1. cada consumidor controla seu offset $\to$ possibilita a leitura exatamente do ponto onde parou
4. **Coordenação e Monitoramento:** Kafka controller coordena a saúde do cluster, gerencia a distribuição de dados, ajuda na recuperação no caso de falhas

- arquiteturas do Kafka $\to$ escalabilidade horizontal, alto desempenho e resiliência (milhões de mensagens por segundo)
  - sistemas distribuídos

#### Por que usar HDFS, Spark e Kafka na mesma infraestrutura?

- armazenamento distribuído + processamento massivo + ingestão em tempo real
  - **HDFS** $\to$ repositório principal de dados históricos e como fonte de dados para análise batch
  - **Apache Spark** $\to$ processamento massivo de dados
    - acesso a grandes conjuntos de dados no HDFS para realizar análises avançadas, ML e transformações complexas
    - processamento em memória
  - **Apache Kafka** $\to$ backbone para pipeline de dados
    - captura e entrega de eventos ou logs de sistemas variados
    - sistemas de ingestão de dados em tempo real

- **Benefícios da Integração**
  - **ingestão em tempo real**: Kafka captura e distribui dados em tempo real
    - sensores IoT, logs de aplicativos ou transações financeiras
  - **processamento flexível**: Spark consome dados do Kafka para análise em tempo real ou do HDFS para batch
    - insights rápidos ou análises históricas
  - **armazenamento persistente (HDFS)**: armazena dados históricos e pode ser usado como backup dos dados processados por Kafka ou SPark
    - durabilidade e acessibilidade para análises futuras
