### PySpark para Processamento Distribuído de Dados - Parte I

#### RDD (Resilient Distributed Dataset) e DataFrames no Apache Spark

- **RDD (Resilient Distributed Dataset)**
  - a abstração de dados original do Spark
  - coleção imutável de objetos que podem ser processadas em paralelo
  - dividido em partições, distribuições pelos nós do cluster
- **DataFrame**
  - abstração mais alta introduzida no SparkSQL
  - coleção distribuída de dados organizados em colunas nomeadas, similar a uma tabela em um banco relacional

|| **Vantagens** | **Desvantagens** |
| --- | --- | --- |
| RDD | <li>flexibilidade $\to$qualquer tipo de transformação usando funções de baixo nível<li>controle fino e otimização dos jobs controlando partição e manipulação<li>tolerância a falhas: recuperação automática, reprocessamento das partições perdidas | <li>baixo nível de abstração (programar em RDD pode ser complexo, e propenso a erros)<li>otimização manual pode ser desafiador e demorado<li>menor desempenho em alguns casos: operações complexas e shuffling de dados |
| DataFrame | <li>alto nível de abstração: mais fácil de entender e usar<li>otimização automática (Catalyst optimizer)<li>interoperabilidade: integração com outras fontes de dados e APIs como Parquet, JSON, Hive e JDBC | <li>menos flexibilidade (muitas funcionalidades prontas para uso, personalizações profundas)<li>dependência do otimizador $\to$ poderão encontrar o plano de execução mais eficiente

#### Compreendendo o Conceito de Particionamento no Apache Spark

- maneira como os dados são distribuídos fisicamente através dos diferentes nós do cluster Spark
  - permite o processamento paralelo em diferentes nós de um cluster
- por que é importante?
  - **paralelismo:** particionamento afeta a eficiência do processamento paralelo (uso eficaz dos recursos)
  - **desempenho:** desbalanceamento de carga entre partições
  - **redução do tráfego de rede:** pode ajudar a minimizar o tráfego de rede necessário
    - operações de embaralhamento (redistribuição de dados)
- tipos de particionamento
  - **hash:** padrão para operações como `reduceByKey` e `groupBy`
    - função de hash a uma chave específica de cada dado e usa o resultado para determinar a partição que o dado será colocado
      - ajuda a garantir distribuição uniforme entre partições
  - **intervalo (range)**: usaod por operações `sortByKey`
    - partição por intervalos de chaves
    - dados ordenados ficam nas partições corretas e em ordem
- como configurar:
  - **número de partições:** ao criar o RDD ou aplicações de transformações como `repartition()` ou `coalesce()`
    - `repartition()` $\to$ aumentar ou diminuir o número de partições, envolve embaralhamento completo
    - `coalesce()` $\to$ geralmente usado para reduzir o número de partições e tenta minimizar o embaralhamento

#### Time Diff e Timestamp

- funcionalidade para trabalhar com datas e horários no Spark
- Time Diff (diferença de tempo)
  - calcular diferenças entre duas colunas de timestamps
  - medir a duração de eventos
  - expressa em unidades como segundos, minutos, ...
- Timestamp
  - pontos específicos no tempo, incluindo data e hora
  - ordenação, filtragem, agregações no tmepo
  - funções de extração de componentes de data
  - truncamento para unidades de tempo específicas
  - conversão entre formatos de data e hora

#### Window Functions no Spark

- cálculos complexos em subconjuntos de dados relacionados, sem a necessidade de agrupar os dados internamente
  - médias móveis
  - somas acumuladas
  - ranking e diferenciais
- **Definições de Janelas**
  - usando a classe `Window` $\to$ particionar e ordenar as linhas sobre as quais a função de janela será aplicada
    - janela pode ser definida por uma ou mais colunas de partição (`partitionBy`) e uma ordem específica (`orderBy`)
- **Tipos Comums de Window Functions**
  - agregações
  - ranking $\to$ rank, dense-rank, row-number
  - funções de deslocamento $\to$ lead, lag
  - funções de janela $\to$ distribuição acumulada em quantis
