### PySpark para Processamento Distribuído de Dados - Parte I

#### Ferramentas e Componentes do Apache SPark

- **Resilient Distributed Dataset (RDD)**
  - abstração fundamental do Spark, representa uma coleção imutável de objetos distribuídos através do cluster
    - RDD podem ser criados de várias formas
    - capazes de realizar operações como `map`, `filter` e `reduce`
- **Directed Acyclic Graph (DAGs)**
  - grafo acíclico direcionado para planejar a execução
  - permite a otimização do plano de execução
  - minimiza o tráfego de rede e a leitura de disco
- **Cluster Manager**
  - responsável por adiar recursos para as aplicações Spark
  - pode ser integrado a vários gerenciadores de cluster
    - YARN
    - Mesos
    - Kubernetes
    - além do próprio gerenciador do cluster Spark
- **Spark Core**
  - funcionalidade básica do Spark
    - tarefas de agendamentos, memória, gerenciamento de falhas
  - oferece APIs para a construção de RDDs e operações de transformação e ação sobre elas
- **Spark SQL**
  - permite a execução de consultas SQL em dados estruturados
  - integra-se com Hive e suporta várias fontes de dados
    - JSON, CSV, Parquet
- **Spark Streaming**
  - habilita o processamento de streams em tempo real
  - funciona dividindo os dados de streaming em micro-batches para realizar operações de RDD em tempo real
- **MLlib (Machine Learning Library)**
  - biblioteca para aprendizado de máquina
  - facilita a construção de pipelines de aprendizado escaláveis
- **GraphX**
  - processamento de grafos e análises de grafos de larga escala
  - construção de grafos
- **API de linguagem**
  - várias linguagens de programação, como Scala, Python, Java
  - oferece interface que permite executar operações Spark usando linguagem R

#### Entendendo Paralelismo e Distribuição no Spark

- **paralelismo:** execução simultânea de múltiplas tarefas
  - no contexto do Spark, dividir uma tarefa grande em sub-tarefas menores que podem ser executadas ao mesmo tempo em diferentes núcleos de processadores ou até mesmo em diferentes máquinas
- **RDD (Resilient Distributed Datasets):** são divididas em várias partições
  - cada partição pode ser processada em paralelo em um núcleo CPU diferente
  - o número de partições de um RDD influencia diretamente o nível de paralelismo, pois cada partição pode ser processada simultaneamente
    - operações como `map` e `reduce`, de forma que cada partição pode ser processada simultaneamente
- Spark usa um gerenciador de cluster para distribuir e gerenciar tarefas através dos nós do cluster
  - aloca recursos como CPU e memórias para os diferentes nós e garante a execução de maneira eficiente
- RDDs são distribuídos através do cluster
  - diferentes partes do conjunto de dados estão localizados em diferentes máquinas
  - permite processamento de dados que não caberiam na memória de uma única máquina
- traz desafios como tolerância a falhas
  - usa RDD para reconstruir automaticamente, garantindo a resiliência do sistema

#### Transformações e Ações em RDDs

##### Transformações

- operações que criam um novo RDD a partir de um RDD existente
  - aplicadas de forma "lazy" $\to$ não são executadas imediatamente
  - execução apenas quando uma ação é realizada
- características
  - **lazy evaluationa:** define uma nova operação no DAG, mas não é computada até que seja necessária
  - **imutabilidade:** cada transformação cria um novo RDD, pois os RDD são imutáveis
- exemplos:
  - `map()`
  - `filter()`
  - `fillup()`
  - `union()`
  - `distinct()`

##### Ações

- devolvem um valor final após processar operações nos dados de um RDD
  - forçam as execuções das transformações e operações RDD
- características
  - **triggering computations:** são responsáveis por iniciar as computações no Spark, ativando a execução da DAG
  - **produz resultados:** Spark retorna um resultado concreto, que pode ser um valor, uma coleção de valores ou escrita num sistema de armazenamento
- exemplos:
  - `collect()`
  - `count()`
  - `take(n)`
  - `reduce(func)`
  - `saveAsTextFile(path)`
