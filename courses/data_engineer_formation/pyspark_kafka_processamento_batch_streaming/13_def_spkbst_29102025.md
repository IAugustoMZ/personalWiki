# Formação Engenheiro de Dados

## PySpark e Apache Kafka para Processamento de Dados em Batch e Streaming

### PySpark para Processamento Distribuído de Dados - Parte I

#### Conceitos Fundamentais do PySpark Streaming

- extensão que permite processar fluxos contínuos de dados
  - divisão em micro-batches para processamento distribuído
- capacidade de processamento paralelo e escalável, aplicando a dados que chegam de fontes como Kafka, sockets ou sistemas de filas de mensagens

1. **DStream (Distributed Stream)** $\to$ fluxo contínuo de dados, onde os dados em tempo real são divididos em micro-batches
   1. cada micro-batch é tratado como um RDD no tempo
   2. processamento de forma distribuída
2. **Micro-batch**: intervalos discretosd para processamenmto, facilitando operações paralelas e distribuídas
3. **Receivers**: capturar dados de fontes externas e repassá-los para o sistema de streaming
   1. podem ser confiáveis ou não, dependendo da necessidade de confirmar a entrega dos dados
4. **Window Operations:** agregar ou analisar dados dentro de uma janela de tempo
   1. cálculos
   2. insights sobre dados de diferentes intervalos temporais
5. **Stateful Operations:** manter o estado dos dados entre as micro-batches
   1. acompanhamento das informações em tempo real
6. **Checkpointing:** armazenar dados intermediários e garantir a resiliência em casos de falhas
   1. cenários críticos onde é necessário recuperar o estado e e continuar o processamento sem perda de dados

#### Principais Práticas de Tratamento e Limpeza de Dados em Stream

1. filtragem de dados irrelevantes ou corrompidos
2. conversão de tipos de dados
3. tratamento de valores nulos ou ausentes
4. normalização e padronização
5. deduplicação: streaming pode gerar dados duplicados
   1. identificação e remoção de duplicatas com base em chaves ou IDs exclusivos
6. agregação e enriquecimento de dados: operações de JOIN ou windowing

##### Windowed Operations

- processar e agregar dados que chegam ao longo de uma janela de tempo específica
  - **janela de tempo (window):** o intervalo de tempo em que os dados serão agrupados e processados
  - **deslizamento da janela (sliding interval):** intervalo que a janela é recalculada

##### Stateful Processing

- manter estado entre micro-batching, rastreio e acúmulo de informações ao longo do tempo
  - padrões que se estendem para além de uma janela de tempo

1. **atualização de estado (`updateStateByKey`)**: manter um estado associado a cada chave de um stream
2. **`mapWithState`**: API mais avançada $\to$ rastrear eventso complexos e associar transformações adicionais a cada chave
   1. flexibilidade para definir o que é "estado"
3. **Chekpointing**: garantir que em caso de falhas, o estado possa ser recuperado e o processamento continue sem perda de dados
   1. salver periodicamente o estado atual num armazenamento resiliente

##### Persistência de Dados Processados em Tempo Real

- garantir disponibilidade posterior dos dados

1. **Armazenamento em Bancos de Dados Relacionais e NoSQL**
   1. **relacionais**: uso de JDBC para inserção de dados nas tabelas
   2. **NoSQL**: MongoDB, Cassandra, HBase são opções eficazes
      1. grandes volumes de dados não estruturados ou semi-estruturados
2. **Datalakes e Data Warehouses**
   1. **Data Lake:** arquivos estruturados (Parquet, JSON, CSV), que podem ser analisados por sistemas Big Data
   2. **Data Warehouses:** análise agregada ou construção de relatórios complexos
3. **HDFS (Hadoop Distributed File System):**
   1. dados gravados diretamente no cluster
   2. comuns em pipelines de Big Data $\to$ larga escala
4. **Sistemas de Mensagens (Kafka, RabbitMQ):**
   1. alta disponibilidade e baixa latência
5. **Sistemas de Arquivos:**
   1. JSON, CSV, Parquet, Avro
   2. distribuídos ou locais
6. **Elasticsearch:** persistir dados para buscas binárias ou visualizações em Dashboards
   1. dados de logs ou métricas em tempo real

##### Checkpointing no PySpark Streaming

- técnica para garantir a resiliência e a recuperação do sistema em caso de falhas
- armazenamento periódico de informações importantes
  - estado de processamento
  - dados de streaming
- quando ocorre uma falha $\to$ Spark pode recuperar o estado salvo no último checkpoint e retomar o processamento a partir desse ponto
- **Checkpointing de Dados (Metadata Checkpointing)**
  - informações sobre o progresso do processamento
  - não mantém o estado das transformações específicas ou de operações complexas
- **Checkpointing de Estado (State Checkpointing)**
  - stateful processing $\to$ armazena o estado completo das operações
  - útil em cenários `updateStateByKey` ou `mapWithState`
- checkpointing recomendado para garantir a consistência e a durabilidade dos dados em pipelines de streaming
  - aplicações resilientes e tolerantes a falhas 

#### Integração do Spark Streaming com Fontes de Dados Externas

- ampla variedade de fontes de dados suportada

1. **Apache Kafka:** conector nativo do Spark Streaming
   1. `KafkaUtils.createDirectStream` $\to$ consumo eficiente e controle de offset
2. **Sistemas de Mensageria:** consumir dados de filas ou tópicos para processamento distribuído e escalável
   1. Amazon Kinesis para ingestão de dados em pipelines baseados em nuvem
3. **Arquivos em Tempo Real:** sistemas de arquivos distribuídos, dados processados, assim que são salvos nos file systems
   1. útil para arquivos de logs ou arquivos batch periodicamente atualizados
4. **Bancos de Dados relacionais e NoSQL**
   1. usando conectores JDBC
   2. integrações com Spark de bancos NoSQL  como Cassandra e MongoDB
5. **Socket:**
   1. suporte à ingestão via sockets de rede
   2. útil para cenários simples onde dados são transmitidos através de conexões TCP/UDP
      1. dados de sensores, logs, ou mensagens

#### Monitoramento e Debugging de Aplicações de Streaming de Dados

- garantir que os sistemas em tempo real funcionem de forma eficiente e sem interrupções
  - resolver problemas rapidamente
  - garantir processamento correto
- UI Spark oferece uma visão abrangente das aplicações
  - monitorar a duração dos jobs, status de micro-batches, uso de recursos
- sistema robusto de logs $\to$ possibilita capturar eventso , falhas, e exceções em tempo real, auxiliando no diagnóstico de problemas
  - uso de sistemas distribuídos para armazenar os logs
- Spark Streaming coleta métricas de desempenho
  - monitoramento de latências, throughput e o uso de recursos
- métricas de backpressure são úteis ajustando a taxa de ingestão de dados com base na capacidade do sistema, evitando sobrecargas
  - ferramentas de monitoramento
  - visão em tempo real do estado do sistema
- debugging facilitado com o uso de checkpointing
  - resiliência dos sistema em caso de falhas
- desenvolvimento e teste $\to$ *local Spark Context*
  - frameworks $\to$ Spark Testing Base
  - permitem testar a lógica de streaming em ambientes locais com dados simulados

#### Estratégias de Backpressure e Rate Limiting

-  garantem que o sistema de processamento de stream possa lidar com a ingestão de dados de forma eficiente, sem sobrecarga de recursos
   -  equilíbrio entre a taxa de ingestão e de dados com a capacidade de processamento do sistema
-  **Backpressure**
   -  ajuste automático da taxa de ingestão de dados com base no tempo de processamento dos micro-batches 
   -  reduz a taxa de ingestão para evitar o acúmulo excessivo de dados não processados
      -  `spark.streaming.backpressure.enabled`
      -  sistema monitora o tempo de processamento e ajusta dinamicamente o upload dos dados
-  **Rate Limiting**
   -  complementa o backpressure ao definir os limites explícitos de quantidade de dados ingerida a cada período de tempo
   -  configurar taxa máxima de dados
      -  `spark.streaming.receiver.maxRate`
   -  útil em cenários onde a fonte de dados pode gerar picos inesperados de dados.
