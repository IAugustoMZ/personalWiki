# Formação Engenheiro de Dados

## PySpark e Apache Kafka para Processamento de Dados em Batch e Streaming

### Multi-Node Cluster Spark, HDFS e Kafka

#### O Kafka é um Banco de Dados?

- não, é uma plataforma de streaming de dados distribuída para lidar com o processamento e transmissão de grandes volumes em tempo real
  - permitir a comunicação de forma eficiente entre diferentes sistemas
  - modelo de assinatura / publicação $\to$ consumo e produção de maneira assíncrona
- ingestão de dados, processamento em tempo real e integração entre sistemas
- armazenamento das mensagens em tópicos por um período configurado
- não oferece suporte a consultas avançadas com SQL ou busca indexada
- não possui garantia de consistência transacional como sistemas ACID
- dados armazenados de forma efêmera, dependendo do tamanho ou tempo configurado
- existem ferramentas para processar dados diretamente no Kafka (Kafka Streams e KSQL)

#### O que são Mensagens no Kafka?

- unidade básica de dados que é escrita e lida de um tópico
  - contém informações transmitidas de um produtor e lidas por um consumidor
- composição de uma mensagem
  - **chave (key):** identificar opcional usado para particionamento. Mensagens com a mesma chave são enviadas para a mesma partição
  - **valor (value):** conteúdo principal da mensagem
    - qualquer daod, texto, JSON, XML, binário ou qualquer outro formato
  - **timestamps:** informações de tempo associados à mensagem, como o momento em que foi criada ou registrada no Kafka
  - **cabeçalhos (headers)**: dados opcionais que podem ser usados para transportar informações adicionais sobre a mensagem, como metadados
- mensagem $\to$ tópico $\to$ partições $\to$ mensagens ordenadas
  - escalabilidade e consumo paralelo das mensagens pelos consumidores
- mensagens são imutáveis
  - permanecem no Kafka por um tempo determinado ou até atingir um limite de espaço, mesmo depois de terem sido consumidas
    - processamento de eventos, streaming em tempo real e replay de dados

#### Produtores e Consumidores

- **Produtores** $\to$ enviar as mensagens para os tópicos no Kafka
  - origem dos dados, aplicações, sensores ou sistemas que geram eventos ou registros
  - escrever mensagens em um ou mais tópicos
    - pode especificar uma chave para particionamento
    - pode ser particionado de acordo com algoritmos pré-definidos
      - hashing de chave
    - pode ser particionado de forma aleatória
  - mensagens numa mesma partição são armazenadas em ordem $\to$ mantêm a ordem lógica dos eventos
- **Consumidores** $\to$ lêem as mensagens dos tópicos no Kafka
  - sistemas de processamento ou utilização dos dados gerados pelos produtores
  - pode se inscrever em um ou mais tópicos e processar as mensagens das partições associadas
  - podem ser organizadas em grupos de consumidores, onde cada partição de um tópico é atribuída a apenas um consumidor dentro do grupo
  - permite que os consumidores escolham de onde começara ler as mensagens
    - início do tópico ou apenas mensagens recém chegadas

- no projeto, 3 terminais serão abertos
  - Kafka, HDFS, Spark
- projeto inclui a geração dos dados em tempo real e o consumo em tempo real pelo Spark
  - necessário instalar os pacotes necessários para executar os scripts de geração de dados
- JARs (*Java Archive Files*) $\to$ arquivos compactados que contêm bibliotecas, classes e metadados necessários para executar programas Java
  - Kafka: armazenar as implementações de clientes, produtores, consumidores e outras bibliotecas
- aplicativo que consome mensagens de um tópico Kafka
- JARs de bibliotecas Kafka (Kakfa-clients) fornecem APIs para interagir com clusters Kafka
- Kafka Connect $\to$ ferramentas do Apache Kafka para transferir grandes volumes de dados entre o Kafka e outros sistemas de forma escalável e confiável
  - conectores $\to$ são plugins que facilitam essas integrações
    - **source connectors:** leem dados de sistemas externos e publicam em tópicos Kafka
    - **sink connectors:** consomem dados de tópicos Kafka e os enviam para sistemas externos
- às vezes precisamos modificar versões para garantir compatibilidade
  - Spark não se integra nativamente a muitos outros softwares $\to$ precisamos dos arquivos JAR que atuam como conectores
    - `maven central repository` $\to$ classes Java que permitem a execução e integração entre sistemas
- Kafka Confluent $\to$ necessário para produzir os dados na forma esperada pelo broker Kafka
  - após a geração de dados $\to$ encaminhamento para o tópico do Kafka
    - tópico será criado no Kafka se ele não existir na primeira tentativa de publicação
    - o que é enviado para o Kafka é um objeto produzido no formato *key-value*
- na produção dos dados, devemos focar no mínimo possível de intervenções (transformações) para que dados não sejam perdidos
