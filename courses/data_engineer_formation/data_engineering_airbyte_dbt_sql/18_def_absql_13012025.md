# Formação Engenheiro de Dados

## Engenharia de Dados com Airbyte, DBT e SQL

### O que são Testes Automatizados no dbt?

- verificações progrmáticas para ajudar a garantir qualidade e inegridade de dados
  - inconsistências, valores esperados e problemas de qualidade
- configuração em YAML -> tabelas ou colunas específicas
- testes pré-definidos
  - `NOT NULL`
  - `UNIQUE`
  - accepted values -> conjunto pré-determinado
  - referential integrity -> validação dos relacionamentos entre tabelas
- dbt permite a criação de testes específicos


#### Tipos de Testes no dbt

1. nativos -> já fornecidos pelo YAML
2. personalizados -> queries SQL
   1. comparação de valores em colunas distantes
   2. verificação de intervalos ou padrões de dados
   3. validações complexas (múltiplas tabelas ou junções)
3. testes de dados adicionais
   1. macros e lógicas adicionais
   2. controle e validação de regras

#### Como Funcionam os testes no dbt

- consultas execuadas contra dados transformados
- views temporárias criadas durante os testes ou tabelas intermediárias

1. **definição e configuração**
   1. mesmo arquivos onde estão os modelos dbt (arquivos .yml)
      1. associar em tabelas ou colunas -> especificação das regras de validação desejadas
2. **execução dos testes**
   1. gera consultas SQL para cada teste configurado
   2. execução de consultas no banco
   3. views temporárias ou tabelas com os resultados dos testes
3. **interpretação de resultados**
   1. relatório indicando testes falhos e sucessos
   2. cada falha detalha para investigação da origem
4. **integração com CI/CD**
   1. integração com CI/CD e testes automatizados
   2. verificação das alterações dos dados antes de serem enviadas para produção
      1. deploy pode até ser impedido

#### Benefícios dos Testes Automatizados n dbt

1. **qualidade e consistência dos dados**
   1. critérios devem ser atendidos
2. **detecção rápida dos erros**
3. **automação e escalabilidade**: consistência em uma execução do pipeline
4. **facilidade do depuração**: informações detalhadas sobre falhas
5. **integração CI/CD**: integração de testes no deploy, verificação antes do envio para produção
6. **manutenção de conformidade e segurança**: regulatória, políticas internas de governança
7. **redução de curstos e tempo de revisão**: auditoria manual de qualidade de dados
8. **confiança na análise de dados**: dados constantemente validados

### Uso de Hooks e Triggers

- ações automáticas que podem ser configuradas antes ou depois de certos eventos do pipeline de dados

#### Hooks

- comandos SQL executados automaticamente antes ou depois de um estágio do ciclo de vida do projeto
  - tarefas customizadas
    - modificar tabelas temporárias
    - ajustar permissões
    - inserir dados em tabelas de auditoria
    - limpar ou preparar dados
    - registrar logs ou auditorias
    - gerenciar permissões

#### Triggers

- não são um conceito nativo
- mecanismo semelhante aos dos bancos de dados
  - eventos automáticos que disparam ações específicas em respostas a mudanças em tabelas ou dados
- hooks implementam coisas parecidas
