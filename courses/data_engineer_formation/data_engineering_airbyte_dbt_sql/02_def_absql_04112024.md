# Formação Engenheiro de Dados

## Engenharia de Dados com Airbyte, DBT e SQL

### Ciclo de Vida do Projeto ETL / ELT

#### 1. Requisitos de Negócio e Análise

- necessidades do processamento de dados
- determinar fontes de dados, entender estrutura e qualidade
- definir requisitos de qualidade e KPIs para o processo ETL / ELT

#### 2. Planejamento e Design

- modelo de dados para Data Warehouse ou hierarquia de dados para Data Lake
- pipeline de dados, mapeamento da origma para destino
- projeto arquitetura do job ETL
  - hardware
  - software
  - rede
- estratégia da transformação de dados

#### 3. Desenvolvimento do Job

- ferramenta(s)
- desenvolver scripts ou usar ferramentas ETL
- configurar ambientes de desenvolvimento, teste e produção
- implementação das transformações

#### 4. Tests Unitários

- testes unitários para validar etapas individuais
- testes de sistema para garantir todo o processo ETL / ELT
- conduzir testes de aceitação do usuário para garantir aceitação das necessidades do negócio

#### 5. Implementação

- migrar o job para ambiente de produção
- executar um ou mais ciclos de carga completas ou carga incremental de dados
- monitorar desempenho e ajustar conforme necessário

#### 6. Documentação

- garantir que o processo seja bem compreendido e possa ser mantido
- fornecer referências para a solução de problemas e futuras melhorias

#### 7. Monitoramento e Manutenção

- monitoramento desempenho, corrigir problemas
- ajustar transformações, adicionar novos dados conforme evolução dos requisitos
- garantir atendimento aos requisitos de qualidade e desempenho

#### 8. Auditoria, Controle de Qualidade e Refinamento

- conformidade com regulamentos e padrões internos
- controles de qualidade, correção de problemas
- refinar para melhorar a eficiência e o desempenho

- ciclo de vida é iterativo, executado enquanto o processo é necessário
- regulamentos de privacidade e proteção de dados
- lidar com escalabilidade
- manter ciclos de feedback com usuário finais (alinhamento com necessidades do negócio)

### Tratamento de Dados Faltantes

#### Técnicas para se lidar com dados ausentes

- análise de sensibilidade, análise exploratória

1. ignorar ou excluir
2. imputação
   1. média, mediana, moda
   2. *hot-deck* - valores aleatórios de conjunto de dados semelhantes
   3. KNN: observações mais próximas
   4. Múltiplas, analisando cada conjunto e combinando os resultados
   5. Condicional: outra colunas
3. Algoritmos
   1. Regressão
   2. Machine Learning
4. Verossimilhança
5. Bayesianos
6. Uso de Modelos Robustos a dados ausentes

#### Tratamento de Dados Duplicados

1. identificar duplicatas
2. examinar
3. critérios de unicidade
4. estimativa de tratamento
5. automatizar detecção e remoção
6. prevenir
7. monitorar
8. documentar

#### Validação de Qualidade de Dados

- dados preciso, consistentes e utilizáveis
- adequação para atender requisitos
  - precisão, integridade, atualidade, consistência, relevância

##### Aspectos da Qualidade dos Dados

- **Precisão:** dados corretos e livres de erros
- **Integridade:** Completude dos dados
- **Atualidade**
- **Consistência:** emt odos os sistemas e formatos
- **Relevância:** pertinentes e adequados para o propósito
- **Confiabilidade:** fonte e processo de extração
- **Unicidade:** sem duplicatas

1. critérios -> 2. validações -> 3. auditar e limpar -> 4. regras de validação -> 5. monitorar -> 6. automatizar -> 7. testar -> 8. tratar exceções -> 9. documentar -> 10. revisar e melhorar continuamente

### Versionamento de Pipelines de Dados

- gerenciamento de mudanças e colaboração

1. **sistemas de controle de versão**
   1. rastrear mudanças
   2. reverter versões
   3. *branching* e *merging*
2. **versionar artefatos relacionados**
   1. scripts de transformação
   2. arquivos de configuração
   3. modelos de dados
   4. notebooks para análise
   5. arquivos IaC
3. **convenções de nomenclatura**
   1. semântica de versionamento
   2. marcos ou sprints
   3. tipos de ambiente
4. **automatizar o versionamento**
   1. *hooks* de pré-commit (testes / quality checks)
   2. *hooks* de post-commit para tageamento
   3. triggers de CI para construir e testar o pipeline
5. **documentar alterações**
   1. novos recursos
   2. correções de bugs
   3. mudanças na infraestrutura
6. **controlar dependências**
   1. bibliotecas ou pacotes
   2. SGBDs e motores de execução
   3. containers Docker
7. **versionar dados**
   1. isolar ambientes
   2. pipelines implantados e versionados em cada ambiente
8. **ferramentas de CI/CD**
   1. Jenkins, GitLab CI/CD, GitHub Actions
   2. automatizar implantação e teste
9. **monitoramento e alerta**
   1.  saúde dos pipelines
10. **treinamento e conscientização**
    1.  práticas de versionamento / controle de versão
    2.  governança de dados e operações
