# Formação Engenheiro de Dados

## Engenharia de Dados com Airbyte, DBT e SQL

### Arquitetura e Componentes do dbt

- projetado para facilitar a transformação de dados
- baseada em componentes

1. *models* (modelos)
   1. arquivos SQL que definem as transformações de dados
   2. tabela ou view no Data Warehouse
   3. modular e reutilização
   4. estrutura de diretórios
2. *sources* (fontes)
   1. tabelas brutas de onde os dados são extraídos
   2. documentar e testar os pipelines de dados
   3. arquivos YAML
      1. descrição da oriem
      2. estrutura dos dados
      3. metadados
      4. testes de qualidade
3. *seeds* (sementes)
   1. pequenos conjuntos de dados carregados no DW a partir de arquivos CSV
   2. armazenar dados de referência, configuração e pequenas tabelas de mapeamento que não mudam frequentement
   3. garantir consistência e integridade
4. *snapshots* (instantâneos)
   1. captura e acompanhamento de mudanças nos dados ao longo do tempo
   2. rastrear histórico de alterações
   3. auditoria de mudanças
   4. arquivos YAML -> lógica da captura
5. *tests* (testes)
   1. scripts SQL que verificam integridade e qualidade dos dados
   2. testes genéricos -> valores comuns (nulos ou unicidade)
   3. testes personalizados -> regras de negócio específicas
6. *documentation* (documentação)
   1. gerada automaticamente a partir dos outros módulos
   2. descrições, comentários e metadados
   3. documentação navegável (web)
7. *macros*
   1. funções SQL reutilizáveis para automação de tarefas repetitivas, padronização
   2. Jinja -> linguagem de templates, pode encapsular lógica SQL
8. *settings* (configurações)
   1. ajustar comportamento de modelos, fontes, seeds, snapshots
   2. materializações (table, view, incremental)
   3. opções de performance e execução
      1. global
      2. modelo
      3. projeto

### dbt Semantic Layer

- camada de abstração que facilita a definição, gestão e uso de métricas e conceitos de negócios de maneira centralizada e consistente
  - mesmas definições de métricas para toda organização
- resolver problemas de consistência e deuplucação na definição de métricas e cálculos de negócios
  - consistência

#### Componentes da Semantic Layer

1. *metrics* (métricas) -> cálculos de negócio
   1. definição usando SQL
   2. lógicas complexas para consistência em diferentes contextos
   3. repositório central
2. *dimensions* (dimensões) -> atributos descritivos usados para segmentar ou categorizar métricas
   1. dividir e analisar diferentes perspectivas
   2. definidas juntamente nas métricas para garantir consistência
3. *semantic models* (modelos semânticos)
   1. camadas de abstração que agrupam métricas para um contexto claro para negócios
   2. analistas interagem com conceitos de negócios em vez de tabelas e colunas
4. *documentation and metadata* (documentação e metadados)
   1. detalhada definições e contextos das métricas e dimensões
   2. informações sobre a origem dos dados, métodos de cálculos e qualquer transformação
   3. transparência e governança dos dados


- **benefícios**
  - consistência e confiança dos dados
  - facilidade de uso e colaboração
  - integração com ferramentas de BI
  - governança e transparência
