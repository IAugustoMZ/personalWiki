## Engenharia de Dados com Airbyte, DBT e SQL

### SQL Avançado para Transformações de Dados

#### Subconsultas

- consultas aninhadas dentro de outras consultas
- usar o resultado da consulta interna na consulta externa
  - **1. correlacionadas:** externa depende da interna. A consulta interna é executada para cada linha da externa
  - **2. não correlacionadas:** não dependem da externa e a consulta interna é executada uma única vez

#### Common Table Expression

- tabela temporária que pode ser referenciada
  - simplificar consultas complexas, recursivas

```sql
WITH CTE AS (
    SELECT campo1, campo2
    FROM tabela
    WHERE condicao = 'valor'
)
SELECT * FROM CTE
```

#####  Subconsultas correlacionadas

```sql
SELECT e.salario, e.nome
FROM empregados e
WHERE salario > (
    SELECT AVG(e2.salario)
    FROM empregados e2
    WHERE e2.departamento_id = e.departamento_id
)
```

#####  Subconsultas não correlacionadas

```sql
SELECT nome, salario
FROM empregados
WHERE departamento_id IN (
    SELECT departamento_id
    FROM departamentos
    WHERE localizacao = 'New York'
)
```

##### CTEs Recursivas

- consultas recursivas para dados hierárquicos

```sql
WITH RECURSIVE hierarquia (campo1, campo2) AS (
    SELECT campo1, campo2
    FROM tabela
    WHERE condicao = 'base'
    UNION ALL
    SELECT t.campo1, t.campo2
    FROM tabela t
        INNER JOIN hierarquia h ON
            t.campo1 = h.campo2
)
SELECT * FROM hierarquia
```

#### Otimização de Consultas SQL

1. selecionar colunas específicas (evitar o `SELECT *`)
2. utilizar cláusulas `WHERE` (operações como `LIKE` não utilizam índices eficientemente)
3. uso eficiente de `JOIN`
   1. `INNER JOIN` é mais eficiente que `OUTER`
   2. `JOIN` usando colunas de índices
4. evitar o uso de funções no `WHERE`, pois impedem o uso de índices
5. lmitar resultados com `LIMIT` \ `OFFSET`
6. usar subconsultas e CTEs com cuidado
   1. especialmente se são chamadas várias vezes

##### Técnicas de Indexação

- acelerar buscas no banco de dados
  - índices de colunas frequentemente usadas, `WHERE`, `ORDER BY`, `JOIN`
    - índices excessivos prejudicam operações de escrita
  - índices compostos em múltiplas colunas quando as consultas envolverem várias colunas
    - ordem das colunas importa -> primeira coluna deve ser a mais usada
  - índices de texto completo para buscas de textos grandes
  - dividir a tabela por partições
  - aumentar fisicamente dados na forma do índice
  - remover índices ineficazes

### Funções de Janela e Análise com Linguagem SQL

- funções analíticas -> cálculos complexos em um conjunto de linhas relacionados
  - mantêm a granularidade original dos dados
  - operações como sumarização, medidas móveis, rankinks
- conceitos
  - `OVER()` -> define a janela sobre a qual a função opera. Dentro, especificamos as operações
  - `PARTITION BY` -> dividir os dados em partições distintas, sem reduzir o número de linhas retornadas
  - `ORDER BY` -> especificar a ordem das linhas para a função de janela
  - `ROWS/RANGE` -> subconjunto de linhas em cada partição
- exemplos de funções de janela:
  - `ROW_NUMBER()` -> atribui número único para cada linha, começando com 1

    ```sql
    SELECT 
        nome, departamento, salario,
        ROW_NUMBER() OVER (PARTITION BY departamento ORDER BY salario)
    FROM empregados
    ```
  - `SUM()`, `AVG()` -> calcula a soma ou a média para um conjunto definido de linhas

    ```sql
    SELECT 
        data, valor,
        SUM(valor) OVER (PARTITION BY data) AS soma_diaria,
        AVG(valor) OVER (PARTITION BY data) AS media_diaria
    FROM vendas
    ```
  - `LEAD()`, `LAG()` -> acessa dados da linha seguinte ou anterior sem realizar um auto-join
    - bom para compara valores em sequência

    ```sql
    SELECT 
        data, valor,
        LAG(valor, 1) OVER (ORDER BY data) AS valor_ant,
        LEAD(valor, 1) OVER (ORDER BY data) AS valor_seg
    FROM vendas
    ```
  - `RANK()`, `DENSE_RANK()` -> fornece um ranking para cada linha dentro de uma partição
    - no caso de empate, `RANK()` deixa lacunas
    - `DENSE_RANK()` não deixa lacunas

    ```sql
    SELECT 
        nome, departamento, salario
        RANK() OVER (PARTITION BY departamento ORDER BY salario DESC)
    FROM empregados
    ```
  - `NTILE()` -> divide as linhas ordenadas em um único número definido de grupos de tamanho aproximadamente igual

    ```sql
    SELECT 
        nome, salario,
        NTILE(4) OVER (ORDER BY salario DESC) as quartil
    FROM empregados
    ```
