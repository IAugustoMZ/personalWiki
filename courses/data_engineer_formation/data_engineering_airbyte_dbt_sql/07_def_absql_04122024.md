# Formação Engenheiro de Dados

## Engenharia de Dados com Airbyte, DBT e SQL

### SQL Avançado para Transformações de Dados

#### Elementos do Plano de Execução

- **sort** - organiza os resultados da consulta em uma ordem específica, com base em uma ou mais colunas
- **hash aggregate** - agrupa linhas de dados em grupos baseados em uma ou mais colunas e calcula as estatísticas
  - agrupamento por *hash* da coluna de agregação
  - eficiente para grandes conjuntos de dados  se grupos são pequenos
- **hash** - tabela de *hash* em memória a partir de uma tabela base ou de uma subconsulta
  - preparação para um *hash join* ou *hash aggregate*
- **hash join** - operador *hash* usado para juntar duas tabelas baseando-se na igualdade
  - eficiente quando uma das tabelas é pequena ou pode ser particionada para caber na memória
- **seq scan** - leitura sequencial de todas as linhas da tabela
  - aplica o filtro `WHERE` especificado na cláusula
  - quando não há índices apropriados, ou quando a leitura sequencial é mais eficiente (tabelas pequenas)

##### Exemplos e Contextos de Uso

- **sort** - consultas com `ORDER BY`
- **hash aggregate** - `GROUP BY`
- **hash join** - condições de igualdade
- **hash** - antes de *hash aggregate* ou *hash join*
- **seq scan** - acesso direto e sequencial, sem filtros ou índices

- tabelas *hash* não é exclusiva do banco de dados
  - estrutura de armazenamento

- **função de hash**
  - transforma a chave em um índice em array (vetor) -> valor armazenado
  - colisões -> quando duas chaves possuem o mesmo índice
  - **encadeamento (chaining)** -> cada índice no array aponta para uma lista de pares chave-valor que mapeiam para o mesmo índice
  - **enderçamento aberto (*open addressing*)** -> quando ocorre uma colisão, o algoritmo busca outro índice livre

- **eficiência**
  - inserção, exclusão, busca -> O(1), desde que a função seja boa, e a tabela não seja muito cheia.
