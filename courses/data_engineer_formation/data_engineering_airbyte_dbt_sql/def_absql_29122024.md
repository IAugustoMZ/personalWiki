# Formação Engenheiro de Dados

## Engenharia de Dados com Airbyte, DBT e SQL

### O que é Transformação de Dados?

- processo de converter or modificar dados de um formato ou estrutura para outro
  - integração de sistemas
  - análises de dados
  - migração de dados
- principais aspectos
  - limpeza de inconsistências, duplicatas e erros
  - normalização -> padrão comum
  - agregação -> combinação de múltiplos conjuntos de dados
  - enriquecimento -> informação adicionais
  - formatação -> tipos ou estrutura
- **aplicações práticas**
  - ETL
  - integração de sistemas
  - análises de dados

#### Como escrevemos transformações no dbt?

- transformações em SQL + práticas de engenharia de software

1. **definição de modelos** - arquivos SQL ou Jinja da pasta models
2. **utilizar macros e Jinja** - código mais reutilizável e dinâmico
3. **configurar dependências** - função `ref()`; garantir a ordem correta de execução
4. **gerar documentação** - descrição e metadados nos modelos
5. **testes** - qualidade e integridade

#### Uso de Módulos e Funções

- modularizar, organizar e reutilizar código
- **módulos**: macros definidas e reutilizadas em diferentes modelos
  - definidas em arquivos `.sql`
  - dentro da pasta macros
  - funções ou trechos de código SQL
  - lógicas reutilizáveis e dinâmicas
- **funções**: linguagem Jinja
  - blocos de código dinâmico
  - manipular ou gerar SQL com base em parâmetros
  - funções embutidas
    - loops
    - condicionais
    - variáveis e manipulaçãode strings

### O Conceito de Macro de dbt

- blocos Jinja para gerar consultas SQL e funções dinâmicas personalizadas
- reduzir repetição
- **características principais**
  - **reutilização**: como funções em linguagens de programação -> manutenção
  - **dinamicidade** parametrizadas, consultas personalizadas
    - flexibilidade das transformações
    - colunas ou tabelas como parâmetros de uma macro
  - **uso de Jinja**: motor de templates, incorporação de lógicas
  - **definição de macros**: arquivos `.sql` na pasta macros -> sintaxe do Jinja
  - **chamando macros**: de qualquer parte do modelo ou em outras macros

```jinja
{{ nome_macro (parametro1, parametro2) }}
```
  - **disponíveis globalmente**: podem ser acessadas de todo o projeto dbt
  - **macros-internas**: gerenciamento de referência entre modelos, versionamentos de nomes de tabela
- **principais vantanges**
  - **manutenção facilitada**: alterações na macro são propagadas para todos os locais que referenciam
  - **escalabilidade**: lógicas genéricas e aplicáveis a diferentes contextos
  - **legibilidade**: organização do código

### Compreendendo o Conceito de Refatoramento

- processo de restruturar e otimizar o código de transformações sem alterar a lógica e comportamento final
- **principais objetivos**
  - **eliminação de redundância**: consolidação de lógicas numa única fonte, quebrar o código em modelos menores
  - **divisão de modelos complexos**: maior modularização, cada um lidando com partes específicas
  - **uso de dados**: abstração de padrões comuns
  - **documentação e testes**: integridade e consistência
  - **otimização de performances**: simplificação de junções, melhorar agregações, reduzir larga no banco de dados
  - **modularização**: isolamento em etapas claras, cmadas lógicas do modelo (*staging*, *intermediate*, *final*)
