# Formação Engenheiro de Dados

## Engenharia de Dados com Airbyte, DBT e SQL

### Criando o modelo dbt para Transformação de Dados

- essencialmente uma consulta SQL
- definidos em arquivos .sql
  - tabelas ou visualizações no Data Warehouse
  - cada modelo pode ter múltiplas transformações
- controlados e gerenciados de forma modular
  - manutenção, reutilização e documentação dos pipelines de dados
  - testes e qualidade
- `dbt run` -> executar o dbt (na pasta do projeto)
- `dbt docs generate` -> criação da documentação
- `dbt docs serve` -> serve a documentação numa página web (apenas o esqueleto)
- podemos criar um arquivo `schema.yaml` com metadados de descrições do modelo de dados, para melhorar a documentação

### Versionamento com dbt

- organização e controle do desenvolvimento
- **integração com git**
  - gerenciamento eficiente das mudanças
  - manuseio das informações (histórico de versões)
  - colaboração

1. **repositórios git** -> tudo do dbt pode ser armazenado em git (permite reverter ações)
2. **branches (ramos)** -> prática comum
3. **pull requests** -> revisão de código (colaboração), qualidade e consistência


#### Estruturas de Pastas

1. **modelos** -> baseado em esquemas ou funcionalidades
2. **macros e seeds** -> clareza e modularidade
3. **snapshots e documentação** -> manutenção e controles de versão

#### Controles de Versã e Artefatos de Dados

1. **versionamento de tabelas**: estado dos dados ao longo do tempo
2. **monitoramento e logs:** CI/CD para registrar logs, rastreio de mudanças e resolução de problemas

#### Boas Práticas

1. **commits atômicos** - facilitar o rastreamento e revisão das alterações
2. **mensagens de commits claras** - descritivas, ajuda no histórico de mudanças
3. **testes automatizados** - validação das transformações
4. **documentação atualizada** - mudanças de versão

### Ciclo de Vida de Projetos dbt

#### 1. **Planejamento e Configuração Inicial**

- definição de escopo e objetivos
  - identificar requisitos do projeto e os objetivos do negócio
  - definir dados transformados e quais métricas são importantes
- configuração do ambiente
  - dbt
  - data warehouse
  - controle de versão

#### 2. **Desenvolvimento**

- modelagem de dados
  - modelos SQL para transformações
  - organizações dos modelos numa estrutura de diretórios
- definição de fontes e seeds
  - arquivos YAML para documentação e testes
  - dados estáticos ou de referência
- escrita de macro
  - encapsular lógica SQL complexa

#### 3. **Testes e Validação**

- testes de dados
  - genéricos e personalizados para validar a qualidade
  - testes regulares
- documentação
  - modelos, fontes, métricas e macros
  - documentação navegável

#### 4. **Implementação**

- execução de modelos
  - transformação dos dados
  - podem ser executadas transformações específicas
```bash
dbt run --select <model>
```
- agendamento e orquestração
  - integração com ferramentas de orquestração
  - pipelines CI/CD para automatizar a execução e os testes

#### 5. **Monitoramento e Manutenção**

- monitoramento contínuo
  - modelo e qualidade dos dados
  - alertas e notificações
- atualizações e melhorias
  - revisão e atualização -> mudanças nos requisitos de negócio e estrutura de dados
  - melhoria contínua (feedback e desempenho)

#### 6. **Governança e Auditoria**

- controle de versão e auditoria
  - versionamento
  - histório claro de mudanças e revisão de código
- revisões e aprovações
  - qualidade e conformidade com as melhores práticas

#### 7. **Descontinuação e Arquivamento**

- arquivamento de projetos
  - arquivamento de forma organizada
  - preservação dos dados e documentação
- transição e encerramento
  - planejar transição
  - documentar o encerramento e comunicar aos stakeholders

- ciclo de vida -> iterativo e contínuo

### Camadas da Arquitetura do Modelo e Camada de Staging

- organização em camadas modulares

#### **1. Camada de Staging**

- primeira após a ingestão dos dados
- preparar dados para transformações adicionais
- limpeza e correção de erros
- pequenas transformações adicionais

#### **2. Camada Intermediária**

- transformações mais complexas
- consolidação de múltiplas fontes
- cálculos intermediários

#### **Camada de Marts (ou modelos)**

- aplicação de lógica de negócios para transformar para modelos finais
- métricas e agregações
- tabelas analíticas
- organização em diretórios lógicos

#### **Benefícios das Camadas**

- modularidade
- reutilização
- clareza e organização
  
#### Documentação e Metadados

- papel na gestaão e compreensão dos projetos de dados
- detalhada, acessível, e fácil de gerar e navegar

### **Documentação no dbt**

1. definição em arquivos YAML -> modelos, fontes, seeds e snapshots
   1. adicionadas diretamente aos artefatos
2. geração por comando
3. visualização
   1. servidor web local
   2. navegação pelas tabelas, colunas, testes e dependências

#### Metadados

- informações adicionais que descrevem artefatos
  - fontes -> nome da tabela, descrição e origem
  - modelos -> nome, descrição materialização (table, view, incremental), dependências
  - seeds e snapshots
    - seeds -> nome, descrição, tipos de colunas
    - snapshots -> nome, descrição, lógica de versionamento
  - testes -> tipos e resultados

#### Boas Práticas para Documentação e Metadados em dbt

1. documentação consistente e detalhada
2. automatização da geração de documentação (pipeline CI/CD)
3. revisão e manutenção regular
4. utilização de metadados para governança
   1. governança, linhagem de dados e auditoria
   2. entender o histórico e contexto

### Estratégias de Deploy e CI/CD

- automação de tarefas, validar mudanças

1. configuração de ambientes
   1. múltiplos (desenvolvimento, staging e produção)
   2. isolar e testar mudanças
   3. isolar schemas de banco de dados
   4. variável de ambiente
   5. conexões seguras
2. pipelines CI/CD
   1. **pipeline de integração contínua**
      1. testes
      2. linting para qualidade e consistência do código
      3. documentação
   2. **pipeline de deploy contínuo**
      1. implantação de mudanças após testes
      2. revisão e aprovação manual antes do deploy de produção
3. tests automatizados
   1. genéricos
   2. personalizados
4. monitoramento e alertas
   1. execução
   2. alertas automatizados
5. gestão de mudanças e versionamento
   1. controle de versão
   2. pull requests, revisão de código
6. boas práticas
   1. deploy incremental, tempo e recursos para atualizar grandes volumes de dados
   2. rollback: reverter rapidamente em caso de problemas

- `dbt debug` -> forma de validar as informações do projeto, testar conexão com banco de dados
- cada modelo pode ser documentado e testado individualmente
  - podem depdender de outros modelos
  - dbt usa a estrutura de dependências lógica para criar / executar as transformações na ordem correta
    - reexecução automática no caso de alteração de modelos predecessores
- deployment
  - **table**: tabela física no banco
  - **view**: view, que não armazena os dados mas executa a query a cada execução
  - **incremental**: atualiza apenas dados que mudaram desde a última atualização

### O Conceito de Mart no Contexto do dbt

- camada mart -> camada de entregas otimizada para consulta de negócio, camada limpa e organizadora, agregada no pipeline
  - consumo analítico -> dados agregados, métricas calculadas e dimensões preparadas
- se não especificamos a forma de materialização, o padrão é view
  - podemos mudar o `dbt_model.yaml` para modificar o padrão de materialização

### Modelo com Materialização Incremental

- não pode ser aplicado a views (apenas tables)
- atualizar apenas dados adicionados ou modificados desde a última atualização
  - definir lógica de como detectar novos dados (coluna `updated_at`) ou campo de classe
  - inserções, atualizações ou exclusões
