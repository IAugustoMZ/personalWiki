# Formação Engenheiro de Dados

## Engenharia de Dados com Airbyte, DBT e SQL

### O que é Change Data Capture?

- capturar e identificar alterações feitas em um banco de dados para processamento posterior
  - dados sincronizados
  - reação à mudanças
  - sistemas de replicação de banco de dados
- comum no Modern Data Stack
  - arquitetura de microsserviços
- funcionamento
  - monitoramento de mudanças (inserções, atualizações, exclusões)
  - captura de alterações -> detalhes capturadosm natureza, momento e dados alterados
  - armazenamento de eventos da mudança -> log de eventos ou armazenamento separado (processamento sem prejuízo ao desempenho principal)
  - processamento de mudanças -> manter dados sincronizados em tempo real
- Benefícios do CDC
  - atualizações em tempo real
  - redução de carga no banco de dados (foco apenas no modificado)
  - consistência de dados
  - otimização de recursos
- não apenas rastrear mudanças, mas tomar ações
- toda operação SQL realizada fica registrada em logs
  - possível reverter tudo

- *debezium* -> varre os logs para detectar as mudanças no banco de dados
- SGBD -> um ou mais databases
  - um database -> um ou mais schemas
    - um schema -> um ou mais tabelas
- *Airbyte* não deve ter todos os privilégios no banco de dados
- é necessário configrar a replicação no SGBD para monitorar alterações na tabela
  - *logical decoding* -> slot de replicação para que algum plugin possa monitorar os logs
- processo de exrair mudanças persistentes em tabelas do banco de dados
- no PostgreSQL -> logical decoding implementado via *unit-ahead-logging*
  - mudança no nível de armazenamento

### O que é sincronização incremental?

- periodicamente da origem ao destino (agendamento)
  - apenas as alterações ocorridas desde a sincronização anterior
  - dados que já estão no destino não são copiados novamente
- apenas para destinos onde a normalização dbt/SQL é suportada
  - não suporta `DELETE`
- **como funciona?**
  - **cursor field**: identificação do campo cursor nos dados de origem
    - timestamp ou id
    - usado para rastrear quais recursos foram replicados
  - **cursor value**: valor replicado mais recente
    - armazenado como estado da conexão
  - consulta ao sistema de origem em busca de registros novos ou atualizados
  - todos registros com valor maior que o cursor
  - registros com valor maior que o cursor
  - registros gravados no destino
  - atualização do cursor
- vantagens
  - eficiência -> quantidade reduzida de dados trafegados
  - atualizações
  - custos reduzidos de transferência (nuvem)
- requerem um campo adequado para cursor e ordenação de dados consistente

### Diferença entre os modos de sincronização incremental

- **append** -> tabela final normalizada + cópia histórica de cada registro inserido ou atualizado
  - mesmo que atualizado muitas vezes -> várias entradas
- **depuded history** -> duas tabelas de destino normalizadas
  - 1 de histórico (SCD) -> versões históricas de cada registro + datas de início e término
  - 1 tabela deduplicada -> cópia única de cada registro
