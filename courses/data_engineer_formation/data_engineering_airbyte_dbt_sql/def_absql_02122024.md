### SQL Avançado para Transformações de Dados

#### Estratégias de JOIN e Merge

- combinar dado de duas ou mais tabelas baseadas em colunas relacionadas
  - integração de múltiplas fontes de dados

##### Tipos de JOIN

1. **INNER JOIN**: retorna apenas com correspondência em ambas as tabelas (mais rápido)

```sql
SELECT a.*, b.*
FROM tabela_a a
    INNER JOIN tabela_b b 
        ON a.id = b.id
```

2. **LEFT (OUTER) JOIN**: todas as linhas da tabela à esquerda e as linhas correspondentes da tabela à direita

```sql
SELECT a.*, b.*
FROM tabela_a a
    LEFT JOIN tabela_b b 
        ON a.id = b.id
```

3. **RIGHT (OUTER) JOIN**: todas as linhas da tabela à direita e as linhas correspondentes da tabela à esquerda

```sql
SELECT a.*, b.*
FROM tabela_a a
    RIGHT JOIN tabela_b b 
        ON a.id = b.id
```

4. **FULL (OUTER) JOIN**: retorna linhas quando há correspondências em pelo menos uma das tabelas

```sql
SELECT a.*, b.*
FROM tabela_a a
    FULL OUTER JOIN tabela_b b 
        ON a.id = b.id
```

5. **CROSS JOIN**: produto cartesiano das tabelas, onde cada linha da primeira tabela é combinada com todas as linhas da segunda tabela
   1. evitado por conta de problemas de alta cardinalidade

```sql
SELECT a.*, b.*
FROM tabela_a a
    CROSS JOIN tabela_b b 
```

##### Estratégias de Merge em Data Processing

- merge: combinas dois conjuntos de dados fora do SQL
  - **chaves específicas**: similar ao JOIN
    - `df1.merge(df2, on='key_column')`
  - **chaves diferentes**: quando nomes são difrentes
    - `df1.merge(df2, left_on='df1_key', right_on='df2_key')`
  - **outer, inner, left e right**: similar aos JOIN do SQL

- **dicas de otimização**
  - **indexação**: colunas usadas nos merges / JOIN
  - **reduzir dados antes do JOIN**: filtrar ou selecionar apenas o necessário
  - **avaliar tamanho dos dados**: *broadcasting*, replicação da tabela menor para acelerar o JOIN
  - **ferramentas apropriadas**: processamento distribuído? (Spark)

### SQL para Engenharia de Dados

1. **extração de dados**: seleção, filtros e consultas
2. **transformação dos dados**: agregação, JOINs, subconsultas, CTEs, funções de janela
3. **carregamento de dados**: processos ETL, data warehouse, data lake, automação de carregamentos, integridade e qualidade
4. **agendamento e automação**: Airflow, cron jobs, scripts SQL, tarefas de manutençãi, relatórios regulares, atualizações
5. **otimização de desempenho**: sistemas rápidos e eficientes, plano de execução de consultas, ajustes de índices, estratégias de JOIN
6. **garantia da qualidade**: consistência, precisão e completude, dados ausentes, duplicados ou incorretos
7. **integração de dados**: mapeamento de formatos, artugis para novos esquemas, transformações e etapas de verificação

#### Segurança e Boas Práticas

- integridade e confiabilidade dos dados

1. **prevenão de injeção de SQL** - manipulação de consultas, incluindo instruções maliciosas
   1. *prepared statements* para separar dados das instruções
   2. ORM -> geração automática de SQL, de forma segura
2. **conrole de acesso**
   1. princípio do menor privilégio -> usuário acessa apenas o que ele precisa
   2. autenticação e autorização fortes
   3. auditoria e logging
3. **gerenciamento de transações**
   1. usar transações (blocos de trabalho atômicos)
   2. locks quando necessário -> consistência
4. **criptografia**
   1. dados em repouso
   2. dados em trânsito (prevenir interceptações)
5. **backups e recuperação de dados**
   1. backups regulares
   2. planos de recuperação de desastre (testados)
6. **performance e manutenção**
   1. indexação
   2. análise dos planos de execução
   3. limpeza dos dados (rotina)
7. **monitoramento contínuo**
   1. performance e saúde (utilização)
