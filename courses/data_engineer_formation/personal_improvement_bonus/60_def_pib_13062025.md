### Administração do Sistema Operacional Linux com Docker e Kubernetes

#### Orquestração de Containers Docker para Escalabilidade de Web App e Banco de Dados

```bash
docker compose build # apenas cria as imagens
docker swarm init # inicialização do cluster
docker network create --driver <driver> <network-name> # para criar a rede que será usada pelo cluster orquestrado
docker service create --name <name> \
-network <network> \
--replicas <no> \
-p <port-mapping> <service-name>
```

- criarmos o container de forma manual, perdemos a orquestração
- o serviço Docker permite o Swarm prover disponibilidade e escalabilidade

| Escalabilidade Vertical | Escalabilidade Horizontal |
| --- | --- |
| <li>melhorar a capacidade de processamento de um único servidor / máquina<li>adicionando recursos como CPU/RAM ou armazenamento<li>limitada ao hardware disponível<li>eventualmente mais custosa | <li>adicionar mais servidores ou máquinas, distribuindo a carga entre eles<li>expansão indefinida<li>mais flexível ou econômica<li>maior tolerância a falhas e disponibilidade<li>maior complexidade técnica<li>soluções mais robustas e escaláveis a longo prazo |

- cada vez que o usuário acessa o site, ele é direcionamento para um ou outro container
- com o aumento do número de acessos $\to$ escalabilidade

```bash
docker swarm scale <service>=<number>

docker service update --image <image-name> <service-name> # atualização das imagens de forma dinâmica sem tirar a aplicação do ar
```

- se algum dos containers caírem, o Swarm garante que o número de réplicas desejados permaneça
  - o Docker mantém os serviços gerenciando a quantidade de containers

```bash
docker service ls # lista serviços em execução
docker service inspect --pretty <service> # inspeciona os serviços
docker service rm <service> # parar e remover serviços
docker swarm leave --leave # encerramento do serviço Swarm
```

#### Deploy e Orquestração de Aplicação de IA com Docker e Kubernetes

- **Kubernetes:** plataforma open source de orquestração e automação de implantação, escalabilidade e gerenciamento de aplicações containerizadas
  - alta disponibilidade
  - balanceamento de carga
  - recuperação automática de falhas
  - atualizações gradativas
- **kubectl:** ferramenta da linha de comando para interagir com Kubernetes
  - criar, monitorar, atualizar e excluir recursos
  - gerenciar aplicações e serviços implantados
- **minikube**: rodar localmente um ambiente Kubernetes simplificado
  - testes, aprendizado e desenvolvimento
- Kubernetes usa arquivos de configuração yaml

1. instalar o *kubectl* na máquina host
2. instalar o minikube

- Kubernetes gerencia as chamadas de serviços por uma nodeport
  - essa porta mapeia para a porta de cada serviço

3. `minikube start` $\to$ criar o container para iniciar o serviço orquestrador
4. `kubectl cluster -info` $\to$ checar informações do cluster
5. `docker build -t <image-name>` $\to$ criar a imagem do container
6. `minikube image load <image-name>` $\to$ carrega a imagem criada no ambiente do orquestrador

- **Pod:** menor unidade básica de implantação e gerenciamento
  - grupo de um ou mais containers relacionados
  - partilhamento de recursos (armazenamento, rede, namespace)
  - pode conter mais de um container no caso de forte acoplamento
    - permite que containers internos comuniquem-se entre si através de um localhost
      - compartilhamento de volumes e configurações específicas
  - cada pod recebe um endereço IP único dentro do cluster $\to$ comunicação direta com os outros pods
  - são efêmeros e descartáveis por natureza
    - quando um é destruído, outro é automaticamente criado pelo Kubernetes
    - disponibilidade e continuidade dos serviços
- configuração do Kubernetes
  - `deployment.yaml`
  - `service.yaml`

```bash
kubectl apply -f <deployment.yaml-path> # aplicação da configuração do deployment (mesmo para o service.yaml)
kubectl get pods # lista os pods em execução
kubectl get services # lista os serviços em execução
minikube service <service-name> # para realizar a disponibilização do serviço
kubectl scale deployment <deploy-name> --replicas=4 # (em outro terminal), para realização da escalabilidade
kubectl delete pod <pod-name> # para deletar o pod
kubectl describer pod <pod-name> # informações detalhadas sobre o pod, como node, endereço IP, ponto de montagem
kubectl exec -it <pod-name> --bash # entrar no container do pod para execução de comandos Linux
minikube stop # parar o cluster
minikube delete # eliminar o cluster
```

- o Kubernetes é bem rápido em repor os pods
