### Sistema Operacional Linux, Docker e Kubernetes

#### Lab3 - Trabalhando em Rede com Docker e Linux

- rede do Docker -> comunicação entre containers
    - cada rede tem um driver associado
- podemos especificar no momento da criação ou mudar depois
- rede é um ambiente onde computadores se comunicam por protocolos
- `docker networks ls` -> lista todas as redes docker
    - rede *bridge* é a que permite a comunicação entre containers
- a rede existe para permitir comunicações entre containers, visto que cada um deles é uma máquina virtual superleve
- docker não oferece recursos avançados de configurações de redes
- `docker network` -> lista comandos relacionados às redes Docker
- a menos que seja especificado, todo container vai conectar na *bridge*
- `docker inspect <container_name>` -> para inspecionar as configurações do container
    - gateway -> caminho para internet (máquina física)
- `docker inspect <nome> -f "{{*property_name}}"` -> para formatar a saída apenas com as propriedades desejadas
- `docker ps --format "{{.id}}{{.Names}}{{json.Networks}}"` -> formatar a saída dos processos em execução
- `docker network inspect <nome>` -> inspeciona os parâmetros da rede selecionada
- `docker network creta <nome>` -> cria uma nova rede. Usa od driver *bridge*
- `docker run -dit --network <name> --name <name_container> <image_name>` -> cria o container ligando-o a uma rede
- containers liggados a redes diferentes são incomunicáveis pois cada rede é independente
    - *firewalls* por IP tables
- `apt-get net-tools` -> pacote de ferramentas de internet / rede
- `ifconfig` -> mostra as configurações de rede
- `ping <IP address>` -> para testar a conexão com outra rede
- `apt -get install ip-utils-ping` -> pacote utilitário com o ping
- o ping envia pacotes pela rede e espera uma resposta da outra máquina
- `docker network disconnect <network_name> <container_name>` -> disconecta o container da rede
- `docker network connect <network_name> <container_name>` -> conecta o container a uma rede
- quando dois containers estão na mesma rede, o ping envia pacotes e recebe continuamente respostas
