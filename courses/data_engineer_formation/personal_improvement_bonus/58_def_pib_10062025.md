### Administração do Sistema Operacional Linux com Docker e Kubernetes

#### Persistência no Docker com Volumes

- abordagem de armazenamento e gerenciamento dos dados gerados por containers
  - independente do ciclo de vida do container
- volumes são gerenciados diretamente pelo Docker
  - abstração do armazenamento físico
  - flexibilidade e portabilidade
  - criados e mantidos diretamente no sistema hospedeiro
- compartilhamento fácil entre vários containers
- menos propensos a erros de caminhos errados ou permissionamento
- criados explicitamente com comandos Docker ou executados automaticamente como uma referência ao volume inexistente

```bash
docker run -it \
--name <container-name> \
--mount source=<source-folder>,destination=<destination-folder>
<image-name>

docker container start <container1> <container2> ... <container n> # para inicializar vários container parados ao mesmo tempo

docker stop .... # para parar os containers

docker rm ... # para remover os containers

docker rm -f ... # remover forçadamente

docker rmi <image-name> # para remover imagens
```

#### Busca no sistema de arquivos do Linux e Conceito de Overlay

- **overlay**: sistema de arquivos baseados em camadas
  - criar e gerenciar imagens e containers de forma eficiente
- cada camada representa um conjunto de arquivos e alterações realizadas na camada anterior
- combinações no OverlayFS $\to$ visualização unificada dos arquivos (mesmo que fisicamente separados)
- imagem base $\to$ camada inicial  
  - cria camadas superiores, permitindo gravações sem modificar as camadas inferiores originais
- eficiência $\to$ compartilhamento das mesmas camadas inferiores
  - economia de espaço em disco
  - acelera a criação e execução dos containers
  - facilita o armazenamento e a distribuição de diferentes imagens que compartilham as mesmas camadas inferiores
    - apenas camadas novas precisam ser baixadas ou armazenadas ao criar / atualizar imagens
- buscar padrões no Linux `ls -la *.txt` $\to$ busca qualquer arquivo com extensão txt
- `cd ~` $\to$ navegar para a pasta raiz do usuário conectado
- `find <dir-path> -name "*.txt"` $\to$ busca arquivos cujo nome possua a extensão regular txt
- `find <dir-path> -type d -name "<name>"` $\to$ busca pastas
  - o `<dir-path>` é o diretório inicial da busca
  - `-size +10M` $\to$ expressão para buscar arquivos pelo tamanho (> 10MB nesse caso)
- `grep "<word>" <file-path>` $\to$ busca `<word>` dentro de um arquivo
- `df -h` $\to$ espaço total em disco, incluindo os volume mapeados
- `du -sh <dir-path>` $\to$ detalhamento do uso de disco de um diretório
- `du -h -max-depth=1 <start-dir>` $\to$ uso de disco a partir do diretório inicial, com profundidade de 1 filho
- `stat <file-path>` $\to$ verificação de estatísticas do arquivo

#### Trabalhando em Rede com Docker e Linux

- `docker network ls` $\to$ colunas `DRIVER` E `SCOPE`
  - `DRIVER`: mecanismo usado para criar e gerenciar a rede
    - *bridge*: mais comum, cria uma rede privada interno, onde containers pode se comunicar entre si (isolada da rede externa, por padrão)
    - *host*: compartilhamento da rede do host, sem isolamento, maior desempenho e menos restrições
    - *null*: rede desativada, sem comunicação externa ou interna, para containers que não precisam acessar nenhuma rede
  - `SCOPE`: alcance ou escopo da rede
    - local: limitado ao host onde Docker está, não se estende por múltiplos hosts ou servidores
    - swarm: redes que abrangem múltiplos hosts no contexto do cluster
- `docker inspect <network-name>` $\to$ trazer as informações da rede
  - endereço IP, *gateway*
  - pode-se filtrar tags desejadas
    - `-f"{{ json.NetworkSettings.Networks }}"`

```bash
docker ps --format "{{ .id }}{{ Names }}{{ json.Networks }}" # exibição dos detalhes de cada container numa forma mais estruturada

docker network create <network-name> # cria uma nova rede Docker
```

- para mudar o container de rede
  - destruir o container e recriá-lo na nova rede
    - `docker -dit --network <network-name> --name <container-name> <image>`
    - Docker gerencia toda a criação de redes para nós
      - cada vez que criamos os containers, pode mudar o endereço IP
  - desconectar e conectar na nova rede

```bash
docker network disconnect <network-name> <container-name> # desconectar
docker network connect <network-name> <container-name> # conectar
```

##### Administração de Redes no Linux

- `ifconfig`
  - `etho` $\to$ interface de rede (saída externa) $\to$ canal para ambiente de rede
  - `lo` $\to$ interface interna do SO
- `ping` $\to$ testar a conexão de rede
  - `ping <IP address>`

```bash
docker network inspect bridge | \
grep "IPv4 Address" | \
awk -F '"1"'{ print $4} # lista os endereços IP dos containers conectados ne bridge

docker ps -q | xargs docker inspect \
--format '{{ Name }} - {{ range.NetworkSettings.Networks }}{{ .IP Address }}{{ end }}' # lista os nomes e endereços 
```

- container em ambientes de rede diferentes não se comunicam
- `netstat -tuln` $\to$ checa portas TCP abertas no container
- `nmap <ip_address>` $\to$ escaneamento de portas abertas
  - escaneamento básico
  - `-p-`: força um escaneamento mais profundo
  - `-ss -sV -p-`: mostra os serviços que estão sendo executados na porta
- `lsof -i:8501` $\to$ retorna os processos sendo executados

#### Trabalhando em Shell Script

- shell = interpretador de comandos que permitem interação com Linux
  - *bash scripting*: automação de tarefas
- precisamos dar a permissão de execução aos scripts bash antes de eles poderem ser testados

```bash
# definir variáveis
TEXTO="string"
echo $TEXTO

# algumas variáveis já são definidas
$HOME # caminho da pasta home
$HOSTNAME # nome da máquina
$TERM # terminal
$PATH # tipo de caminho

# para ler entradas do usuário
read VARIABLE

# declaração de arrays
array = ("item1", ..., "itemn")

# laços de repetição
for INDEX in ${SERVERLIST[@]}: do
    <commands>
done

# condicionais
case $VAR in:
    option1)
    ...
    optionN
esac

# exibe o nome e a versão atual da distribuição Linux em uso
cat /etc/os-release | grp -e PRETTY_NAME -e VERSION

# mostra o espaço total usado e disponível, nas partições em formato legícel, indicando o sistema de arquivos
df -TH 

# lista o espaço disponível em formato legível, excluindo sistemas temporários (tmpfs) e unidade CD/DVD
df -H | grep -VE 'tmpfs|cdrom'

# lista o espaço disponível em formato legível, sem incluir a linha de cabeçalho e excluindo sistemas temporários (tmpfs) e unidade CD/DVD
df -H | grep -VE 'tmpfs|cdrom'

# exibe apenas a porcentagem usada e o nome do disponível das partições do disco, excluindo sistemas temporários e CD/DVD
df -H | grep -vE 'Filesystem|tmpfs|cdrom' | awk '{ print$5 " " $1}'
```

- free: informações sobre o uso da memória RAM e swap de sistema
- uptime: mostra há quanto tempo o sistema está ligado, número de usuários logados e média de carga recentes

```bash
# lista 5 processos que mais consomum memória, % de memória, CPU e o nome dos processos
ps -eo %mem,%cpu,comm --sort=%mem | head -n 6:

# busca por aquivos no sistema inteiro que possuem permissões totais de leitura, escrita e execução para todos os usuários
find / -type f -perm O777

# extrai apenas o valor numérico percentual da primeira coluna armazenada na variável $output
$(echo $output | awk '{ print $1}' | cut -d '%' -H)

# extrai apenas o conteúdo da segunda coluna armazenada na variável $output
$(echo $output | awk '{ print $2}')
```

- `awk` $\to$ ferramenta de processamento e manipulação de textos no Linux
  - analisa arquivos linha por linha
  - divide cada linha em campos (separados por espaços ou tabs)
  - realiza ações definidas pelo usuário
    - exibir colunas
    - filtrar linhas por condições
    - cálculos matemáticos
    - formatar relatórios
  - `awk 'condição {ação}` (linguagem awk)

#### Orquestração de Containers Docker para Escalabilidade de Web App e Banco de Dados

- orquestração $\to$ gerenciar e automatizar a implantação, escalabilidade e operação de larga escala
  - gerenciamento de recursos
  - balanceamento de carga
  - atualização automática
  - tolerância a falhas
  - disponibilidade de aplicações

| Docker Compose | Docker Swarm | Kubernetes |
| --- | --- | --- |
| <li>definir e executar aplicações multi-container<li>arquivo YAML simples<li>desenvolvimento e testes locais<li>não oferece escalabilidade e nem gerenciamento avançado de infraestrutura distribuída | <li>solução nativa do Docker<li>balanceamento de carga integrado<li>escalabilidade automática básica<li>alta disponibilidade<li>simples, intuitivo e de fácil configuração<li>limitado em termos de recursos avançados e flexibilidade | <li>plataforma poderosa, altamente flexível<li>amplamente adotada<li>recursos avançados: autoescalabilidade, controle fino de recursos, atualizações graduais (*rolling updates*)<li>balanceamento de carga eficiente<li>gerenciamento de estado das aplicações<li>tolerância a falhas robusta<li>suporte extenso para ambientes multi-cloud e híbridos<li>manutenção e configuração são mais complexos |
