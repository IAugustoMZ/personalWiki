#### Lab 6 - Deploy de Containers com Docker Compose

- deploy 1 -> web app + Python + Redis
- deploy 2 -> web app + API + banco de dados

*Docker Compose*
    - definir e executar aplicações que requerem vários containers
    - arquivo YAML para configurar os serviços das aplicações
    - workflow automatizado de vários containers 
- desenvolvimento, teste, fluxos de trabalho de CI/CD ou produção
    - vários ambientes isolados num único host
    - preservar os dados em volumes
    - recriar apenas containers modificados
    - mover variáveis de uma composição entre ambientes
    - orquestrar vários containers juntos na mesma máquina host
        - Dockerfile para imagem customizada
        - Swarm / Kubernetes orquestram vários containers em vários hosts

*Redis* -> *data-store in-memory*
    - gerenciar dados chave-valor em tempo real
    - escala e velocidade

- o *docker-compose* cria todos os containers na mesma rede
    - containers já estarão se comunicando

- *docker-compose.yml*
    - *version* -> versão do docker-compose
    - *services* -> descrição dos containers dos serviços
        - *build* -> se usar Dockerfile
        - *image* -> se puxar direto do Docker Hub
        - *ports* -> mapear a porta local para a porta do container (aquela que está exposta no Dockerfile)
    - *volumes* -> mapeamento de portas de volumes
    - *environment* -> definição de variáveis de ambiente
- `docker compose up` -> executa o docker-compose.yml
    - na pasta onde está o yml
    - aceita `-d` para ser executado em segundo plano
- `docker compose down` -> remove os containers
- fazendo o mapeamento do diretório até o container permite a atualização contínua e em tempo real
