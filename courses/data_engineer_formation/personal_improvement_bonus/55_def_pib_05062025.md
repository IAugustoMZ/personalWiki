## Cursos de Aperfeiçoamento Profissional - Bônus da Formação

### Administração do Sistema Operacional Linux com Docker e Kubernetes

#### Docker

- plataforma que permite empacotar, distribuir e executar aplicações por meio de containers
  - container: unidade leve, isolada e portátil que contém o código, bibliotecas, dependências e configurações para executar aplicações
- permite consistência nos ambientes
  - integração contínua
- compartilham diretamente o kernel do sistema operacional
  - leves, rápidos de iniciar, menos recursos exigidos

#### Kubernetes

- plataforma de código aberto projetada para gerenciar, orquestrar e escalar aplicações baseadas em containers
  - automatiza processos como implantação, escalabilidade, balanceamento de carga e gerenciamento de falhas
- administrar múltiples containers Docker em larga escala $\to$ arquiteturas de microsserviços
  - robustez, automação e resiliência
  - alta disponibilidade e balanceamento automático
- usar quando
  - aplicações complexas baseadas em múltiplos microsserviços
  - escalabilidade automática e balanceamento de carga
  - garantir alta disponibilidade e recuperação automática de falhas
  - necessitar atualizações frequentes (deploy contínuo), sem interrupção de serviço
- em soluções mais simples, o `docker-compose` pode ser suficiente

#### Compreendendo o Conceito de Microsserviços

- abordagem arquitetural em que uma aplicação é desenvolvida como um conjunto de serviços pequenos e independentes, autônomos
  - cada um com sua responsabilidade específica
  - comunicação por meio de interfaces bem definidas, geralmente APIs REST ou protocolos de mensagens
- contrasta com a abordagem monolítica
  - aplicação inteira é construída e implantada como uma única unidade
- vantagens de facilitar o desenvolvimento, manutenção e escalabilidade das aplicações
  - cada serviço pode ser desenvolvido, testado, implantado e escalado separadamente
- recomendado para
  - a aplicação se torna complexa e difícil de gerenciar como monolito
  - necessário escalar partes específicas da aplicação de maneira independente
  - a organização deseja ciclos rápidos de desenvolvimento e implantação contínuas
  - a equipe de desenvolvimento deseja utilizar múltiplas tecnologias e linguagens diferentes simultaneamente
- cuidados adicionais: comunicações entre serviços, monitoramento, sergurança e gerenciamento operacional
  - ferramentas: Docker e Kubernetes
- **imagem:** template para execução (precisa ser criada primeiro)
  - *DockerHub* $\to$ sempre buscar imagens oficiais
  - escrever o `Dockerfile` = personalizar uma imagem
- **container:** uma instância de execução que é executada a partir de uma imagem
- **Dockerfile:** arquivo de texto que personaliza a imagem
  - comandos em caixa alta: `FROM`, `RUN` $\to$ são comandos Docker
  - comandos Linux para personalização

```dockerfile
FROM # referencia a imagem base
LABEL # nomeia o mantenedor da imagem
RUN # executa comandos Linux
WORKDIR #diretório de trabalho
CMD # único comando executado quando o container é iniciado
```

```bash
docker build # criar a imagem
docker run # criar o container
docker exec # executar o terminar dentro do container
-d # modo "detached" (segundo plano)
-it # modo interativo
```
  
- não consigo deletar a imagem se um container associado estiver em execução
- para executar o `docker exec`, não precisamos estar na mesma pasta do `Dockerfile`
  - estamos acessando o container Docker que está sendo executado
