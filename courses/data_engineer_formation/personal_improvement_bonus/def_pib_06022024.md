#### Lab 2 - Estrutura de Diretórios, Sistema de Arquivos, Partições e Volumes

- `tree -l 1` - mostrar a hierarquia da estrutura de diretórios (`-l` = level)
    - usar com parcimônia - muitos níveis podem travar o SO
- `apt-get install tree` - para instalar o pacote `tree`
- `link` -> atalho, aponta para outra pasta
- `bin` -> arquivos binários de aplicativos
- `boot` -> arquivos de inicialização do Linux
- `dev` -> arquivos de dispositivos (placas, discos)
- `etc` -> arquivos de configuração (DNS, nome da máquina, firewall)
- `home` -> pasta que os usuários colocarem os arquivos
- `pastas lib XXX` -> bibliotecas para o funcionamento do SO e Apps
- `media/mnt` -> servir como ponto de montagem
    - `media` -> montagem para mídia removível
    - `mnt` -> montagem para novos discos
- `opt` -> pastas para arquivos que não cabem em mais nenhuma pasta
- `proc` -> visualização de arquivos em execução
- `root` -> diretório home do usuário `root`
- `run` -> visualização dos processos em execução
- `sbin` -> binários do sistema
- `srv` -> diretório para servir outras coisas (aplicativos)
    - configuração do servidor
    - todo SO Linux é um servidor
- `sys` -> arquivos de sistema
- `temp` -> arquivos temporários
- `usr` -> instalação de aplicativos geralmente vai nesse diretório
- `var` -> arquivos temporários para execução de aplicativos

#### Introdução ao Sistema de Arquivos

- sistema de arquivos -> software que ajuda o SO a gerenciar os arquivos
    - Windows = NTFS
    - Linux = ext4
- diretórios são estruturas lógicas para facilitar o nosso relacionamento
- no Linux, é comum mapear uma pasta (`home`) para uma partição do disco e o `boot` para outra partição do disco
    - boot = crítico
    - posso criar quantas partições quiser
- `df -f` -> mostra a organização do sistema de arquivos
- `df -Th` -> mostra o tipo do sistema de arquivos
- `overlay` -> implementação de um `Union File System`
    - representa a união de vários sistemas de arquivos sem manter o container pesado
        - `tmpfs` -> montado na memória
        - `ext4` -> montado no disco, para escrever dados
- quando desligamos o container, todos os dados escritos são perdidos -> precisamos escrever em *volumes*
