### MLOps Essentials: Para Portfolios de Projetos, Gestão de Código e Dados com Git e DVC

#### A Arquitetura de Versionamento: Git + DVC

- versionamento híbrido
- ``git`` $\to$ ferramenta de versionamento de código
  - rastrear arquivos de texto leves e mostrar diferenças linha a linha
  - ruim para ersionar arquivos binários grandes
- `dvc``$\to$ camada complementar ao git
  - armazena os dados em um local externo
    - bucket no AWS S3
  - cria pequenos arquivos de texto "ponteiros" que contêm o hash (impressão digital) do arquivo original
- versionamento do arquivo de dados grandes com o DVC que gera um pequeno arquivo de metadados com o git
  - o git instancia a versão do dado que seu código está usando mas o peso do dado em si
- permite que o repositório permaneça leve, rápido e organizado, mas garante que código e dados estejam sempre sincronizados
- com o checkout de um antigo no git, dvc saberá exatamente qual versão antiga dos dados baixar para garantir que aquele código funcione

#### Configuração do Ambiente

- ambiente profissional, precisamos abandonar configurações manuais e adotar um ambiente de desenvolvimento padronizado
- dependendo de onde salvará os dados, extensões adicionais podem ser necessárias

#### Estrutura de Repositório Padrão 

- dependendo da estrutura, pode ser difícil ler e manter ao longo do tempo
- modelo do Cookiecutter Data Science
  - `data/` $\to$ subdividida em RAW (bruto/imutável), processed (limpo), e final (pronto para o modelo)
  - `notebook/` $\to$ análise exploratória. numerados para indicar a ordem
  - `src/` $\to$ código modularizado. Funções de limpeza, treino e avaliação transformadas em pacotes Python importáveis
  - `models/` $\to$ onde os binários dos modelos treinados são salvos (geralmente versionados via dvc, não git)

#### O poder do `.gitignore` em Data Science

- instrui o git sobre quais arquivos devem ser intencionalmente ignorados
- segurança, performance, e limpeza
- **dados (`data/`)**: não devem ir para o git (Github tem limite de 100 MB)
  - git ignora e o dvc assume o controle dela
- **credenciais e segredos (`.env`)**: nunca saiba chaves de API, senhas de bancos de dados ou credenciais
- **artefatos de ambientes**: pastas de ambientes virtuais e arquivos temporários de compilação Python não são portáveis e poluem o `diff`
