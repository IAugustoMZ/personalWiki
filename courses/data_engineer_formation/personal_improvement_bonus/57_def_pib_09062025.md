#### Compreendendo o conceito de *shell* e Gerenciando Usuários no Linux

- *shell* = interpretar de comandos, interface entre o usuário e o kernel do SO
  - execução de comandos, manipulação de arquivos e diretórios
  - automação de tarefas por *scripts*
- `sh` (*bourne shell*) $\to$ sistemas com alta compatibilidade e portabilidade
- `bash` $\to$ evolução direta
  - auto-complete
  - histórico de comandos com edição
  - variáveis e funções avançadas
  - programação mais complexa por meio de scripts
- `zash` (*z shell*) $\to$ mais recente, alta customização e recursos avançadas

- quando deletamos o container, tudo que está salvo nele será perdido
  - diferentes *hostnames*
- para descobrir o shell que está sendo usado
  - `$SHELL`
- `useradd` $\to$ para adicionar um novo usuário
  - verificar os usuários: `cat /etc/passwd`
- usuários `nlogin` $\to$ usuários de serviço, usados apenas para inicializar serviços
  - `user add -m -s <std shell>` $\to$ para definir qual o shell padrão do novo usuário
- para definir a senha do usuário: `passwd user`
  - usuário `root` consegue mudar a senha de qualquer outro usuário do sistema
- melhorar os outputs dos comandos, podemos contar
  - `cut -d: -ft <file-name>`
- renomear usuário $\to$ `usermod -L <new-name> <other-name>`
  - quando criamos usuários, novas pastas de trabalho são definidas `/home/newuser`
  - renomear usuários não muda o nome da pasta de trabalho
- para buscar coisas específicas num arquivo
  - `getent <file> <search>`
- para mudar a pasta de trabalho

```bash
mkdir <dir_path>
usermod -d <dir_path> <username>
```

- quando criamos usuários, também são criados grupos de usuários com mesmo nome
  - podemos verificar os grupos: `cat /etc/groups`
  - mudar o grupo: `usermod -ag <group> <user>`
  - um usuário pode estar em múltiplos grupos
  - o super usuário pode fazer login em múltiplos usuários: su $\to$ user
    - exit: volta para o usuário root
- para modificar o shell padrão do usuário
  - `usermod -s <shell_path> <user>`
  - o shell precisa estar instalado antes de realizar a modificação

```bash

apt install zsh -y # -y é para já confirmar a instalação
```

##### Gerenciamento de Campos

- organização de lógica para conceder privilégios
  - `groupadd` $\to$ adicionar novo grupo
  - `groupmod -n <newname> <oldname>` $\to$  renomear o grupo
- `gpasswd -d <user< <group>` $\to$ eliminar o usuário do grupo
- `groupdel <group>` $\to$ apaga grupo
  - os usuários não são deletados
- `userdel <user>` $\to$ apagar usuário
  - `-r` $\to$ deleção recursiva (para apagas a pasta de trabalho do usuário)

##### Gerenciamento Permissões de Pastas e Arquivos

- permissões $\to$ definem quam pode acessar, modificar ou executar cada item no sistema
  - formato específico (sequência de caracteres)
- 3 blocos distintos
  - permissões ao usuário proprietário
  - permissões para o grupo
  - permissões para outros usuários
- letras de permissões
  - `r` (leitura) = 4
  - `w` (escrita) = 2
  - `x` (execução) = 1
- exemplo: `-rw-r--r--` = 644 (octal)
  - proprietário: leitura e escrita
  - grupo: leitura
  - outros usuários: leitura
- permissão para diretórios
  - leitura: visualizar o conteúdo da pasta
  - escrita: criar, remover, ou renomear arquivos dentro da pasta
  - execução: entrea no diretório (`cd`)
  - `chmod 777 <file>` $\to$ muda permissões do arquivo
    - 777 $\to$ formato octal das permissão
    - 777 $\to$ `-rwxrwxrwx`
  - `chmod u+x <file>` $\to$ equivalente a dar permissões de execução ao usuário
  - `chmod  g-R <file>` $\to$ remover privilégios de leitura do grupo
  - `chmod o+w <file>` $\to$ adicionar leitura a todos os outros usuários
  - `chmod a +rw <file>` $\to$ adicionar leitura e escrita a todos os blocos
  - `chown <user> <file>` $\to$ mudar o propritário do arquivo
  - `chgrp <group> <file>` $\to$ mudar o grupo do arquivo
    - `-R` = realiza mudanças de forma recursiva

##### O que considerar ao migrar de sistema operacional?

- **Windows** $\to$ atrapalha a produtividade, sendo bom para o usuário final
  - lento
  - genérico para atender a muitos *hardwares*
  - instável
  - falhas de segurança
- **Linux** $\to$ SO gratuito (não tem problema de licenças)
  - curva de aprendizado $\times$ ganhos de produtividade
  - padrão na área de dados
- **MacOS**
  - custo significativo $\times$ ganhos de produtividade

- migração soft = *dual boot*
- dá para fazer muito mais com uma distribuição completa Linux

#### Trabalhando com Sistemas de Arquivos (*File System*) com Docker e Linux

- estrutura do diretório organiza de forma hierárquica
  - partem de ponto raiz (`/root`)
  - facilita a organização, segurança e gerenciamento eficiente dos recursos do SO
- ponto raiz $\to$ ponto mais alto da hierarquia

| Diretório | Função / conteúdo |
| --- | --- |
| `\bin` | comandos executáveis básicos |
| `\sbin` | executáveis administrativo e comandos de manutenção do sistema |
| `\etc` | arquivos de configurações do sistema e das aplicações |
| `\home` | <li>pastas pessoaos dos usuários do sistema<li>arquivos pessoais, documentos e configuração individuais |
| `\var` | arquivos variáveis, logs, arquivos temporários do sistema, banco de dados, conteúdo dinâmicos gerados por aplicativos ou serviços |
| `\tmp` | armazenamento temporário de arquivos (periodicamente limpo) |
| `\usr` | arquivos de programas, bibliotecas e recursos compartilhados acessíveis por todos os usuários
| `\opt` | instalação de aplicações adicionais ou opcionais não incluídas no sistema operacional |
| `\lib` (`\lib64`) | bibliotecas essenciais para o funcionamento dos binários `\bin` e `\sbin` |
| `\dev` | dispositivos físicos e virtuais, como disco rígidos, dispositivos USB e interfaces de rede |
| `\proc` e `\sys` | <li>arquivos virtuais que fornecem informações detalhadas sobre processos<li>usuário ou adm acessar informações do kernel em tempo real |


- padrão em qualquer distribuição Linux ou MacOS

##### Sistemas de Arquivos e Partições - Linux e Docker

- sistema de arquivos $\to$ conjunto organizado de regras e estruturas para
  - armazenar
  - gerenciar
  - acessar dados em dispositivos de armazenamento
- define como dados são armazenados, nomeados, organizados e recuperados
  - identificação e gerenciamento
  - controle da organização lógica dos dados
  - permissões e direitos de acesso
  - gerenciamento do espaço disponível
  - garantia da integridade
  - exemplos
    - Ext4 (Linux)
    - NTFS (Windows)
    - APFS (MacOS)
- registro de metadados
  - nomes
  - tamanho
  - data de criação e modificação
  - permissão de acesso
  - localização física
- no Linux: dados armazenados em solução específicas do disco rígido
  - separação física e lógica entre áreas como arquivos pessoais, configurações dos sistema e arquivos temporáveis
    - segurança e desempenho
- container possui um sistema de arquivos isolado do *host* (imagem pré-configurada)
  - camadas $\to$ cada alteração gera uma nova camada incremental
    - melhor uso do espaço em disco
    - eficiência em gerenciamento das imagens
- Docker faz uso intensivo de volumes e montagens (*mounts*)
  - compartilhar e persistir dados além da vida útil do container
  - acessar arquivos e diretório diretamente do host
  - armazenamento de informações permanentemente mesmo após remoção ou reinicilização

##### Persistência com Bind Mount

- técnica para compartilhar diretamente um diretório ou arquivo do sistema operacional host com o container
  - persistência dos dados gerados ou modificados mesmo após o container ser destruído / reiniciado
- exige especificação explícita do caminho da pasta no host ao realizar a montagem
  - facilita o desenvolvimento $\to$ edição direta no host com reflexão imediata dentro do container
  - facilita testes e depurações
- exige um proce de gestão adicional dos arquivos na máquina host
  - privilégio de acesso e backup

```bash
docker run -it \
--name <container-name> \
--mount type=bind,source=<source-folder>,target=<target-container-folder> \
<image-name>
```

- não precisa estar na mesma pasta do Dockerfile mas é bom especificar o caminho completo no `<source-path>`
- dois (ou mais) containers podem apontar para o mesmo diretório de montagem

```bash
docker container start <container-name>
```

- usado para inicializar containers sem reconstruir a imagem

```bash
docker ps # lista containers em execução
docker ps -a # lista todos os containers (em execução ou parados)
```
