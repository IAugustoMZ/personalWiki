### Engenharia de Software com IA Generativa e Vibe Coding

#### O que é Engenharia de Software?

- aplicação sistemática de princípios de engenharia ao desenvolvimento, operação e manutenção de software
  - metodologias estruturadas para criar sistemas confiáveis, eficientes, e que atendam às necessidades dos usuários
- todo o ciclo de vida abrangido
  - levantamento de requisitos, design da arquitetura, implementação, testes, implantação e manutenção
  - práticas de gestão de projetos, controle de qualidade e documentação
- áreas centrais
  - análise de requisitos $\to$ o que o sistema precisa fazer
  - arquitetura de software $\to$ como os componentes se organizam
  - metodologias de desenvolvimento $\to$ agile, scrum, ou waterfall
  - garantia de qualidade e testes
  - DevOps $\to$ integração entre desenvolvimento e operações

#### Princípios Fundamentais da Engenharia de Software

- **abstração:** esconder detalhes irrelevantes e concentrar no que realmente importa para a resolução de um problema
  - linguagens de programação, frameworks e bibliotecas
  - lidar com sistemas complexos de forma mais simples, produtiva e segura
- **modularidade**: estruturar sistemas como conjuntos de partes independentes, porém bem integradas
  - alta coesão, concentrados emúnica responsabilidade e baixo acoplamento, minimizando dependências externas
  - favorece o trabalho em paralelo, facilita testes, reduz impactos de mudanças, e permite a substituição ou evolução de partes do sistema sem compremeter o todo
- **separação de responsabilidade (*separation of concerns*)**: cada componente do sistema deve ter um propósito claro e uma única razão para sofrer mudanças
  - torna o software mais compreensível, mais fácil e fazer manutenção e adaptável ao longo do tempo
- **DRY (don't repeat yourself)**: eliminar a duplicação de código e de conhecimento dentro do sistema
  - diminuir risco de erros e incosistências
  - centralização de responsabilidades e o reaproveitamento consciente
  - reduz complexidades e facilita a evolução do software

#### O Ciclo de Vida do Software

- **levantamento de requisitos** $\to$ o que o sistema deve fazer e sob quais condições
  - funcionais: descrevem comportamentos
  - não funcionais: estabelecem qualidades
- **design** $\to$ traduzir requisitos em estrutura
  - decisões arquiteturais definem componentes principais e suas interações
  - design detalhados especifica algoritmos, estruturas de dados e interfaces
  - bons designs são flexíveis para mudanças futuras sem serem especulativos sobre mudanças imprevisíveis
- **implementação** $\to$ design $\to$ código executável
  - código de qualidade é legível (para humanos também), pode ser testado (estruturado para verificação automatizada) e facilita a manutenção (fácil de modificar por quem não escreveu)
- **testes** $\to$ verificam se o software funciona conforme o esperado
  - testes unitários validam componentes isolados
  - testes de integração validam interações entre componentes
  - testes de sistema avaliam o sistema por completo
  - testes de aceitação confirmam que requisitos do usuário foram atendidos
- **manutenção**: tipicamente 60-80 \% do esforço total de um projeto. Inclui correções de defeitos, adaptação a novos ambientes, melhorias de funcionalidades
  - refatoração para melhorar qualidade interna sem alterar o comportamento interno
