### Sistema Operacional Linux, Docker e Kubernetes

#### Docker File System

- conjunto de camadas somente leituras -> *Union File System* (overlay)
    - camada de leitura de gravação ao iniciar um novo container -> como se fosse Linux padrão
    - camada perdida quando o container fecha
- *bind mounts* -> conexão com a máquina host compartilhando o sistema de arquivos da máquina host (*read* ou *read/write*)
- `docker volumes` -> nativo do Docker, o volume tem um ciclo de vida maior que o do container
    - volumes podem ser compartilhados entre containers

#### Lab 2 - Docker File System

- `docker run -it --name <name> --mount type=bind, source= <source_path>, target <target_path>` - criar um container com mapeamento para pasta local
- `echo <conteudo> <filename>` -> inclui o conteúdo do arquivo

- modo interativo do container -> ação, quando saímos, o container é desligado

- outra forma de fazer o mapeamento -> `docker run -it --name <name> -v <source>:<target_path> <image_name>`

- outra forma de iniciar o container -> `docker container start <name>`

- vantagem do `bind mount` -> possível de mapear qualquer coisa do computador
    - discos externos inclusive
    - NFS
    - volumes totalmente gerenciados pelo Docker

- `docker volume create <volume_name>` -> criar volume
- `docker volume list` -> visualizar volumes criados
- `docker volume inspect <volume_name>` -> realiza a inspeção do volume
- `docker run -it --name <name> --mount source=<volume_name>, destination=<target_name> <image-name>` -> mapeia os arquivos do container para algum lugar gerenciado pelo Docker File System
- volume -> monitoramento e persistência

- `docker volume rm <volume_name>` -> realiza a remoção do volume
- `docker container rm <container_name>` -> remove o container
