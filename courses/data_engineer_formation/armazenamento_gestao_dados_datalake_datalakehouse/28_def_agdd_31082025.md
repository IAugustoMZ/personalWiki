# Formação Engenheiro de Dados

## Armazenamento e Gestão de Dados com Datalake e Datalakehouse

### Pipeline de Engenharia de Dados com a Plataforma Lakehouse da Databricks

#### Camadas Bronze, Silver e Gold

##### Camada Bronze (Raw Data)

- armazena os dados brutos exatamente como foram extraídos das fontes, sem qualquer transformação significativa
- **objetivo**: preservar dados originais para referência futura, auditoria ou reprocessamento
  - todos os registros, incluindo dados inconsistentes ou com erros
  - camada mais detalhada ou volumosa

##### Camada Silver (Cleaned Data)

- armazena os dados após um processo de limpeza e validação, eliminando inconsistências, duplicações e erros
- **objetivo**: preparar dados confiáveis e organizados para análises mais específicas ou transformações adicionais
  - normalização ou padronização aplicadas
  - dados com quanlidade garantida, nível de detalhe intermediário

##### Camada Gold (Curated Data)

- contém dados refinados, otimizados e prontos para consumo em análises avançadas, relatórios ou modelos de Machine Learning
- **objetivo**: servir como base para decisões de negócio e análises estratégicas
  - estruturas otimizadas, agregações ou tabelas específicas para relatórios
  - dados alinhados às necessidades do negócio

##### Benefícios

- *escalabilidade* $\to$ volume organizado em etapas
- *confiabilidade* $\to$ rastreabilidade e qualidade de dados à medida que eles aumentam
- *flexibilidade* $\to$ acesso a dados em diferentes níveis de granularidade
- *facilidade de auditoria* $\to$ dados originais continuam na bronze

#### Monitoramento e Alertas

- acompanhar desempenho, a saúde e a execução de pipelines e workloads dentro da plataforma
- **monitoramento de jobs**
  - acompanhar status de execuções de jobs (completos em execução ou com falhas)
  - analisar logs detalhados para identificar erros ou gargalos
- **métricas de desempenho**
  - monitorar o uso de recursos
  - identificar ineficiências em notebooks, jobs ou clusters
- **alertas**
  - notificações automáticas baseadas em condições específicas, como falhas em jobs ou thresholds de desempenho
  - notificações podem ser enviadas por e-mail, API ou integradas a ferramentas de monitoramento externas
- **visualização de logs**
  - integração de ferramentas como Datadof, Prometheus, Azure Monitor para análise centralizada
  - logs detalhados para troubleshooting

### Estratégias de Escalabilidade no Databricks

- lidar com volumes crescentes de trabalho e cargas de trabalho

1. **uso de cluster de auto-scaling**
   1. ajustar automaticamente o número de nós com base na carga de trabalho
   2. reduz custos em momentos de baixa demanda e garante recursos suficientes em picos
2. **cluster pools (pools de clusters)**
   1. reutilizar instâncias de clusters pré-criadas para reduzir tempo de inicialização e aumentar a eficiência
   2. minimiza a latência para jobs recorrentes e melhora a utilização de recursos
3. **separação de workloads**
   1. workloads dedicados para tipos de jobs
   2. evita contenção de recursos e otimiza o desempenho para cada tipo de tarefa
4. **particionamento de dados**
   1. dividir os dados em particionamento lógico para processamento distribuído eficiente
   2. melhora o desempenho permitindo múltiplos dados em paralelo
5. **uso de Delta Lake**
   1. adotar o formato Delta para gerenciar dados e otimizar leituras, escrita e consultas
   2. operações ACID, compactação de arquivos pequenos e caching eficiente
6. **caching de dados**
   1. armazenar dados frequentemente acessados na memória
   2. reduz leitura de disco e acelear operações subsequentes
7. **otimizações de shuffles**
   1. minimizações de operações de shuffle, reorganizando dados para evitar trocas desnecessárias entre nós
   2. reduz latência e uso de recursos em operações de grande escala
8. **gerenciamento de workspaces multi-tenancy**
   1. organizar workloads e equipes em diferentes workspaces para isolar recursos
   2. evita concorrência de recursos entre equipes
   3. aumenta a previsibilidade de desempenho
9. **uso de clusters específicos para streaming**
   1.  otimizados para processamento em tempo real
   2.  grande eficiêncis para workloads de streaming contínuo
10. **revisão de configurações de Spark**
    1.  ajuster parâmetros do Spark, como memória, números de executores e tamanho das suas partições
    2.  maximiza a utilização de recursos e evita gargalos

### Criando o Catálogo de Dados

- organização e gerenciamento de dados num ambiente unificado
  - descoberta, governançaa e compartilhamento de dados
- visão centralizada dos ativos
  - tabelas, bancos de dados e esquemas
  - suporte a controle de acesso, rastreamento de linhagem e metadados
- no momento de carregar os dados, podemos usar o `*` para consolidar todos os arquivos semelhantes na mesma tabela
  - padrão de nomenclatura e de numeração de tabelas
  - arquivos precisam ler o mesmo esquema para que a consolidação funcione
- tipos de pipeline podem ser *triggered* ou contínuos
- definir o source code para execução de pipelines
- selecionar o catálogo (origem e destino)
- podemos analisar os caminhos percorridos pelos dados de forma gráfica
  - grafo direcionado das Delta Live Tables
- para criação de tabelas de streaming, usamos a função `STREAM`
  - ler dados continuament da fonte de dados
  - cenários de dados dinâmicos ou em tempo real

#### Restrições de Qualidade de Dados

- cláusula `CONSTRAINT` define regras para garantir a qualidade dos dados
  - qualquer linha que viole as condições é descartada com o comando `ON VIOLATION DROP ROW`
- para construção de dados enriquecidos, podemos usar `JOIN` para unir tabelas
- tabela silver $\to$ dados limpos, enriquecidos e integrados, prontos para tabela Gold
- tabela gold $\to$ final do pipeline, onde os dados devem estar prontos para consumo por ferramentas de análise de dados
  - dados agrupados ou estatísticas calculadas
