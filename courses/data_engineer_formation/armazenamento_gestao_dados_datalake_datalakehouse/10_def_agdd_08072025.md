# Formação Engenheiro de Dados

## Armazenamento e Gestão de Dados com Datalake e Datalakehouse

### Implementação

- podemos adicionar uma segunda camada para incluir o processamento de dados $\to$ ROI do projeto
- carregar os dados do Data Lake
  - mapeamento de volume na criação do cluster (útil para subir grandes quantidades de uma vez)
  - execução de comandos para verificação de listagem de dados
    - interação com o sistema de arquivos HDFS: `hdfs dfs -ls`
  - sistema de arquivos distribuído é uma camada de software sobre o sistema de arquivos local
    - gerenciar o espaço em disco várias máquinas como uma unidade
  - com o mapeamento do volume do container, o arquivo é mapeado para o sistema de arquivo local do master, mas vão para o HDFS: `hdfs dfs -put <file-env> <file-path>`
- arquivo dividido em 2 e cópias foram enviadas para cada servidor com a replicação desejada
- precisamos executar o comando para subir os dados no data lake
- o HDFS é para armazenar dados e não para edição e visualização
  - `hdfs dfs -get <file_path>`
- script Python de processamento $\to$ PySPark
  - não dá para usar Python puro
  - sessão Spark é aberta na execução do script
    - conexão ao cluster
- `spark -submit` $\to$ envia o job para o master que vai gerenciar a execução do mesmo
- se a sessão já existir, ele apenas conecta
- a segunda camada já usa o processamento dos dados de forma distribuída $\to$ ROI mais rápido
- variáveis criadas residem na memória do cluster (distribuída)
  - Spark processa dados na memória do cluster
  - pode ser necessário aplicar técnicas de particionamento dos dados
- estrutura importante no Spark $\to$ `VectorAssembler`
- pipeline $\to$ concatenação de passos de processamento
