# Formação Engenheiro de Dados

## Armazenamento e Gestão de Dados com Datalake e Datalakehouse

### Data Lakehouse - Convergência entre Data Lakes e Datalakehouses

#### Delta Live Tables x Delta Lake

- Delta Live Tables $\to$ funcionalidade da plataforma Databricks que permite construir e gerenciar pipelines de dados de forma declarativa e confiável
  - projetado para simplificar o processo de desenvolvimento, execução e manutenção de data pipelines
  - automatizando tarefas complexas como gerenciamento de dependências, validação de qualidade de dados e monitoramento em tempo real
  - usa o poder do Delta Lake
- não existe análise de dados não estruturados, pois sempre precisamos estruturar os dados antes
- Delta Lake $\to$ framework de armazenamento open source para construir Data Lakehouses de forma agnóstica
- pacote Python que pode ser instalado via `pip`

#### O que são Operações CRUD?

- operações básicas em sistemas de gerenciamento de dados
- **CREATE**: inserir novos dados no sistema (`INSERT`)
- **READ**: consultar ou buscar dados existentes no sistema (`SELECT`)
- **UPDATE**: alterar dados existentes no sistema (`UPDATE`)
- **DELETE**: remover dados do sistema

- tudo o que vamos fazer no Spark é um app
- Spark não é para armazemar, somente para processar
  - Delta Lake, nesse caso, salva os dados localmente
- as operações salvam os dados num arquivo Parquet
- pasta `delta_log` $\to$ log de transações
- podemos criar views temporárias e depois aplicar consultas SQL
- usando o `structtype`$\to$ definir esquema para validação e transformação
  - RDD
- também é possível criar novas colunas para trabalhar com limpeza e engenharia de atributos
