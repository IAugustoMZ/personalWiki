# Formação Engenheiro de Dados

## Armazenamento e Gestão de Dados com Datalake e Datalakehouse

### Data Lakehouse - Convergência entre Data Lakes e Datalakehouses

#### Fundamentos de Delta Lake

##### Compreendendo o conceito de Delta Lakes

- camada de armazenamento de código aberto que se baseia no Apache Spark $\to$ confiabilidade, consistência e escalabilidade
- adiciona recursos avançados a um Data Lake tradicional
  - gerenciamento unificadoo de dados estruturados e não estruturados
- **principais características**
  - **transações ACID**: consistência, mesmo em sistemas distribuídos
  - **versionamento de dados**: histórico, reversões e auditoria
  - **esquema evolutivo**: suporta mudanças incrementais sem interromper o fluxo de trabalho
  - **gerenciamento de dados por tabelas**: estrutura tabular suporta operações analíticas
  - **performance aprimorada**: índices e compactação para melhorar a performance de leitura e escrita
  - **compatibilidade com o Data Lake existente**: integração com formatos de armazenamento comuns, como Parquet e pode ser implementado com infraestruturas existentes

##### Princípios ACID

- conjunto de propriedadees que garantem a confiabilidade e a integridade das trasações em sistemas de bancos de dados
  - **Atomicidade (Atomicity)**: garantia de que a transação seja realizada na totalidade ou não seja
    - se qualquer parte falahr, todas as mudanças até aquele ponto são revertidas
  - **Consistência (Consistency)**: toda transação leva o banco de um estado consistente até outro estado consistente, respeitando todas as regras definidas no sistema
    - dados válidos e conformes com as regras do negócio
  - **Isolamento (Isolation)**: transações são executadas de forma independente umas das outras. Mesmo em execuções paralelas, o resultado deve ser o mesmo se cada uma delas fosse executada em sequência
  - **Durabilidade (Durability)**: uma vez que uma transação seja concluída, suas alterações devem ser permanentes e sobreviver a falhas no sistema
    - dados gravados de forma segura e consistente

##### Arquitetura do Delta Lake

- camada de armazenamento que adiciona recuros avançados a sistemas tradicionais de Data Lake
  - integração nativa com Apache Spark
  - implementado sobre sistemas de armazenamento em arquivos
    - Amazon S3
    - Azure Data Lake
    - HDFS
  - principais componentes
    - **camada de dados armazenados**
      - formatos de armazenamento baseados em arquivos como Parquet
      - manter dados organizados em tabelas
      - arquivos acessíveis por operações analíticas e processamento
    - **logs de transações**
      - coração da arquitetura $\to$ rastreia todas as operações realizadas numa tabela (ACID + versionamento)
      - armazenado como arquivos JSON e fornece rastreabilidade de transações
      - cada alteração cria um novo "snapshot" da tabela
        - permite acesso a versões anteriores (*time travel*)
    - **catálogo de metadados**
      - gerenciado pelo Delta Lake
      - esquemas de tabelas, índices e otimização
      - facilita a evolução do esquema (criação ou alteração de colunas) sem interromper operações
    - **transações ACID**
    - **camada de computação (Apache Spark)**
      - usar APIs de processamento paralelo e em larga escala
        - transaformações e análises diretamente sobre os dados armazenados
    - **otimizações de leitura e escrita**
      - compactação de arquivos pequenos em arquivos maiores para eficiência
      - indexação para acelerar buscas
      - data *splupping* para ignorar partes irrelevantes dos dados durante as leituras com base em critérios específicos
    - **intração com ferramentas de análise**
      - consumo direto sem a necessidade de movimentação ou duplicação
