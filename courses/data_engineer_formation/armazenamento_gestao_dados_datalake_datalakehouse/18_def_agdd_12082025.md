# Formação Engenheiro de Dados

## Armazenamento e Gestão de Dados com Datalake e Datalakehouse

### Data Lakehouse - Convergência entre Data Lakes e Datalakehouses

#### Vantagens da Convergência

- única plataforma que unifica o armazenamento e o processamento de dados estruturados e não estruturados com múltiplos casos de uso
  - análises, aprendizado de máquina, e inteligência artificial

1. **simplicifafe e unificação**: todos os dados, independente do formato ou estrutura, podem ser armazenados e processados em um único sistema
    - reduz a complexidade operacional
2. **suporte a dados estruturados e não estruturados**: sem comprometimento do desempenho
3. **custos reduzidos**: arquitetura em camdas, evitando custos redundantes de manter e integrar duas infra-estruturas distintas
4. **alto desempenho para análises e processamento avançado**: eficiência de consulta e otimização do data warehouse
    - flexibilidade e escalabilidade dos data lakes
    - análises em tempo real e processamento de grandes volumes de dados
5. **flexibilidade para casos de uso avançados**: processamento de dados em larga escala (aprendizado de máquina), análises transacionais e preditivas, sem a necessidade de usar dados entre sistemas
6. **governança e controle unificados**: políticas de segurança, conformidade e controle de acesso de forma unificada
7. **redução da movimentação de dados**: dados residem num único sistema
    - sem a necessidade de ficar movimentando grandes volumes de dados
8. **escalabilidade**: arquitetura baseada em nuvem e arquiteturas distribuídas
    - altamente escalável $\to$ volumes massivos de dados

#### Arqitetura e Design de um Data Lakehouse

1. **camada de armazenamento**
   - escalável e econômico, geralmente nuvem
   - grandes volumes de dados brutos e processados, independente do formato
2. **camada de processamento**
   - processamento distribuído (Apache Spark ou serviços gerenciados)
   - transformação, limpeza, análise e processamento em tempo real
3. **camada de metadados**
   - gerencia informações sobre os dados armazenados (schema, particionamento, localizações)
   - consultas eficientes
   - Delta Lake, Apache Iceberg $\to$ estrutura e transações ACID, consistência e integridade
4. **camada de governança e segurança**
    - controle de acesso, criptografia, e auditorias
    - conformidade com regulamentações
    - Apache Ranger / AWS Lake Formation
5. **camada de consulta e análises**
    - mecanismos de consulta SQL otimizadas
      - Databricks SQL, Presto ou BigQuery
    - suport de ferramentas de BI
    - análises interativas e visualizações
6. **integração com machine learning**
    - suporte de aprendizado de máquina e inteligência artificial
    - treinamento e implantação de modelos na plataforma

#### Design do Data Lakehouse

- **unificação de dados**: todos os tipos de dados armazenados
- **escalabilidade elástica**: recursos de nuvem para ajustar a capacidade conforme a demanda
- **eficiência de custo**: custo-benefícios do armazenamento em Data Lakes com performance otimizada de Data Warehouses
- **interoperabilidade**: suporta diversos usos de caso e ferramentas de análise, machine learning, e processamento

#### Processos e Pipeline em Data Lakehouses

- ingerir, transformar, armazenar, e disponibilizar dados de forma eficiente
  - espinha dorsal operacional de um data lakehouse

1. **ingestão de dados**
   - dados de várias fontes e carregados para o Lakehouse
     - lote (*batch*)
     - tempo real $\to$ dados capturados e processados continuamente (Apache Kafka ou AWS Kinesis)
2. **transformação e limpeza**
    - garantir qualidade e consistência
    - normalização, padronizaçã, conversão de fórmulas
    - limpeza de dados, remoção de duplicatas e preenchimento de valores ausentes
    - enriquecimento $\to$ mais fontes
    - Apache Spark, Databricks, servicços de nuvem (AWS Glue, Azure Data Factory)
3. **armazenamento e conversão**
    - *raw layer* $\to$ dados brutos em formato original
    - *cleansed layer* $\to$ dados tratados e prontos para uso analítico
    - *curated layer* $\to$ dados preparados para análises específicas ou modelos de aprendizados

- Delta Lake, Apache Iceberg ou Hud
    - transações ACID e versionamento

4. **indexação e metadados**
    - atualização de catálogos $\to$ consultas
    - Hive Metastore ou AWS Glue Catalog
5. **consulta e análise**
    - disponibilização por meio de ferramentas como SQL ou interfaces de BI
6. **machine learning e streaming avançado**
    - pipelines especializados para processar dados em tempo para treinar ou atualizar modelos de aprendizado de máquina continuamente
