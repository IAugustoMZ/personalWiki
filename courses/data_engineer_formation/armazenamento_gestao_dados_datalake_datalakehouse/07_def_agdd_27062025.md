### O Futuro dos Data Lakes e Data Lakehouses

#### Data Lakes

- integração de tecnologias de IA e ML para análise e processamento de dados
- priorização de governança e segurança para proteção e conformidade regulatória

#### Data Lakehouse

- evolução nos termos de eficiência de consulta, gerenciamento de metadados e integração de diferentes de dados

##### **Integração e Interoperabilidade**

- entre diferentes plataformas e tecnologias
  - conexão com facilidade
  - fontes de dados, ferramentas de análise e inteligência empresarial

##### **Regulamentação de Dados**

- preocupações com privacidade e segurança
- GDPR / LGPD $\to$ gestão
- mecanismos mais robustos de gestão de consentimento e anonimização

##### **Automação e Self-Service**

- tendência de democratização do acesso aos dados
- acessibilidade a usuários não-técnicos
  - interface intuitiva
  - ferramentas de acesso self-service

##### **Sustentabilidade e Eficiência Energética**

- critérios importantes na construção e manutenção de Data centers

### Os 4 Estágios para construir um Data Lake de Forma Eficiente

- aumento de informações e processamento $\to$ fluxo quase infinito de informações
  - variados formatos e fontes
  - alto volume de dados à disposição - como gerar valor?
- expansão da infraestrutura de gerenciamento de forma rápida
  - data lakes $\to$ dados estruturados e não estruturados
  - complemento aos data warehouses corporativos
    - menor custo para operar
- conjuntos de dados não precisam ser indexados e preparados para armazenamento na ingestão
  - dados mantidos em formatos nativos e reconfigurados quando necessário
  - robusto programa de análise de avançada
- a integração pode ser demorada e complicada $\to$ mão de obra muito especializada
  - engenheiros de dados
- abordagem ágil ao design e à implementação de Data Lakes
  - testes e refinamento
  - padrões regulatórios GDPR / LGPD
  - velocidade nas análises de mercado e geração de percepções

| Stage 1 | Stage 2 | Stage 3 | Stage 4 |
| --- | --- | --- | --- |
| Landing zone for new data | data science environment | offload to data warehouses | critical comp. of data operations |
| low cost, scalable, "pure-capture", environment | actively used as a platform for experiments | integrating with existing enterprises data warehouses | core part of data operations |

#### **Estágio 1: Landing Zone for Raw Data**

- separado dos sistemas de TI
- "captura pura" de baixo custo e escalável
- fina camada de gerenciamento dos dados
  - dados armazenados indefinidamente
- efeitos mínimos na arquitetura existente
- governança forte, classificação rigorosa dos dados

#### **Estágio 2: Data Science Environment**

- plataforma de experimentação
  - acesso fácil e rápido aos dados
  - foco nos experimentos e análise de dados
- trabalho com dados inalterados para criar protótipos
- implantação de ferramentas comerciais para criar ambientes de testes

#### **Estágio 3: Offload to Data Warehouses**

- integração aos EDW existentes
- armazenamento de dados sem pressionar a capacidade dos Warehouses
- manter ETL complexos em EDW existentes
  - menos complexos podem ir para o Data Lake

#### **Estágio 4: Critical Component of Data Operations**

- grande parte dos dados da companhia
- parte essencial da infraestrutura de dados
  - substitui data marts existentes ou armazenamento de dados operacionais
  - dados como serviços
- aproveitar a natureza distribuída dos Data Lake
  - análises avançadas ou implantar programas de aprendizado de máquina
  - aplicativos de uso intensivo de dados
  - APIs para combinar insights gerados

- em cada estágio:
  - questões de volume e variedade de seus conjuntos de dados
  - recursos existentes
  - nível de especialização em Big Data
  - conhecimento do produto
- jornada pode ser acelerada por meio de metodologias ágeis
  - líderes técnicos e não técnicos na mesma sintonia
  - foco em questões de gerenciamento de dados
  - caminho técnico + ambiente de trabalho compatível

## Construindo um Data Lake: uma Abordagem Ágil

- TI toma iniciata de examinar as possíveis opções de tecnologia para Data Lake
- abordar e definir questões relevantes sobre tecnologia e design
  - on premises $\times$ nuvem ?
  - quais dados? quando?
- população baseada em usos de negócios de prioridade mais alta
  - feita com iterações
- business back
  - identificar caminhos de obtenção de valor
  - inclusão dos cenários no design
    - preenchimento com dados de grupos específicos ou casos de uso
    - testes de poucos candidatos finais de diferentes fornecedores $\to$ desempenho no mundo real
      - facilidade de integração e escalabilidade
- detecção antecipada de desafios de desempenho e implementação
  - incorporação de feedback das unidades de negócio
  - modificação de processos e protocolos de controles de dados à medida que o Data Lake é preenchido
- à medida que o Data Lake assume o papel cada vez mais central
  - reconsidera estratégias de governança
  - equilibrar rigidez da supervisão tradicional com flexibilidade
  - permite aos Data Scientists explorar os dados mesmo que os casos de negócio ainda estejam sendo indentificados
  - designar certo indivíduos como proprietários nos conjuntos de dados e processos
    - responsabilidades claras e decisões rápidas
  - armazenar metadados em todas as fontes de dados
    - mantém catálogo
  - reconfiguração dos direitos de acesso
    - privacidade
    - requisitos regulamentares
    - comunicação dos direitos de acesso às partes interessadas
