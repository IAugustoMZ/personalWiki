## Armazenamento e Gestão de Dados com Datalake e Datalakehouse

### Data Lakehouse - Convergência entre Data Lakes e Datalakehouses

#### O que são Operações CRUD?

- para realizar o update da tabela, precisamos
  1.  carregar a tabela Delta Table
  2.  transformar em dataframe (conversão em memória)
  3.  `update()` $\to$ especificar o condition e o set (update em si)
- o condition aceita expressões lógicas da forma de string
- a expressão do ser também pode ser matemática, entre aspas `"idade + 5"`
  - se houver uma string dentro do set, precisa ser colocada entre aspas simples dentro das duplas - `"'novo nome da pessoa'"`
- a condition também aceita instruções SQL
  - condition: `nome LIKE '%z'`
  - também aceita funções SQL no set: `set:{"nome":"CONCAT(nome, '-suffix')"}`
- com o mesmo objeto Delta Table $\to$ deleção
  - `delta_table.delete(condition="id=1")`
- no Delta Lake, não há suporte nativo para adicionar novas colunas via API de manipulação de tabelas
  - podemos adicionar uma nova coluna ao DataFrame em memória e sobreescrever a tabela Delta com o esquema atualizado
  - habilitar a opção `MergeSchema` ao sobrescrever os dados na tabela Delta $\to$ pode ser ativada como configuração de sessão
- função `lit` $\to$ preenche todos os valores com um valor default definido
- usar `mode=append` para escrever coisas mantendo o que já existe lá no Delta Table
- HDFS $\to$ produto "bruto" para armazenamento de arquivos distribuídos $\to$ conceito de Data Lake
- Delta Lake $\to$ adicionar uma camada de armazenamento estruturado sobre o armazenamento bruto $\to$ Data Lakehouse
- no show $\to$ podemos usar `truncate=False` para melhorar as visualizações
- **upsert**: combinação de operações de `UPDATE` e `INSERT` permitindo atualizar registros existentes e inserir novos registros
  - integração de forma incremental
  - garante consistência e integridade (ACID)
- praticamente tudo o que fazemos com Apache Spark, conseguimos fazr com Delta Lake
  - convertendo para Dataframe Spark, temos acesso aos métodos do Spark $\to$ manipulação de dados
- as regras de aspas duplas e simples também se aplicam aos casos de de filtros e análises

#### Histórico de Alterações (*Time Travel*)

- funcionalidade que permite acessar versões anteriores de uma tabela
  - histórico de transações armazenadas
  - permite consultas a estados passados com base em timestamps ou números de versões
- ter boa base em banco de dados ajuda muito na aplicação de tecnologias de Data Science
- *time travel* $\to$ método `history`
  - arquivos JSON $\to$ snapshots com metadados que caracterizam o estado do Delta Lake
- precisamos especificar qual a versão histórica queremos olhar
  - podemos manipular dados normalmente com os dataframes recuperados das versões históricas
- podemos realizar comparações dos dados entre diferentes versões dos dados
  - auditoria e debugging
- cada alteração feita vai para um log recuperável
  - converter para JSON
- podemos inclusive substituir a versão atual com versões antigas
  - os dados não substituídos na prática, mas sim uma nova versão será criada
  - dessa forma, nenhuma versão dos dados é de fato perdida
- dessa forma, muitas versões podem ser criadas em pipelines reais
  - `VACCUM` $\to$ eliminação com segurança configurando o tempo de retenção mínima
    - o padrão é de 7 dias
  - depois da eliminação, não é possível realizar o time travel, pois as versões são definitivamente eliminadas

#### Segurança e Governança com Delta Lake

- **controle de acesso**
  - integração com plataformas de gerenciamento de identidade IAM para definir permissões
  - suporte a RBAC para granularidade
- **auditoria e rastreamento de alterações**
  - alterações capturadas pelo log de transações
  - permite auditorias completas e detalhadas
- **time travel**
  - histórico dos dados, recuperação de estados
  - análise retrospectiva, investigação de alterações
- **qualidade e validação de dados**
  - definição de regras de qualidade
  - rejeita ou registra entradas inconsistentes para tratamentos posteriores
- **retenção ou limpeza**
  - configuração de políticas de retenção para eliminação segura de dados obsoletos
  - garante conformidade com políticas organizacionais e regulamentações
- **criptografia e proteção**
  - dados criptografados em repouso e em trânsito

### Pipeline de Engenharia de Dados com a Plataforma Lakehouse da Databricks

#### Pipeline ETL

- processo para coletar, transformar, e carregar dados de múltiplas fontes
  - **extract**: coleta de diversas fontes, no formato bruto
  - **transform**: processamento para atender à necessidade de análise ou integração
    - limpeza, normalização, agregação, enriquecimento, cálculo de métricas, conversão do formato
  - **load**: carregamento do sistema de rastreio

#### Delta Live Tables - conceito e aplicação

- funcionalidade da Databricks que facilita a criação, manutenção, e monitoramento de pipelines de dados em tempo real ou em lotes
- automatiza tarefas complexas de engenharia de dados
  - dependências entre tabelas
  - validação da qualidade de dados
  - execução otimizada de transformações
