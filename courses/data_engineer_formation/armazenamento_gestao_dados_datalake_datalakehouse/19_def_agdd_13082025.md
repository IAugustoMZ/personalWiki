# Formação Engenheiro de Dados

## Armazenamento e Gestão de Dados com Datalake e Datalakehouse

### Data Lakehouse - Convergência entre Data Lakes e Datalakehouses

#### Segurança e Governança de Data Lakehouse

1. **controle de acesso baseado em funções (RBAC)**
    - com base em funções e responsabilidades dos usuários
    - Azure Active Directory, AWS IAM e Databricks Access Control
2. **criptografia de dados**
    - em repouso (armazenamento) e em trânsito (TLS)
3. **auditoria e monitoramento**
    - registros de acessos, consultas e alterações
    - identificação de comportamentos suspeitos
4. **isolamento de rede e camadas de segurança**
    - redes privadas virtuais (VPN) e firewalls
    - segregação de dados em camadas $\to$ controle
5. **gestão de identidades e chaves**
    - integração com sistemas de autenticação OAuth
    - autenticação multifator (MFA)
    - gerenciamento seguro de chaves

- aspectos de governança em data lakehouses
    - governança federada $\to$ políticas regionais + padrões globais
    - catálogo de dados e metadados
        - centralizado
        - esquemas, descrições e locais
        - Apache Atlas ou AWS Glue
    - qualidade de dados
        - processo automatizados
        - precisão, consistência, completude
    - políticas de retenção ou exclusão
        - dados sensíveis ou desnecessários
    - linhagem de dados $\to$ rastreamento do ciclo de vida

#### Configuração da Fonte do Airbyte

- `set up sources`$\to$ PostgreSQL
    - encontrar o conector
    - `host` $\to$ nome da máquina do servidor que está executando o PostgreSQL
    - `port` $\to$ porta do servidor
    - mudar o nome apontado como schema padrão (campos opcionais)
    - definir usuário e senha
    - crtiérios de segurança
        - SSL
        - túnel SSH
    - método de atualização $\to$ scan source
    - definir JDBC, se necessário

- **Troubleshooting**: processo sistemático de identificar, analisar e resolver problemas ou  falhas em sistemas
    - diagnosticar a causa raiz $\to$ observação, testes, eliminção de hipóteses e ferramentas
    - restaurar a funcionalidade ou melhorar o desempenho
- sempre bom acessar o log para analisar os erros
- no `host`, devemos considerar se o PortgreSQL está rodando em containers
    - usar o nome do container onde o PostgreSQL está sendo executado

host.docker.internal # aponta para a rede interna do Dockar e a porta informada no Dockerfile
