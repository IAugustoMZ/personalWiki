# Formação Engenheiro de Dados

## Armazenamento e Gestão de Dados com Datalake e Datalakehouse

### Planejamento e Design de Data Lakes Locais

- on-premises $\to$ organizações que precisam do controle total sobre a infraestrutura
  - requisitos de segurança
  - regulamentações específicas

1. **Avaliação dos requisitos e objetivos**
   1. definir o que a empresa espera alcançar
   2. requisitos de dados $\to$ tipos de dados, volume, velocidade e variedade
   3. requisitos legais e de compliance $\to$ regulamentações que afetam o armazenamento e o processamento
2. **Arquitetura e Design**
   1. escolha da tecnologia (hardware, software $\times$ requisitos)
   2. design modular (zonas ou camadas) para organizar dados de diferentes níveis de processamento ou acessibilidade
   3. segurança e governança $\to$ autenticação, autorização, criptografia e monitoramento
   4. políticas de governança
   5. gerenciamento de metadados, qualidade de dados e ciclo de vida
3. **Infraestrutura de Suporte**
   1. hardware e redes bem dimensionadas para volume e cargas esperados
   2. backup e recuperação $\to$ durabilidade e disponibilidade
4. **Implementação e Integração**
   1. Ingestão de Dados (contínua)
      1. diversas fontes
      2. volume $\times$ frequência $\times$ formatos
   2. processamento e análise
      1. pipelines de processamento, transformação, agregação e análise
   3. integração com ferramentas de análises
5. **Monitoramento e Manutenção**
   1. desempenho $\to$ velocidade de ingestão, tempo de resposta de consultas, eficiência de processamento
   2. manutenção contínua $\to$ rotinas de manutenção (otimização de armazenamento)
      1. atualização de software e hardware
      2. ajustes de performance
6. **Adaptação e Escalabilidade**
   1. projetar para ser facilmente escalável
      1. adicação de mais armazenamento ou capacidade de processamento
   2. adaptação a novas necessidades
      1. novas necessidades do negócio
      2. novas tecnologias e padrões de dados

### Implementação

- 2 camadas $\to$ armazenamento distribuído (Hadoop) + processamento distribuído (Spark)
- implementação no Docker Desktop
  - 5 máquinas virtuais
    - workers, master + history
  - Spark e Hadoop foram escritos em Java, então devemos baixar a open-jdk dentro do container
  - YARN $\to$ gestor do cluster Hadoop e Spark
  - aplicações Java possuem arquivos de configuração em xml ou `.conf`
    - modificar a parametrização do Data Lake
  - SSH $\to$ para garantir a comunicação somente entre o node master e os workers
