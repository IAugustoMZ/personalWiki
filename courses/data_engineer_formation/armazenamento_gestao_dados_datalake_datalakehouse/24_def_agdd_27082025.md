# Formação Engenheiro de Dados

## Armazenamento e Gestão de Dados com Datalake e Datalakehouse

### Data Lakehouse - Convergência entre Data Lakes e Datalakehouses

#### Fundamentos de Delta Lake

##### Fluxo de Operações na Arquitetura

- ciclo de vida do dado desde a ingestão até a análise com garantias de integridade e performance

1. **ingestão de dados**
   1. diferentes formatos suportados
      1. arquivos CSV, JSON, Parquet, bancos de dados, sistemas em tempo real, APIs
      2. dados salvos como arquivos no Delta Lake
      3. integração de múltiplas fontes de dados heterogêneas
2. **conversão para tabelas Delta**
   1. organização em tabelas Dela
      1. adicionar metadados sobre o schema e a organização dos dados
      2. armazenar logs de transações associados à tabela para rastrear alterações
      3. possibilidade de compactação e reorganização dos arquivos para melhorar a eficiência
   2. combina flexibilidade de um Data Lake eom a estrutura e consistência de um banco de dados
3. **armazenamento no log de transações**
   1. todas operações realizadas na tabela Delta
      1. cada operação cria um "commit", descrevendo as alterações
      2. log de transações permite reverter para vrsões anteriores dos dados (*time travel*)
      3. garante que transações concorrentes não causem inconsistências (ACID)
4. **operações de leitura e escrita com consistência**
   1. durante leituras e escrits, consulta ao log de transações
      1. garantir que dados acessados estão consistentes
      2. evitar conflitos quando múltiplos usuários ou processos acessam a mesma tabela
      3. fornecer visões instantâneas (*snapshots*) dos dados permitindo a leitura de versões específicas
5. **otimização dos dados**
   1. aplicação de técnicas para melhorar a performance e gerenciar o armazenamento
      1. compactação de arquivos: combinação de arquivos menos em arquivos maiores para reduzir a fragmentação
      2. otimização de layout: reorganização dos dados para acelerar as consultas
         1. particionamento
         2. ordenação por colunas utilizadas em filtros
      3. data *slupping*: partes irrelevantes dos dados são ignoradas com base em índices e estatísticas armazenadas
      4. *vaccum*: arquivos obsoletos ou versões antigas podem ser removidas para liberar espaço
6. **consulta e análise**
   1. dados podem ser consumidos por ferramentas de análise e visualização
      1. sem necessidade de copiar ou duplicar dados

##### Otimização de Armazenamento e Consulta no Delta Lake

- questões de leitura e escrita rápidas, mesmo com alto volume de dados e vários usuários acessando o sistema simultaneamente
- **otimizações de armazenamento**
  - **comptação de arquivos**: sistemas baseados em arquivos lidam melhor com menos arquivos maiores do que com mais arquivos menores
  - **particionamento**: com base em colunas frequentemente usadas como filtro, reduzindo o escopo dos dados analisados durante uma consulta
  - **vaccum**: libera espaço removendo arquivos antigos ou desnecessários que não são mais referenciados pelo log de transações
  - **manutenção de estatísticas e índices**: estatísticas de colunas em metadados, usadas para otimizar o planejamento das consultas
  - **esquema evolutivo**: suporta mudanças no esquema de forma incremental e eficiente, sem interrupção e sem a necessidade de recriar ou reorganizar dados
- **otimizações de consulta**
  - **data slupping**: permite ignorar automaticamente partes dos dados durante as leituras com base nos valores das estatísticas
  - **reorganização de dados (optimize)**: organiza fisicamente os dados para melhorar o desempenho de consultas
    - agrupamentos e organizações com base em colunas frequentemente vistas
  - **leitura incremental (streaming)**: apenas dados adicionados ou modificados desde a última execução sejam lidos em fluxos contínuos
    - eficiente para casos de dados em tempo real
  - **caching**: dados frequentemente acessados, reduz leituras redundantes
  - **consultas de versões (*time travel*)**: consultar versões históricas usando o log de transações, análises baseadas em estados passados sem a necessidade de manter cópias
  - **suporte nativo ao Spark Analyst Optimizer**: query optimizer do Apache Spark para otimização automática para planejamento de consultas e execução paralela.
