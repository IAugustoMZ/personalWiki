# Formação Engenheiro de Dados

## Armazenamento e Gestão de Dados com Datalake e Datalakehouse

### Design da Solução

#### Defindin Role IAM para Segurança de Acesso

- role IAM $\to$ recurso utilizado para gerenciar permissões para outros recursos
  - usuários, serviços e aplicações
  - não precisa de compartilhamento de credenciais
  - permissão temporária por meio de políticas
- criar o script de IaC não substitui o conhecimento de cloud computing
- chaves de acesso = *access keys id + secret keys*
  - programaticamente fazer chamadas para APIs AWS
    - AWS CLI
    - interações com serviços AWS

### Otimização e Escalabilidade

- **otimização**
  - melhorar a eficiência e o desempenho do armazenamento e processamento de dados
    - tipo de armazenamento
    - organização de dados em partições lógicas
    - uso de formatos organizados de armazenamentos
    - compressão, indexação e uso de ferramenta de consulta confiáveis
- **escalabilidade**
  - capacidade de aumentar ou diminuir os recurso conforme o necessário, sem comprometer o desempenho
    - arquitetura desacoplada (armazenamento $\times$ computação)
    - recursos de auto-scaling
    - gestão eficiente de metadados
    - implementação de pipelines de dados escaláveis

### Monitoramento e Gerenciamento de Custos

- **monitoramento do Data Lake**
  - ferramentas para rastrear e analisar o desempenho, utilização de recursos e segurança
    - Amazon Cloud Watch $\to$ métricas ao longo do tempo, criação de alarmes e notificações de eventos, e geração de logs
    - AWS Cloud Trail $\to$ registro de todas as chamadas de API para auditoria e conformidade
    - AWS Config $\to$ monitora e registra as configurações dos recursos
- **gerenciamento de custos**
  - evitar despesas desnecessárias, maximizar o uso de recursos
  - AWS Cost Explorer + AWS Budgets
    - monitorar e explorar gastos em tempo real
    - definir orçamentos
    - prever custos futuros com base em tendências
  - escolhas de classes de armazenamento adequadas
    - Standard, Infrequent Access, Glacier
  - uso de Instâncias Reservadas + Savings Plans para computação
  - políticas de ciclo de vida para mover ou excluir dados não utilizados de maneira automática

### Estratégia de Backup e Recuperação

- garantir integridade e disponibilidade dos dados em caso de falha, desastres, ou corrupção de dados
- **Backup**
  - automação de backup
    - políticas do ciclo de vida do S3 $\to$ cópias de segurança em diferentes classes de armazenamento
    - snapshots automatizados $\to$ bancos de dados e sistemas de armazenamento
  - versionamento de objetos
  - armazenamento em múltiplas regiões
    - redundância geográfica
- **Recuperação**
  - planos de recuperação de desastres
    - dados críticos
    - restruturação dos serviços dentro de um prazo aceitável
      - RTO = *recovery time objective*
      - RPO = *recovery point objective*
    - testes regulares de recuperação
      - garantir integridade dos backups
      - eficiência dos processos de recuperação
        - identificação de falhas e melhoria contínua
    - AWS Elastic Disaster Recovery $\to$ replicação contínua de dados
    - recuperação granular
      - recursos de recuperação *point-in-time* (PITR)

#### Exemplos

- backup de dados S3 para Glacier após período específico
  - redução de custos de armazenamento e disponibilidade a longo prazo
- cross-region replication para dados críticos
- autorização de snapshots com AWS backup
  - centralização do gerenciamento e garantindo consistência
