# Formação Engenheiro de Dados

## Armazenamento e Gestão de Dados com Datalake e Datalakehouse

### RAG Pipeline para IA Generativa no Lakehouse Databricks

- RAG $\to$ técnica de aprimoramento de LLMs por meio da integração dos mesmos aos conhecimento externo
  - busca de informações relevantes no banco de dados
  - informações combinadas com a entrada original e processadas pelo modelo de linguagem para a geração da resposta
- capacidade de gerar respostas atualizadas sem retreinar o modelo
- redução de alucinações
- controle de informações utilizadas
- aplicações onde informações precisam ser atualizadas ou específicas de um domínio

#### Relação entre RAG e IA Generativa

- complementaridade $\to$ respostas mais informadas, contextuais e informadas
- **IA Generativa**: eficazes em tarefas de linguagem natural mas têm limitações, como a possibilidade de "alucinações", dependência de dados de treinamento que podem estar desatualizados
- **RAG como solução para limitações**: mecanismo de recuperação de informações
  - contexto adicional para melhorar a resposta
  - identificação de informações relevantes a partir de um banco vetorial
- **Benefícios**
  - atualização contínua sem retreinamento
  - maior confiabilidade (fontes externas verificáveis)
  - adaptabilidade $\to$ diferentes domínios ou necessidades específicas

#### O que são e Quando devem ser usados Modelos de Embeddings

- modelos que transformam informações, como textos e palavras, em vetores numéricos num espaço dimensional contínuo, capturando relações semânticas
  - conceitos semelhantes ficam próximos nesse espaço
- **quando usar**
  - **busca e recuperação de informações:** com base na similaridade semântica
  - **recomendações**
  - **análise de similaridade**
  - **classificação ou clustering**: organização em grupos ou categorias
  - **redução de dimensionalidade**: compactação de informação

#### O que são bancos vetoriais?

- sistemas de armazenamento e consulta projetados para lidar com dados representados em espaços multidimensionais
  - buscas baseadas em similaridade
- **como funcionam**
  - armazenamento de vetores
  - indexação: índice vetorial organiza vetores para buscas rápidas, usando algoritmos de buscas aproximadas
    - árvores de k-dimensões
    - hashing sensível à localidade
  - consulta por similaridade (proximidade semântica)

#### Compreendendo o conceito de engenharia de prompt ao usar LLMs

- criação de instruções claras, estratégias e eficazes para orientar o modelo a produzir respostas desejadas
  - a forma de estruturar a entrada impacta nas respostas (qualidade e relevância)

##### O que é um Prompt?

- entrada que fornecemos ao modelo LLM para produzir as respostas
  - frases simples, instruções, contexto longo e complexo
- engenharia de prompt ajuda que o modelo compreenda o contexto e gere as respostas ajudando também a reduzir ambiguidade e erros

##### Princípios Fundamentais da Engenharia de Prompt

- **clareza**: reduzir a possibilidade e interpretações erradas
- **especificidade**: detalhamento suficiente para guiar a resposta
- **contexto**: informações relevantes para ajudar o modelo a entender melhor o cenário
- **formato**: indique o formato desejado da resposta
- **iteração**: refinar o prompt com base nos resultados iniciais

##### Ferramentas Avançadas de Engenharia de Prompt

- **encadeamento de prompt**: dividir uma tarefa complexa em etapas menores, criando prompts para cada uma dela
  - um prompt pode alimentar o outro
- **instruções de contexto fixo**: inserir informações estáticas no início do prompt que permanecem relevantes para toda a interação (regras de estilo e terminologia)
- **feedback iterativo**: mecanismo de feedback para ajustar automaticamente os prompts com base nas respostas

##### Por que usar RAG?

- sem prover contexto adicional, respostas do modelo são restritos aos dados de treinamento
  - alucinações
  - dados desatualizados
- RAG $\to$ uso de banco de dados vetorial para criar um banco de dados específico, de forma a prover contexto adicional para o modelo de LLM

##### LangChain

- framework projetado para facilitar a criação de aplicações que interagem com modelos de LLM, com outras fontes de dados e ferramentas computacionais
  - bases de dados externas, APIs, e fluxos de raciocínio avançado
- **principais recursos**
  - **cadeias de operações**: fluxos de processamento, sequência lógica
  - **memória**: permitem modelos "lembrar" do contexto de convesas ou interações anteriores
    - experiências interativas e consistentes
  - **integração de dados externos**: conexão com outras fontes de informação, estendendo a utilidade
  - **ferramentas e agentes**: agentes capazes de tomar decisões e realizar tarefas de forma autônoma
  - **flexibilidade:** compatível com diversos provedores de LLM
- para textos muito grandes, precisamos separar o texto em chunks (pedaços)
- os vetores criados pelo modelo de embedding são sempre baseados no conjunto de dados do treinamento do modelo de embedding
