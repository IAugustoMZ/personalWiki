# Fundamentos de Engenharia de Dados

## Armazenamento SQL / NoSQL ou Armazenamento de Arquivos

- SQL
    - dados tabulares
    - amplamente utilizados
    - ideal para dados estruturados
    - Sistemas Gerenciados de Bancos de Dados (SGBDs)
        - Oracle
        - PostgreSQL
        - SQL Server
        - MySQL
- NoSQL -> nasceu na era do Big Data
    - dados diferentes formatos
    - dados semi-estruturados
        - JSON
        - XML
        - colunar
    - sistemas orientados à performance e facilidade de uso
        - desafiar o paradigma estruturado
    - MongoDB, Redis, Apache Cassandra, HBase, Amazon DynamoDB
- Armazenamento de Arquivos
    - formatos avançados
        - diversos formatos
        - pesquisa e reduzir espaço
    - comuns em operações intermediárias de pipelines
    - Parquet, Avro, JSON, CSV, ORC, HDFS
    - armazenamento único ou distribuído
- Armazenamento Colunas x Linha
    - *formato linha*
        - dados tabulares
        - cada linha representa uma instância daquela entidade
        - fácil de compreender
        - não é pensado para performance
    - *formato colunar*
        - coluna sobre metadados
        - colunas com os dados indexados
        - geralmente são mais performáticos que armazenamento em linhas
            - consultas por índice
            - particionamento colunar
            - aplicações com alto nível de acessos (web, por exemplo)

### Quando usar uma Data Warehouse?

- bancos de dados para consultas e análise eficiente de grandes quantidades de dados
    - várias fontes
    - banco de dados transacionais ou arquivos de log
- conceito -> pode ser implementado em SQL, NoSQL, colunar ou baseado em linhas
1. grande volume de dados
2. necessidade de desempenho de consulta analítica
3. necessitar dados de integrar várias fontes
4. suporte à inteligência de negócios (BI)
5. necessidade de dados históricos (análises ao longo do tempo)

### Quando usar um Data Lake?

- dados brutos podem ser armazenados
- DW -> ETL (dados já limpos e organizados)
- DL -> ELT
    - exige uma boa governança de dados
    - risco de se tornar um pântano de dados
- repositório centralizado -> dados estruturados e não estruturados
    - mais flexibilidade e escalabilidade que um banco relacional
- conceito, mas por definição o banco de dados SQL não é ideal
    - NoSQL
    - armazenamento distribuído
1. armazenamento e processar dados brutos (flexibilidade)
2. armazenamento e processar alto volume de dados
3. dados estruturados e não estruturados
4. necessidade de escalabilidade
5. repositório de dados generalizado
