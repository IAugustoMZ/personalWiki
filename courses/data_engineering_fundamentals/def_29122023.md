# Fundamentos da Engenharia de Dados

## Definindo a Granularidade do Modelo de Dados

- nível de detalhe que os dados são representados
    - alta = muitas entidades, atributos pequenos
        - maior flexibilidade, maior precisão, mais armazenamento
    - baixa = poucas entidades, atributos menores
        - menor precisão, menos armazenamentos
- equilíbrio é essencial

## O que são formas normais?

- regras e princípios para garantir a integridade da base de dados e eficiência do banco
- assegurar relacionamentos corretos
- evitar redundância e inconsistência

### Principais formas normais

- **Primeira Forma Normal** - todos os valores na tabela são indivisíveis
- **Segunda Forma Normal** - todos os atributos não-chave devem ser dependentes funcionalmente da chave-primária
- **Terceira Forma Normal** - não deve haver dependência transitiva de não-chave para chave
- **Quarta Forma Normal** - não devem haver relacionamentos multivalorados
- **Quinta Forma Normal** - não deve haver relacionamentos com atributos dependentes

- cada condição é uma condição para a condição seguinte
- normalização é feita ao final da modelagem de dados
    - bancos de dados transacionais
- Data Warehouses -> desnormalização para agregação dos dados
    - banco de dados multidimensional

## Projeto de Índices em Modelagem de Dados

- acessar rapidamente registros ("mapa" para os dados)
1. identificar colunas de maior uso
2. escolher a tipagem correta dos índices
3. criar índices apenas em tabelas grandes
4. ordem das colunas com base na frequência de uso
5. avaliar índices compostos -> várias colunas de busca
6. monitoramento e manutenção
7. considerar índices não convencionais

- índices podem afeter negativamente operações de inserção, atualização e exclusão

## Importância do Particionamento em Modelagem de Dados

- dividir grandes tabelas / índices em porções menores
    - melhora o desempenho das consultas, direcionado para as partições específicas
    - facilita a manutenção e backup -> partições podem ser gerenciadas de forma independente
    - melhora a escalabilidade -> distribuição de dados, processamento
    - organização por data, geolocalização ou outras características

## Papel do Engenheiro de Dados

- construir e manter sistemas de gerenciamento de dados -> modelagem
- projetar a estrutura, entidades, atributos, relacionamentos e garantir o alinhamento com o negócio
    - qualidade de dados, limpeza, transformação e validação
    - otimização do desempenho, particionamento de tabelas, projetos de índices
    - garantir a segurança dos dados, criptografia dos dados sensíveis e implementação de medidas de segurança
    - monitoramento e garantia da disponibilidade

## Projeto do Arquiteto de Dados

- projetar e garantir a integridade, qualidade e segurança dos dados
    - coleta, armazenamento, processamento, exibição
- definir a estratégia de dados e garantir a implementação
- estrutura da modelagem e ajudar a garantir a satisfação da demanda
- arquiteto -> planeja e projeta
- engenheiro -> executa e mantém

## O que é Qualidade de Dados (Data Quality)?

- medida de quanto os dados são confiáveis
    - garantir a precisão nos dados para *suportar decisões*

- **como medir a qualidade dos dados?**
    - combinação de técnicas estatísticas e metodologias de avaliação
    - relevância para o negócio e facilidade no uso dos dados

1. *precisão* - confiabilidade dos dados
    - validação de campos?
    - deve ser validado para cada variável utilizada no sistema de dados
    - pode invalidar dados históricos

2. *exatidão* - quão bem os dados correpondem à realidade
    - arredondamentos, formas de cálculo distintas
    - cálculos feitos por humanos, sistemas ETL

3. *consistência* - como os dados são uniformes
    - evitar mudanças muito fortes ou erros
    - reflete integridade
    - valores ausentes? tratamento? descartes?

4. *relevância* - quantidades de informações relevantes sobre um determinado assunto que estão disponíveis
    - alinhado com os casos de uso

5. *cobertura* - quantidades de dados disponíveis para serem usados
    - informações suficientes?
    - deve evoluir conforme a evolução dos requisitos de negócio evoluem
    - modelos de aprendizado de máquina

6. *atualidade* - quão recentes são os dados
    - eventos estudados são refletidos?
    - "recentes" depende do problema em questão

### O Valor da Qualidade dos Dados

- valor está no que fazemos com os dados
- **erros potenciais** -> busca de erros na análise dos dados
    - digitação, ausentes, incorretos, formatação
- **análise estatística e mineração dos dados** -> busca de padrões e anomalias
    - pode ser automatizado (pipeline)
- **teste de qualidade** -> dados corretos e se a conformidade atende aos requisitos
- **avaliação do domínio** -> avaliação em relação ao domínio (contextualizados)
    - qual o negócio que gerou os dados?

### Correções Típicas dos Dados

- *limpeza*: duplicações, dados incompletos, inconsistentes, irrelevantes
- *padronização*: formato comum, padronizar datas, endereços, nomes e códigosm escala
- *tratar valores ausentes*: interpolação, eliminação
- *correção de erros*: verificar e corrigir erros de digitação, remover caracteres desnecessários, sobreposição de colunas
- *normalização*: para um formato normalizado
- *validação*: regras de negócios ou restrições para garantir precisão e integridade
