# Fundamentos de Engenharia de Dados

## Quando usar um DataLake House?

- une benefícios do Data Lake e do Data Warehouse
- armazenamento flexível de dados não estruturados e recursos e ferramentas de gerenciamento de Data Warehouse
    - nuvem de baixo custo, formatos abertos e normalmente, distribuídos
- from BI to AI (nem todas as empresas usam!)
    - muitas empresas precisam apenas de um relatório de BI ou sistema de armazenamento
    - *como a tecnologia pode ajudar as empresas a resolver seus problemas?*
- **vantagens**
    1. escalabilidade
    2. flexibilidade (dados brutos)
    3. desempenho de consulta
    4. repositórios centralizados
- **desvantagens**
    1. complexidade
    2. uso intensivo de recursos
    3. desafios adicionais de governança de dados
    4. desafios adicionais de integração de dados

## Quando usar um Data Store?

- repositório para armazenar e gerenciar dados
    1. bancos de dados relacionais
    2. bancos de dados não relacionais
    3. sistemas de arquivos
        - local ou em rede (NTFS, FAS, NAS, SAN)
        - podem ser distribuídos (HDFS, object storage)
        - pode ser na nuvem (Amazon S3, Azure Blob Storage)
        - objetivo é armazenar dados em qualquer formato de arquivo (CSV, JSON, Parquet)
        - em geral, baixo custo
    4. armazenamento key-value
        - hashmap em escala de produção
        - sem esquemas sofisticados ou relacionamentos entre os dados
        - sem tabelas ou outro grupo lógico
        - Redis e MemCached
    5. full-text search engine
        - uso específico -> pesquisar documentos de texto
        - documentos semi estruturados
        - divisão do conteúdo da mensagem em um formato otimizado para pesquisa
        - Elasticsearch
    6. fila de mensagens
        - age como *middleware*
        - transferência de dados (primariamente) mas podem armazenar com confiabilidade e persistência
        - Apache Kafka
        - preserva ordem de coleta, timestamps
    7. memory data store
        - sistemas que armazenam, lêem, gravam e acessam dados na RAM
        - recuperar dados rapidamente
        - réplicas constantemente atualizados de registros de dados
        - definidos pelo local que mantêm os dados e não pela estrutura de dados
            - Redis
            - VoltDB
            - SAP HANA

- 3 - 7 -> entram na categoria de Data Store propriamente ditos
