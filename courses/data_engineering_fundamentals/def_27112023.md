# Fundamentos de Engenharia de Dados

## Formatos de Arquivos Frequentemente usados em Engenharia de Dados

- maioria é dado estruturado, mas estamos passando por momento de transição para dados semi e não-estruturados
    - qual tipo de estruturação de dados?
    - qual sistema de armazenamento? Integração?
    - armazenamento local, nuvem ou híbrido?
    - qual formato do arquivo usar em passos temporários?

### Formato Parquet

- armazenamento colunar para grandes volumes de dados (estruturados ou semi estruturados)
- ecossistema Hadoop -> consultas e análises eficientes (Spark, Hive e Impala)
- analogia -> "tabela" do Data Lake
- dados, cabeçalhos, metadados
- consultas de dados usando ferramentas semelhantes a SQL
- compartilhamento de dados entre sistemas
- Data Warehousing
- características
    - ótima compressão de dados
    - leitura seletiva (somente do que precisa)
    - suporte em múltiplas plataformas
    - fácil de particionar
- Delta Lake usa parquet para provisionar o Data Lakehouse

### Formato Avro

- formato de serialização
- ecossistema Hadoop
    - grandes quantidades de dados em ambientes distribuídos
- armazenamento de dados com estruturas complexas
- compartilhamento entre sistemas
- processamento de dados com Hadoop
- características
    - permite mudanças de sistema
    - orientado a linha
    - suporte a schema irregular (JSON)

### Formato ORC

- *Optimized Row Colunar* - armazenamento regular
- grupos de linhas
- datetime, decimal e tipos complexos
- armazenam metadados

### Formato CSV

- *comma separated values*
- simples, fáceis e amplamente usados
- nada de especial, sem compressão e sem cabeçalho built-in
- fáceis de usar, desde que o volume de dados não seja grande
- delimitador é importante

### Formato JSON

- um dos mais úteis para dados semi-estruturados
- *JavaScript Object Notation* -> armazenar e trocar dados pela Internet e aplicações web
- alternativas: XML e YAML
